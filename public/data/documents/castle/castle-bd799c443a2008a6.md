# 亲密城堡 Unity 原型实现说明

本原型根据 `Docs/Unity_亲密城堡_成人向卡牌爬塔设计文档.md` 实现，内容保持抽象成人向表达：角色均为成年、自愿、可退出；玩法文本围绕张力、共鸣、边界、契约和节奏，不包含露骨动作或图像。

## 试玩入口

1. 打开 Unity 工程 `G:\TestProject\HSJT`。
2. 打开任意现有场景，例如 `Assets/Scenes/SampleScene.unity`。
3. 点击 Play。
4. `IntimateCastleApp` 会通过 `RuntimeInitializeOnLoadMethod` 自动创建 UI，无需手动拖 Prefab。

首次进入会显示年龄确认。确认后可以新开一局，依次体验地图、战斗、奖励、商店、休息室、事件、设置、卡组和图鉴。

## 主要文件

- `Assets/Scripts/IntimateCastle/IntimateCastleData.cs`
  - 卡牌、遗物、对手、事件、节点等数据结构。
  - 内置首版内容库：30+ 卡牌、20 个遗物、普通/精英/Boss 对手和事件。

- `Assets/Scripts/IntimateCastle/IntimateCastleState.cs`
  - 年龄门配置、本地存档、单局状态、地图状态、商店、奖励和事件处理。

- `Assets/Scripts/IntimateCastle/IntimateCastleCombat.cs`
  - 抽牌、洗牌、出牌、费用、弃牌、消耗、共鸣、张力、冷静、失控冲击、状态、遗物、对手意图和胜负判定。

- `Assets/Scripts/IntimateCastle/IntimateCastleApp.cs`
  - 程序化 UGUI 界面。
  - 覆盖年龄门、主菜单、地图、战斗、奖励、商店、休息室、事件、设置、卡组和图鉴。

- `Assets/Scripts/IntimateCastle/IntimateCastleFeelFeedbacks.cs`
  - 运行时自动创建 Feel 表现 Rig，无需手动拖 Prefab。
  - 使用 `MMF_Player`、`MMF_Flash`、`MMF_CameraShake`、`MMF_TimescaleModifier`、`MMF_Sound` 和 NiceVibrations。
  - 额外提供 UI punch、全屏闪光和根节点轻微位移兜底，保证程序化 UI 重建后仍有反馈。

## 已实现玩法

- 尖塔式 15 层随机地图，每幕包含普通试炼、精英、事件、商店、休息、宝箱、Boss。
- 三幕流程：红幕主持人、镜面双生、城堡之心。
- 初始卡组：基础推进 x5、深呼吸 x4、观察呼吸 x1。
- 卡牌类型：动作、技巧、冷静、姿态、气氛、契约、终结、负面。
- Build 支持：增幅、忍耐控制、共鸣爆发、持续心动、观察反制、多目标、同步、失控利用。
- 遗物触发：战斗开始、回合开始、出牌、张力变化、奖励、商店价格等。
- 内容过滤设置：暗示强度、服装暴露度、文本隐喻程度、镜头表现。
- 本地 Profile：年龄确认、完成局数、失败次数、最高进度、见过的对手。

## UI 对标实现

根据 `Docs/Unity_亲密城堡_UI布局对标杀戮尖塔规范文档.md`，核心界面已从旧的面板流式布局调整为锚点式结构：

- 战斗界面：顶部 HUD、遗物栏、中央角色舞台、玩家左侧、敌人右侧、敌人头顶意图、脚下共鸣条、左下节奏球、抽牌堆、底部扇形手牌、右下弃牌/消耗堆、右侧结束回合按钮。
- 地图界面：羊皮纸主画布、可拖动纵向路线、节点自下而上分布并拉开楼层间距、连线路径、当前可选节点高亮、已访问节点变暗、右侧图例、顶部层数与底部路线资源条。
- 奖励界面：全屏遮罩、中央奖励面板、金币/遗物行、三张卡牌横排、跳过与继续按钮。
- 卡组查看：全屏遮罩、左侧类型 Tab、顶部筛选/计数条、中央卡牌网格、右侧大卡预览。
- 商店、休息、事件界面也同步改为顶部 HUD + 中央房间/弹窗式结构，避免与主界面信息层级冲突。
- Tooltip 信息层：装备/遗物、Buff/状态、敌人意图、行动力、牌堆、卡牌费用和卡牌类型支持鼠标悬浮或按下显示详情；卡牌和图鉴描述中的关键属性会用颜色、加粗、书名号和属性图标前缀区分，并额外显示可悬浮的属性词条。
- 战斗手牌：PC 和移动端统一为按下/长按选中手牌，卡牌用 0.3 秒放大并上移，松开会用 0.3 秒回落；继续向上滑动会打出卡牌，卡牌先以弧线飞向抽牌堆 UI 并缩小消失，再进入战斗结算。

说明：当前仍使用原创程序化 UGUI 形状与文字图标，只对标公开界面的结构、信息层级和交互位置，不复制原作素材、字体、按钮或图标。

## 角色序列帧资源

根据 `Docs/Unity_亲密城堡_角色美术与动作序列帧规则文档.md`，已生成首批可运行角色资源并应用到战斗界面：

- 资源目录：`Assets/Resources/GameArt/Characters`。
- 生成脚本：`Tools/generate_character_sequence_assets.py`，可重复运行。
- 资源范围：主角 `MaleTraveler`，普通对手、精英对手、三名 Boss 均有透明 PNG 帧。
- 动作范围：主角包含 `Idle`、`Idle_Warning`、`Attack`、`Hit`；对手包含 `Idle`、`Intent`、`Attack`、`Hit`。
- 运行时应用：战斗界面加载角色 ID 对应资源，循环播放 Idle/Intent；出牌、共鸣、对手意图、张力上升等 Feel cue 会短暂切换 Attack/Hit 帧。
- 美术边界：所有角色为成年化、非露骨、原创 2D 剪影式资源，可读性优先；后续正式 AI/手绘资源只要沿用相同目录和文件名即可替换。

## 场景 / UI / 卡牌 / 图标美术资源

根据 `Docs/Unity_亲密城堡_场景_UI_卡牌_图标美术规范文档.md`，已生成并接入首批可运行美术资源：

- 资源目录：`Assets/Resources/GameArt`，当前包含场景、UI、卡牌、图标和角色序列帧 PNG。
- 生成脚本：`Tools/generate_scene_ui_card_icon_assets.py`，可重复运行；脚本会保留已有的 `BG_Act1_Battle_01.png`，避免覆盖已生成的战斗背景概念图。
- 场景资源：战斗背景 `BG_Act1_Battle_01` 使用内置图像生成工具生成并裁切为 1920x1080；地图、商店、休息室、事件房背景使用原创程序化 PNG 占位资源。
- UI 资源：丝绒面板、羊皮纸面板、玫瑰按钮和金色按钮已接入通用 `Panel()` / `Button()` 皮肤逻辑；路径线和进度填充保持纯色，避免被 9-slice 皮肤误套。
- 卡牌资源：不同卡牌类型使用独立卡框、费用宝石和卡牌插画区资源，覆盖战斗手牌、奖励卡牌、商店卡牌和卡组预览。
- 图标资源：地图房间节点、敌人意图、抽牌堆、弃牌堆、消耗堆、行动力、金币、状态、设置和结束回合按钮均改为 PNG 图标显示。
- 运行时应用：`IntimateCastleApp` 通过 `Resources.Load<Texture2D>()` 动态创建 Sprite，并按路径缓存；后续正式资源只要保持相同 `Resources/GameArt/...` 路径即可无代码替换。
- 美术边界：所有资源保持原创、抽象、非露骨表达，使用张力、共鸣、冷静、契约、玫瑰、烛光、宝石和哥特城堡元素表达主题。

## Feel 表现提升

- 反馈模型：`CastleFeedbackCue` 按 `Light` / `Medium` / `Heavy` 三档强度驱动表现。
- 全局操作：所有按钮点击都有轻量音效、触感和 UI 缩放。
- 地图流程：进入普通、精英、Boss、宝箱、商店、休息、事件节点时按节点风险播放不同颜色和强度。
- 战斗表现：出牌、抽牌、行动力变化、共鸣增加、张力上升、失控冲击、冷静/增幅/状态、对手意图、边界护盾、遗物触发、胜利和失败都会抛出表现 cue。
- 战斗特效：根据 `Docs/unity_亲密城堡_战斗表现与特效逻辑规范文档.md`，战斗 cue 会额外生成攻击轨迹、命中爆点、状态光环、飘字和屏幕脉冲；攻击方会用 0.5 秒前冲到目标方向，随后播放命中/受击并慢速回位，敌人阶段会按 cue 留出更长可见表演间隔，形成“动作/特效/数值/结算”的表现顺序。
- 数值映射：高费用、稀有牌、终结牌、大额共鸣、高张力、Boss/精英节点和通关结算会触发重反馈；普通抽牌、冷静、小额状态为轻反馈。
- 界面目标：UI 层会把反馈自动打到手牌区、对手区、玩家状态区、奖励/商店区或主面板，不依赖长期存在的按钮对象。
- 失败规则：新开局默认失控容错为 0，张力达到上限会立即触发失败；卡牌、遗物或事件额外获得的失控容错仍可抵消一次满张力结算。

## 项目兼容处理

当前 Unity 版本为 `6000.0.61f1`，原工程的 `com.unity.feature.2d` 会拉入旧版 `com.unity.2d.pixel-perfect@5.0.3`，其 URP 转换器引用了已不存在的旧命名空间并导致编译错误。原型不依赖 Pixel Perfect，因此已从 `Packages/manifest.json` 移除 `com.unity.feature.2d` 聚合包入口，保留 URP、UGUI、InputSystem 等必要依赖。
