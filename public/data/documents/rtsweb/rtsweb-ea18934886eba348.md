# RTS 操作按钮详情页 UI 设计规范

## 一、文档目标

当前以下界面按钮通常只显示：

```text
图标 + 名称 + 消耗
```

需要补充鼠标悬停 / 手指长按后的详情页：

```text
造兵页面
造建筑页面
学习科技页面
华夏族建筑升级页面
机械改造页面
妖族吞噬界面
自然阵营融合界面
融合阵营建筑 / 单位 / 科技页面
```

设计目标：

```text
1. 主界面按钮保持简洁。
2. 复杂信息全部放入详情卡。
3. 详情卡信息完整，但不能堆太多文字。
4. 结构统一，玩家能快速扫读。
5. 不同阵营有不同主题视觉。
6. PC 使用鼠标悬停，手机使用长按。
7. 高风险操作必须显示确认区。
```

---

# 二、整体设计原则

## 2.1 主界面按钮与详情卡分工

### 主界面按钮负责

```text
快速识别
快速点击
判断是否可用
```

按钮只显示：

```text
图标
名称
主要消耗
可用 / 锁定状态
```

### 详情卡负责

```text
解释价值
展示风险
展示完整条件
辅助玩家决策
```

详情卡显示：

```text
定位
属性
消耗
效果
技能
克制
限制
风险
确认
```

---

## 2.2 信息压缩原则

详情卡不能像说明书。

所有内容尽量短句化、标签化、图标化。

推荐写法：

```text
反重甲
范围伤害
水面强化
技能互斥
不可逆
永久消失
资源不足
```

不推荐写法：

```text
该单位在面对敌人的重型护甲单位时，能够通过自己的高穿甲能力造成更高伤害。
```

---

## 2.3 详情卡固定阅读顺序

玩家看到详情卡时，应该按这个顺序理解：

```text
这是什么
它干什么
它强在哪里
要花什么
有什么技能
克制谁
有什么限制
能不能现在执行
```

所以所有详情卡固定为 7 个区块：

```text
A. 顶部标题区
B. 定位标签区
C. 核心数值区
D. 消耗与条件区
E. 效果 / 技能区
F. 克制 / 风险区
G. 操作确认区，可选
```

---

# 三、交互规则

## 3.1 PC端交互

| 操作 | 结果 |
|---|---|
| 鼠标悬停按钮 0.25 秒 | 显示详情卡 |
| 鼠标离开按钮 | 详情卡延迟 0.15 秒消失 |
| 鼠标移动到详情卡上 | 详情卡保持 |
| 左键点击按钮 | 执行按钮功能 |
| 右键点击按钮 | 固定详情卡 |
| ESC | 关闭固定详情卡 |
| 鼠标滚轮 | 详情卡内部滚动 |

---

## 3.2 手机端交互

| 操作 | 结果 |
|---|---|
| 短按按钮 | 执行操作 |
| 长按 0.35 秒 | 显示详情卡 |
| 手指松开 | 详情卡延迟 0.5 秒消失 |
| 长按后上滑 | 保持详情卡 |
| 点击详情卡关闭按钮 | 关闭详情卡 |
| 高风险按钮短按 | 弹出确认详情卡 |
| 详情卡内容超高 | 允许纵向滚动 |

---

## 3.3 高风险操作

以下操作必须弹出确认详情卡：

```text
机械替换改造
妖族主动吞噬友军
自然元素融合
华夏建筑升级
高级科技研究
高级融合单位训练
消耗大量资源的终局技能
拆除融合建筑
```

高风险详情卡必须显示：

```text
执行对象
消耗
收益
损失
是否不可逆
取消按钮
确认按钮
```

# 四、通用详情卡尺寸

## 4.1 PC端尺寸

| 项目 | 建议值 |
|---|---:|
| 宽度 | 380 px |
| 最小高度 | 240 px |
| 最大高度 | 560 px |
| 圆角 | 14 px |
| 内边距 | 14 px |
| 区块间距 | 8 px |
| 边框 | 1.5 px |
| 阴影 | 柔和中阴影 |

PC显示位置：

```text
优先显示在按钮右侧
右侧空间不足显示左侧
上下空间不足时自动贴边
不能遮挡当前鼠标按钮
```

---

| 项目 | 建议值 |
|---|---:|
| 宽度 | 屏幕宽度 86% |
| 最大高度 | 屏幕高度 62% |
| 圆角 | 18 px |
| 内边距 | 16 px |
| 区块间距 | 10 px |
| 位置 | 屏幕中下方 |
| 背景遮罩 | 15%黑色透明，可选 |

手机显示方式：

```text

高风险详情卡：居中弹窗
不能遮挡顶部资源栏

```

# 五、通用详情卡 UI 结构

---

## 5.2 A 顶部标题区

### 显示内容

```text
大图标
名称
类型标签
稀有度 / 阵营标签
一句话描述
关闭按钮，手机端显示
```

### UI结构

```text
┌────────────────────────────┐
│ [48x48图标] 名称       标签 │
│            一句话短描述     │
└────────────────────────────┘
```

### 样式规则

| 元素 | 规则 |
|---|---|
| 主图标 | 48x48，圆角8，带阵营描边 |
| 名称 | 18~20号，加粗 |
| 类型标签 | 右上角，小胶囊 |
| 一句话描述 | 12~13号，次级颜色 |
| 手机关闭按钮 | 右上角，28x28 |

### 示例

```text
[图标] 麒麟骑兵      精锐骑兵
高速冲锋，撕开远程阵型
```


```text

9. 互斥、不可逆、永久消失必须醒目。
10. 详情卡不遮挡当前按钮。
11. 详情卡高度超出时可滚动。
12. 玩家3秒内能看懂该按钮的价值和风险。
13. 主界面按钮保持简洁，不把详情文字堆回按钮区域。
14. 手机端详情页可关闭，不影响继续操作。
15. 融合、吞噬、改造这三类必须有专用风险提示。
```

# 十九、最终总结

按钮界面负责：

```text
快速操作
```

详情卡负责：

```text
解释价值
展示风险
辅助决策
```

统一结构是：

```text
标题 → 定位 → 数值 → 消耗 → 效果 → 克制/限制 → 确认
```

最终目标：

```text
玩家不用打开复杂大页面，只需要悬停或长按，就能快速理解单位、建筑、科技、升级、改造、吞噬和融合的完整信息。
```
## 当前项目落地规则

```text
1. 悬停 / 长按浮层详情卡使用 OperationDetailCard_Prefab。

3. 当前统一数据入口为：
   - 建筑：OperationDetailDataFactory.ForBuilding(...)
   - 单位：OperationDetailDataFactory.ForUnit(...)
   - 科技：OperationDetailDataFactory.ForTech(...)
4. 建造页、造兵页、科技树页不得各自再维护一套独立详情字段顺序。
5. Prefab 决定布局和视觉，代码只决定数据内容、状态和按钮可用性。
```
