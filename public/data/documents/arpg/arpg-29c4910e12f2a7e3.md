# 261 Unity 战斗 HUD 卡顿问题总览：原因定位与优化优先级

## 1. HUD 卡顿的本质

战斗 HUD 卡顿往往不是单个控件的问题，而是多个高频系统叠加：

```text
Canvas 频繁重建
Layout 系统反复计算
大量 World Space UI
伤害跳字频繁创建销毁
TextMeshPro 高频改文本
小地图相机持续渲染
技能按钮逐个 Update 轮询
敌人血条逐帧更新位置
UI 材质过多导致 Draw Call 增加
透明 UI 叠加导致 Overdraw
GC 分配引发周期性卡顿
```

典型现象：

```text
敌人少时正常，敌人多时掉帧
多段伤害、暴击、DOT 同时出现时卡一下
大量敌人死亡后出现 GC 峰值
打开小地图后帧率明显下降
技能冷却或 Buff 变化导致整个 HUD 抖动
```

## 2. 优化优先级

### 第一优先：伤害跳字

原因：创建频率最高、TMP 更新最频繁、最容易产生 GC 与 Canvas rebuild。

### 第二优先：敌人血条

原因：数量多、持续跟随、世界坐标转屏幕坐标、异常状态和锁定标记都可能更新。

### 第三优先：常驻 HUD Canvas

角色血条、技能栏、Buff、任务、小地图如果放在同一 Canvas，任何局部变化都可能触发整块重建。

### 第四优先：小地图

额外 Camera、RenderTexture、图标刷新、战争迷雾都会产生稳定成本。

## 3. 最常见错误

```text
每个敌人一个 World Space Canvas
每个伤害数字 Instantiate / Destroy
每个技能按钮都在 Update 中查询技能状态
不可拖动血条仍使用完整 Slider
频繁变化区域使用 LayoutGroup + ContentSizeFitter
频繁调用 SetActive
每帧字符串拼接
所有 UI 开启 Raycast Target
小地图 60 FPS 渲染完整场景
```

## 4. 推荐 HUD 架构

```text
HUDSystem
├── Canvas_Static
├── Canvas_PlayerStatus
├── Canvas_SkillBar
├── Canvas_Buff
├── Canvas_WorldHud
├── Canvas_DamageText
├── Canvas_Minimap
└── HudEventBridge
```

原则：静态与动态分开，高频变化元素独立 Canvas，伤害跳字、世界血条、小地图必须独立。

## 5. 事件驱动

错误：

```csharp
void Update()
{
    hpFill.fillAmount = player.Hp / player.MaxHp;
}
```

正确思路：

```text
生命变化事件
→ HUD 收到事件
→ 只更新一次目标值
→ 需要时启动短时平滑动画
```

适合事件驱动：

```text
生命、护盾、资源变化
技能冷却开始/结束
Buff 增删
敌人进入/离开视野
敌人死亡
锁定目标变化
```

仅时间型状态参与 Tick：

```text
冷却倒计时
引导/蓄力进度
Buff 剩余时间
延迟掉血条
```

## 6. 建议性能预算

以 60 FPS 为目标：

```text
HUD CPU：建议 < 1.5 ms
敌人血条同屏：20-30 个以内
伤害数字同屏：30-50 个以内
小地图刷新：10-20 Hz
屏幕外世界 UI：停止更新
稳定战斗阶段 GC.Alloc：接近 0
```

## 8. 实施顺序

```text
1. 伤害跳字对象池
2. 敌人血条统一 Canvas
3. Canvas 分区
4. 技能按钮事件驱动
5. 关闭无用 Raycast
6. 小地图降频
7. TMP 与字符串优化
8. 分帧更新
9. Draw Call 与 Overdraw
10. 压测验收
```
