# 165 模型 Prefab 结构：LOD、碰撞、Hitbox、VFX 挂点

## 1. 目标

规范所有玩家、怪物、Boss、装备、挂件的 Prefab 结构，避免后期模型资源混乱。

---

## 2. 通用模型 Prefab 结构

```text
PF_Model_Example
├── Root
├── MeshRoot
│   ├── LOD0
│   ├── LOD1
│   └── LOD2
├── RendererRoot
├── ColliderRoot
├── SocketRoot
├── VFXSocketRoot
├── AudioSocketRoot
├── HitboxRoot
└── Metadata
```

---

## 3. LOD 规则

### 3.1 LOD 层级

| LOD | 用途 |
|---|---|
| LOD0 | 近景高模 |
| LOD1 | 中距离 |
| LOD2 | 远距离 |
| LOD3 | 极远距离或阴影简模 |

### 3.2 装备 LOD
装备也要支持 LOD：

```json
{
  "lodGroupId": "LOD_Armor_Medium",
  "lods": [
    {"level": 0, "mesh": "IronChest_LOD0", "screenRelativeHeight": 0.6},
    {"level": 1, "mesh": "IronChest_LOD1", "screenRelativeHeight": 0.3},
    {"level": 2, "mesh": "IronChest_LOD2", "screenRelativeHeight": 0.1}
  ]
}
```

### 3.3 挂件低 LOD 隐藏
小挂件、发光装饰、复杂 VFX 可以低 LOD 隐藏。

## 4. 碰撞结构

### 4.1 模型碰撞不等于战斗判定
区分：

```text
PhysicsCollider：物理碰撞
Hitbox：攻击判定
Hurtbox：受击判定
InteractCollider：交互碰撞
CameraCollider：镜头遮挡碰撞
```

### 4.2 玩家碰撞
玩家使用胶囊体，不依赖模型 Mesh Collider。

```text
CapsuleCollider
CharacterController
GroundCheck
StepCheck
```

### 4.3 怪物碰撞
普通怪：
- CapsuleCollider
- Hurtbox

Boss：
- 多部位 Hurtbox
- 弱点 Hurtbox
- 攻击 Hitbox

---

## 5. Hitbox / Hurtbox 结构

```text
HitboxRoot
├── Hurtbox_Body
├── Hurtbox_Head
├── Hurtbox_WeakPoint
├── AttackHitbox_Weapon
└── AttackHitbox_AOE
```

配置：

```json
{
  "hitboxId": "HB_Boss_Core",
  "type": "Hurtbox",
  "shape": "Sphere",
  "radius": 0.45,
  "socket": "Core",
  "damageMultiplier": 1.35,
  "isWeakPoint": true
}
```

---

## 8. Metadata

每个模型 Prefab 需要有 Metadata：

```json
{
  "modelId": "PF_Sword_Iron",
  "modelType": "WeaponAttachment",
  "author": "ArtTeam",
  "skeletonId": null,
  "socketPreset": "Weapon_R_Sword",
  "materialSet": "MatSet_Sword_Iron",
  "lodGroup": "LOD_Weapon_Small"
}
```

---

## 9. 验收标准

- 所有模型 Prefab 层级统一。
- 玩家/怪物不使用 MeshCollider 作为主要移动碰撞。
- Hitbox 和 Hurtbox 分开。
- VFX 挂点命名统一。
- 装备和挂件都有 Metadata。
- LOD 正常切换。
