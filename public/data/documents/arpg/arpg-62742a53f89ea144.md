# 仙侠 ARPG UI v2 组件拆分与像素规范

## 1. 验收基准

- 设计基准分辨率：`1920 x 1080`，`CanvasScaler` 使用 `Scale With Screen Size`。
- 每张设计图对应一个完整游戏页面，不再使用多页缩略拼图作为还原依据。
- 主功能页使用全屏骨架，商店、NPC 服务、确认等流程使用受控弹窗。
- 截图对比时以内容区占比、关键控件位置、字号、间距、信息层级为主，不要求运行数据与设计图的示例数值一致。

## 3. 通用组件

### UI_Xianxia_PageHeader

- 高度 72 px，左侧放页面标题或 NPC 信息，右侧放货币与系统图标。
- 不使用大面积渐变，仅使用深色漆面、1 px 金色分隔线。

### UI_Xianxia_PrimaryNavItem

- 图标区 36 px，文字 18 px，单项 60-64 px 高。
- 选中态：左侧或右侧 4 px 玉色标记，文字古金色，背景仅轻微提亮。

### UI_Xianxia_Section

- 只承担标题、细分隔线和内容组织，不要在 Section 中再嵌套多层卡片。
- 标题 18 px，正文 14-16 px，辅助文字 12-13 px。

### UI_Xianxia_GridItem

- 图标为主，名称固定在底部，数量和强化等级使用右上/右下角标。
- 品质只改变边框与少量辉光，避免大面积透明叠加。

### UI_Xianxia_DetailPanel

- 使用“名称 -> 类型/等级 -> 基础属性 -> 随机词条 -> 套装 -> 描述 -> 操作”的固定阅读顺序。
- 对比值使用绿/红和方向符号，不仅依赖颜色。

### UI_Xianxia_ActionBar

- 固定在页面底部，页面局部刷新时不重建，避免按钮位置跳变。
- 主命令使用古金填充，次命令使用玉色描边，破坏性命令使用朱砂描边。

### UI_Xianxia_Toast / Modal

- Toast 位于右上安全区，用于强化成功、购买失败、材料不足等反馈。
- 只有不可逆或需要明确选择的操作使用 Modal。

## 5. 性能约束

- 静态背景、宣传图和模型预览的 `Graphic.raycastTarget` 必须关闭。
- 不允许页面根节点在 `Update` 中重建布局；列表、详情和底部操作分开刷新。
- 背包、商店、技能库优先复用格子对象，不在滚动时反复 `Instantiate/Destroy`。
- 大面积模糊、多层半透明绉射、每格独立材质禁止使用。
- HUD 仅在数据变化时刷新文本/进度，世界 HUD 只在可见且屏幕内时参与定位。
