# 数据表设计：JSON、ScriptableObject、ID 规范

---

## 1. 数据驱动原则

本项目系统复杂，必须数据驱动。

代码负责规则，数据负责内容。

```text
代码：如何计算伤害、如何生成装备、如何开启地图
数据：技能数值、词条范围、装备基底、地图词缀、怪物属性
```

---

## 2. ID 命名规范

统一小写蛇形：

```text
item_sword_iron_001
skill_fire_ember_bolt
support_projectile_multi
monster_beast_wolf_001
map_cavern_redstone_01
affix_life_prefix_t3
currency_lock_affix_stone
```

ID 不允许改名。显示名称可以本地化。

---

## 3. 数据类型选择

| 数据 | 推荐格式 |
|---|---|
| 装备基底 | JSON/CSV + 编辑器导入 SO |
| 词条 | CSV/Google Sheet 导出 JSON |
| 技能 | ScriptableObject + JSON 混合 |
| 怪物 | ScriptableObject |
| 地图 | ScriptableObject |
| 掉落表 | JSON |
| UI 文本 | Localization Table |
| 音效配置 | ScriptableObject |

## 14. 配置校验工具

必须做 Editor 校验：

- ID 重复检查。
- 词条组互斥检查。
- 技能标签与辅助兼容检查。
- 掉落表权重为空检查。
- 地图 Boss 不存在检查。
- Addressable 地址缺失检查。
- 本地化 Key 缺失检查。
- 数值范围 Min > Max 检查。

---

## 15. 验收标准

- 新增一个技能不需要改代码。
- 新增一个装备基底不需要改 UI。
- 新增一个地图机制只需要注册机制 Controller 和数据。
- 所有配置错误在编辑器构建前能发现。
- 存档能跨版本迁移。
