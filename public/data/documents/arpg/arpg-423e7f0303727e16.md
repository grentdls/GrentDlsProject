# 84 HUD 预制体结构：世界空间 UI、屏幕空间 UI、对象池

> 项目：Unity 3D ACT 暗黑刷宝 ARPG  
> 文档批次：第七批 HUD 全规则  
> 原则：参考同类暗黑刷宝 ARPG 的信息层级与战斗可读性，不复制任何商业游戏的 UI 视觉、图标、专有名称或具体数值。  
> 目标：所有头顶信息、血条、跳字、Buff、交互提示、拾取标签、Boss 条、目标提示都可以由策划配置，程序只实现通用规则。

## 3. WorldHUDRoot

世界 UI 根节点负责所有 3D 对象头顶信息。

```text
Prefab_WorldHUDRoot
├── WorldHUDManager
├── CameraBillboardSystem
├── VisibilityCullingSystem
├── OcclusionCheckSystem
├── NameplatePoolRoot
├── EnemyHealthbarPoolRoot
├── InteractionLabelPoolRoot
├── LootLabelPoolRoot
├── QuestMarkerPoolRoot
└── WarningMarkerPoolRoot
```

### 3.1 跟随方式

World HUD 不建议每个单位单独挂 Canvas，容易产生性能问题。推荐方案：

```text
每个单位提供 HUDAnchor
→ WorldHUDManager 收集需要显示的对象
→ 将世界坐标投射到屏幕坐标
→ 在 ScreenSpace Canvas 中渲染标签
```

优点：

- 便于做重叠避让。
- 便于统一缩放。
- 便于对象池管理。
- 便于处理遮挡和裁剪。

## 9. 对象池设计

### 9.1 对象池列表

```text
HUDPoolManager
├── NameplatePool
├── HealthbarPool
├── DamageTextPool
├── BuffIconPool
├── InteractionPromptPool
├── LootLabelPool
├── EdgeIndicatorPool
├── ToastPool
└── WarningMarkerPool
```

### 9.2 池化规则

| 对象 | 是否池化 | 原因 |
|---|---|---|
| 伤害跳字 | 必须 | 高频创建 |
| 普通怪血条 | 必须 | 数量多 |
| Buff 图标 | 建议 | 状态频繁变化 |
| 拾取标签 | 必须 | 掉落多 |
| NPC 名称 | 可池化 | 主城数量稳定 |
| Boss 血条 | 不需要频繁池化 | 常驻单例 |
| 小地图标记 | 建议 | 动态变化 |
| Toast | 必须 | 通知队列 |

## 12. 分辨率适配

| 分辨率 | 规则 |
|---|---|
| 1920x1080 | 标准布局 |
| 2560x1440 | UI 缩放 1.0-1.1，不盲目放大 |
| 3840x2160 | 可使用高清字体和图标，布局保持比例 |
| 1366x768 | 压缩任务栏、小地图、Buff 栏 |
| 21:9 | 底部 HUD 不贴边太远，核心信息保持在中心区域 |
| 移动端 | 技能栏和交互按钮扩大，小地图可折叠 |

---

## 13. 预制体验收标准

- 所有 HUD 预制体路径统一。
- 所有 Text 使用 TMP。
- 所有图标支持本地化替换。
- 所有频繁对象使用对象池。
- 所有世界 UI 可以正确跟随、淡出、遮挡判断。
- 所有 HUD 元素可以通过 HUDConfigDatabase 调整。
- 键鼠、手柄、移动端显示的按键图标不同。
- 编辑器中有 HUD Preview Scene，可单独预览所有状态。
