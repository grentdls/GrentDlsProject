# 仙侠 ARPG UI 视觉规范与界面拆分方案

## 视觉基准

整套界面采用“墨黑漆面、青玉、鎏金符印、朱砂状态色、月白文字”的仙侠视觉语言。界面应保持克制、清晰、可扫描，装饰只承担层级和状态表达，不遮挡操作信息。

- 主背景：墨黑与深青灰，用于窗口底板和全屏遮罩。
- 主强调：青玉色，用于当前页签、可用状态、选中框和技能准备状态。
- 次强调：鎏金色，用于标题、稀有品质、重要数值和确认操作。
- 风险状态：朱砂红，用于敌对、失败、不可用和危险提示。
- 辅助状态：霜蓝、灵紫、药绿，分别对应法术、秘术和恢复类内容。
- 文字层级：标题 26-30，分区 18-20，正文 14-16，辅助 11-13；所有中文名称优先，英文只保留必要的内部标识。

## 页面清单

| 页面 | 主要区域 | 关键交互 | 视觉重点 |
| --- | --- | --- | --- |
| 主菜单与角色概览 | 角色展示、快捷入口、资源摘要 | 进入背包、技能、地图、任务、图鉴、设置 | 角色或模型是第一视觉焦点 |
| 战斗 HUD | 生命、法力、耐力、职业资源、技能槽、目标、地图 | 技能释放、目标锁定、交互、快捷键 | 信息低干扰，战斗状态优先 |
| 地图与传送 | 地图分类、可传送列表、地图宣传图、详情 | 选择地图、确认传送、翻页 | 右上区域固定显示场景宣传图 |
| 背包与装备 | 分类栏、网格物品、装备槽、详情、对比 | 选择、装备、使用、丢弃、比较 | 图标 + 中文名 + 品质 + 数量 |
| 技能与装配 | 技能列表、详情、预览、时间轴/节点、快捷键 | 选择、装配、修改键位、预览 | 技能表现与配置分区明确 |
| 商店与服务 | 商品网格、详情、货币、操作面板 | 购买、强化、开孔、修理、分解 | 商品列表与操作详情分离 |
| 任务 | 分类、任务列表、任务详情、奖励 | 选择、追踪、领取、放弃 | 不同任务类型使用图标和色带区分 |
| 图鉴 | 类别横向卡片、条目网格、详情和模型 | 分类、选择条目、查看掉落/弱点 | 已发现、未发现、完成度明显区分 |
| 设置与通用弹窗 | 设置分组、确认框、提示、奖励 | 修改、确认、关闭 | 操作反馈统一从顶部或中心出现 |

## 公共组件拆分

现有工程使用运行时 UGUI 构建，并由 `ArpgUITheme` 和 `ArpgUIWindowTools` 统一创建公共控件。本方案保持这个架构，按以下组件职责拆分：

- `UI_Widget_XianxiaWindowFrame`：全屏遮罩、窗口漆面、标题、关闭按钮、金玉分隔线。
- `UI_Widget_XianxiaSection`：分区标题、状态色标记、内容主体和自适应高度。
- `UI_Widget_XianxiaButton`：主操作、次操作、幽灵按钮、危险按钮、页签和槽位按钮。
- `UI_Widget_XianxiaChip`：品质、伤害类型、任务类型、状态和需求标签。
- `UI_Widget_XianxiaProgress`：生命、资源、冷却、施法、任务进度等只读进度条。
- `UI_Widget_XianxiaGridItem`：图标、中文名、数量角标、品质边框、选中和禁用状态。
- `UI_Widget_XianxiaDetailPanel`：标题、图标/模型、数值区、词条区、说明区、底部操作栏。
- `UI_Widget_XianxiaToast`：成功、失败、资源不足、保存成功和系统提醒。

现有页面根预制体继续承担页面入口，公共控件由主题层统一生成；只有需要单独维护美术资源、动画或复杂交互的内容才制作独立预制体。

现有预制体对应关系：

- 战斗 HUD：`UI_HUD_CombatRoot` / `PF_HUD_Combat`。
- 主菜单与角色：`UI_MainMenuRoot` / `PF_Panel_Character`。
- 背包、装备、技能和天赋：`UI_LoadoutRoot`、`UI_InventoryPanel`、`UI_EquipmentPanel`、`PF_Panel_Inventory`、`PF_Panel_Skills`、`PF_Panel_PassiveTree`。
- 地图、传送和秘境装置：`UI_WaypointRoot`、`UI_DungeonTeleportRoot`、`UI_MapDeviceRoot`、`PF_Panel_WaypointMap`、`PF_Panel_MapDevice`。
- 商店和服务：`UI_ShopRoot`、`UI_BlacksmithRoot`、`UI_AssetServicesRoot`、`UI_SkillVendorRoot`、`PF_Panel_Shop`、`PF_Panel_Blacksmith`、`PF_Panel_SkillMerchant`。
- 任务、图鉴、设置：`UI_QuestLogRoot`、`UI_QuestBoardRoot`、`UI_CodexRoot`、`UI_SettingsRoot`、`PF_Panel_Atlas`。
- 通用反馈：`UI_ItemTooltip`、`UI_ItemCompareTooltip`、`UI_FloatingText`、`UI_MapResultPanel`、`UI_DeathPanel`。

## 布局与适配

- Canvas 使用 `1920 x 1080` 参考分辨率，宽高比变化时保持内容安全边距。
- 页面采用左侧导航/列表、中间内容、右侧详情的稳定三栏结构；窄屏时详情栏下移到列表下方。
- 网格条目保持固定最小尺寸，文本通过换行或省略处理，不让布局因名称变化跳动。
- 视觉图片使用 `RawImage/Image` 作为内容展示，图片失败时保留纯色基底和中文标题，不改变布局高度。
- 装饰图形默认关闭射线检测，只有实际按钮、拖拽槽和滚动条参与 UI 射线。
- 页面打开、切页、选中、确认和失败使用统一的高亮/压暗/提示反馈，避免每个页面各自实现一套颜色。

## 数据与刷新边界

- UI 只负责显示和发送用户操作，数据读取与保存由现有窗口及配置服务完成。
- 列表刷新使用“数据变更后重建当前区域”的方式；不在每帧重建网格、文本或图片。
- 选中条目只刷新详情面板和选中态；购买、装备、强化等操作只刷新受影响的条目、货币和详情。
- 视觉样式全部走主题常量和公共创建方法，禁止在业务窗口中散落一套新的颜色或按钮状态。

## 还原顺序

1. 先改公共主题和窗口框体，使所有页面获得统一仙侠底色、标题和按钮状态。
2. 再改主菜单、战斗 HUD、地图/传送、背包/装备和技能页面，作为核心流程。
3. 最后统一商店/服务、任务、图鉴、设置、死亡和通用弹窗。
4. 每完成一组页面，检查 16:9、16:10、21:9 和窄屏下的文本溢出、点击层级和滚动区域。
