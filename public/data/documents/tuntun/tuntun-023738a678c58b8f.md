# 港口建筑玩法覆盖

## 目标

港口建筑不能只提供一行静态数值。每个内置建筑都必须由
`PortBuildingGameplayCatalog` 显式声明以下内容：

- 功能面板名称与实际操作入口
- 持续运行循环及服务对象
- 场景中的可见反馈
- 受损或失效后的明确后果
- 可选运行方案及其真实规则影响

新增建筑不得依赖目录的通用回退资料。覆盖检查会以建筑 ID 报告缺失项。

## 运行时职责

| 玩法域 | 主要承载 | 已接入的真实状态 |
|---|---|---|
| 指挥、居民、生产、仓储 | `PortInfrastructureSystem` | 工人、原料、产量、口粮、库存整理与冷却结果 |
| 港务、维修、贸易、护航 | `PortInfrastructureSystem` | 真实功能船、泊位队列、返港原因、耐久、护航请求与资源账本 |
| 造船厂 | `PortShipyardSystem` | 建造队列、建造耗时、维修队列与部署数量 |
| 英雄与主舰 | `HeroFleetSystem` | 疲劳、伤势、任务响应、巡逻半径、整备耗时与补给状态 |
| 主舰沉没大修 | `StrategicSeaWorldSystem` | 原地沉船倒计时、干船坞复航倍率与复航耐久 |
| 生态、侦察 | `PortInfrastructureSystem` / `StrategicSeaWorldSystem` | 鱼群、污染、稀有度、天气目标、迷雾海域与研究奖励 |
| 防御、墙体、陷阱 | `PortInfrastructureSystem` / 防守控制器 | 伤害、装填、承伤、目标方案、陷阱次数与补充 |
| 场景活动 | `PortActivityController` / `PortBuildingActivityVisual` | 工人、货物、吊机、齿轮、灯光、警告和主动操作脉冲 |
| 功能界面 | `PortHUDController` / `CareerEntityDetailPanel` | 稳定键局部刷新、方案切换、成本、冷却、结果与专属页面入口 |

## 当前差异化闭环

- 信号台直接重排真实进港船队；轻型军港部署现有守卫舰并影响港防装填。
- 维修泊位只处理功能船；轻型维修站按方案处理功能船或受损建筑。
- 声呐站揭示战争迷雾；海洋观测站分析天气、生态或稀有海域并给出收益。
- 人工鱼礁按方案恢复鱼群、治理污染或提高稀有度。
- 船坞的快速建造与维修船台分别改变真实建造和维修耗时。
- 英雄宿舍改变疲劳恢复对象和速度；主舰船坞改变返港整备；舰队指挥中心改变自动响应阈值、支援优先级及巡逻半径。
- 英雄干船坞的完整大修与快速抢修分别改变沉船复航速度和复航耐久。
- 英雄训练场、战斗学院、舰长议事厅/舰队指挥中心和装备锻造坊分别控制成长、技能/天赋、策略和装备加工写操作；设施损毁后保留查看与安全卸装，但停止对应服务。
- 造船厂、英雄设施和干船坞只统计可运行实例，损毁建筑不再暗中保留等级、队列、恢复或复航加成。
- 装饰建筑提供繁荣度，并以各自主题驱动居民活动、货物、旗帜、灯色和动画表现。

## 性能与存档约束

- `PortBuildingOperationRuntimeData` 持久化方案、冷却、最后结果及执行次数；新增字段必须提供旧存档默认值。
- 数值或冷却变化只能局部刷新已打开的建筑面板，不得重建全部 HUD 或全部建筑表现。
- 场景结构只在建筑增删、移动或定义变化时重扫；操作结果通过单建筑活动脉冲反馈。
- 不为单个建筑新增全局管理器，也不在 `Update` 中扫描全部建筑或重复绑定按钮监听。
