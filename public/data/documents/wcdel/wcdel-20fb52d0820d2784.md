# 第一章运行时性能优化同步

## 目标
- 降低第一章内容量增加后战斗场景的 CPU 峰值和 UI 重建频率。
- 保留现有玩法、UI 表现、地图追踪、宠物、任务提示和 2.5D 投影效果。

## 本次优化内容
- 战斗 HUD 不再每帧完整执行引用查找和 UI 结构 Ensure，改为启动强制刷新，运行中定时补查。
- 小地图刷新改为 0.25 秒节流，地图场景点和地形快照改为 2 秒级缓存。
- Boss 血条在未找到或 Boss 死亡后才按 1 秒间隔扫描敌人，已绑定 Boss 时仍每帧刷新血量和读条。
- 任务目标定位增加短时缓存，降低 HUD、小地图、世界标记重复解析 NPC、宝箱、敌人和区域目标的开销。
- 宠物索敌与宠物技能命中复用敌方 Health 缓存，避免每次决策和攻击都全场扫描 Health。
- 敌人目标查找复用玩家缓存，避免玩家未生成时大量敌人每帧查找玩家。
- 任务触发器缓存 PlanarArea / 半径，并在一次性触发后禁用自身 Update。
- 弯曲世界锚点和单位展示根缓存组件角色判断，减少大量 Sprite 物件和单位的 LateUpdate 组件查询。
- 地面标记与投影光圈减少每帧 Ensure 和材质属性重复写入。

## 调整参数
- `CombatCanvasHudPresenter` 小地图刷新：`0.25s`
- `CombatCanvasHudPresenter` 任务目标视觉刷新：`0.15s`

- `Chapter01QuestTrigger2D` 平面检测刷新：`0.12s`

## 2026-07-01 - Second pass runtime optimization

### Goal
- Reduce remaining Chapter01 stutter after environment blockers and dense transparent sprite art were added.
- Keep gameplay, collision, shop interaction, quest triggers, and editable scene assets unchanged.

### Changes
- `PlanarBlocker2D` now uses a spatial grid lookup instead of scanning every blocker for each movement query.
- Player and enemy movement pass cached `CombatTeam` values into blocker checks, avoiding repeated `GetComponent<Combatant>()` in movement hot paths.
- `BossRewardUnlock2D` no longer scans enemies every frame; it refreshes at a low interval and disables itself after the unlock state becomes final.
- `RegionTrigger2D`, `RespawnPoint2D`, and `Chapter01SighSequence2D` now cache colliders/areas, reuse `CombatRuntimeLookup2D.ResolvePlayer()`, and run planar checks at short intervals instead of every frame.
- `RespawnPoint2D` stops updating after activation, preventing repeated respawn activation and repeated full-heal broadcasts while the player stands inside the point.
- `AbilityLockedGate2D` refreshes at a low interval and disables itself once unlocked.
- `WorldPoiGroundMarker2D`, `WorldProjectedMarker2D`, and `GroundProjectedDecal2D` avoid repeated visual setup, duplicate position updates, mesh dirty flags, and material property writes when marker parameters have not changed.
- `LootPickup2D` reuses the shared player lookup, checks pickup range at a short interval, uses squared distance, and caches the player collect anchor during fly-to-player.
- Added `Chapter01RendererCulling2D`, installed by `Chapter01UprightSpriteRuntimeFixer`, to cull far Chapter01 static sprite renderers and clouds with `Renderer.forceRenderingOff` while preserving GameObjects, colliders, blockers, and interactables.

### Validation
- Ran `dotnet build .\WCDEL.sln /p:BuildProjectReferences=false` after the changes with 0 warnings and 0 errors.

### Follow-up
- If runtime is still slow, use Unity Profiler to separate CPU script cost from GPU/overdraw cost.
- Next candidates are texture import size/compression, dense transparent tree/building overdraw, Canvas rebuild spikes, and total active cloud/decor renderer count.
## 2026-07-01 - Third pass render and texture optimization

### Goal
- Reduce persistent Chapter01 stutter after CPU-side lookup and trigger optimizations.
- Focus on GPU overdraw, transparent sprite cost, texture memory, and scene renderer overhead.

### Changes
- `Chapter01RendererCulling2D` now applies a full culling pass immediately during configuration, so far static sprites are hidden before waiting for incremental refresh.
- Reduced Chapter01 static sprite culling distance from `58` to `42` and increased per-refresh checks from `140` to `240`.
- Static Chapter01 renderers now use low-cost renderer flags: no shadows, no receive shadows, no light probes, no reflection probes, no motion vectors, and no dynamic occlusion.
- Far cloud drift components are paused together with their culled cloud renderers.
- `CloudDrift2D` now updates at a low interval instead of every frame.
- `Chapter01EnvironmentArtGenerator` now imports generated environment textures with compression, smaller max texture sizes, and Tight Sprite Mesh for alpha sprites.
- Added `Chapter01TextureImportOptimizer` editor menu to reimport existing Chapter01 environment textures with optimized settings.
- Updated existing Chapter01 environment PNG `.meta` files to remove 2048 max sizes and uncompressed platform entries. Ground/Sky/clouds are capped at 512, buildings/props at 1024.

### Validation
- Ran `dotnet build .\WCDEL.sln /p:BuildProjectReferences=false` with 0 warnings and 0 errors.
- Checked Chapter01 environment texture meta files: 228 meta files, 0 entries with `maxTextureSize: 2048`, 0 entries with `textureCompression: 0`.
- Unity batchmode texture optimizer execution was attempted but blocked by an already-open Unity project instance.

### Follow-up
- If stutter remains, capture Unity Profiler data and identify whether the dominant cost is Rendering, Scripts, Physics2D, UI Canvas rebuild, or Asset Import/Reimport.
- If rendering is still dominant, next step is reducing active decoration counts per area or baking far background decoration into larger chunk sprites.
