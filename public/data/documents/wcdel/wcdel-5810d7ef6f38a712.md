# DNF Character Config Tool Sync

## Goal

Land a usable Unity 2D editor tool for DNF-style side-scrolling action character configuration without replacing the current runtime architecture.

Current implementation focuses on:

- character config data assets
- editor-side authoring and validation
- sample hero / enemy config generation
- placeholder unit / enemy sprites
- runtime bridge into the current prototype controllers
- full-window authoring workflow
- export and validation support for production-facing config iteration

## Scope

### Runtime Definitions

Added a new `CharacterConfigDefinition` asset model with data blocks for:

- core stats
- movement / jump / dash
- combat runtime timing
- skill runtime timing
- hit reaction runtime tuning
- action definitions
- combo chains
- damage events and hit boxes
- skill entries
- AI tuning
- drop settings
- UI display flags
- SFX / VFX placeholders

Added `CharacterActionEnums.cs` to centralize action, hit, AI and resource display enums.

The runtime tuning layer now also covers:

- jump / dash input buffer times
- default attack buffer and combo reset timing
- fallback cancel-window timing and cancel permissions
- air-attack fallback timing
- skill / ultimate cast timing
- skill input buffer and ultimate input buffer timing
- skill-to-dodge cancel timing
- ultimate super armor / invincibility window
- launch threshold and get-up invincibility

### Runtime Bridge

Added `CharacterConfigRuntimeBridge` so a scene character can consume one config asset and push values into existing prototype systems:

- sprite / facing / scale
- health and combat stats
- move speed and acceleration
- dash distance / cooldown / invincibility window
- player combo action list
- player skill slot injection
- simple melee / ranged enemy tuning

This keeps the project on the current runtime path instead of introducing a parallel controller stack.

### Controller Extensions

Extended existing components with config override entry points:

- `TopDownCharacterMotor2D`
- `DodgeController2D`
- `PlayerCombatController`
- `PlayerSkillController`
- `PlayerHitReactionController`
- `SimpleEnemyController2D`
- `SimpleRangedEnemyController2D`

These are still prototype-friendly adapters, not a full side-view combat rewrite yet.

## Editor Tooling

Added editor tools under `Tools/WCDEL/Characters/`:

- `Open Character Config Tool`
- `Create Sample Character Configs`
- `Export All Character Configs To JSON`

### Character Config Tool

`CharacterConfigToolWindow` provides tabbed authoring for:

- identity
- stats
- movement / jump / dash
- animations
- actions
- boxes
- skills / combo
- AI / drop / UI
- preview / validation

The tool now also includes:

- character list with quick actions
- create-new-config workflow
- animation / action / skill indexed editing panels
- combat timeline summary for selected action
- box summary for body / hurt / hit boxes
- selected-config JSON export
- direct validation / ping / inspector jump workflow
- animation spritesheet import helpers
- in-tool animation playback preview with frame stepping, speed, loop and mirror preview

### Animation Import Helpers

The Animations tab now includes helper actions for the selected animation entry:

- apply sprite import settings for the assigned spritesheet
- slice a spritesheet into ordered frame sprites using `FrameWidth` and `FrameHeight`
- reload sliced sprites back into the animation `Frames` array

This keeps the authoring flow inside the existing ScriptableObject asset instead of requiring manual frame-by-frame drag assignment every time.

### Validation

`CharacterConfigValidator` and `CharacterConfigValidationWindow` currently check:

- identity completeness
- box dimensions and active-frame ranges
- animation id uniqueness and frame setup
- action id uniqueness
- action duration and animation binding
- damage event frame ranges and hit box presence
- cancel window frame ranges
- combo references
- skill binding, projectile ranges and runtime skill references
- runtime timing ranges
- AI / drop / boss UI consistency

### Inspector Entry

Added `CharacterConfigInspector` so selecting a `CharacterConfigDefinition` asset also exposes:

- open tool
- validate current config
- export current config to JSON
- ping export folder

### Preview Support

The Preview / Validate tab now supports:

- play / pause
- previous frame / next frame stepping
- playback speed adjustment
- loop toggle
- mirrored preview
- current frame and current time display

Preview currently uses the selected animation entry from the Animations tab and falls back to the first animation when nothing is explicitly selected.

### Box Canvas Editing

The Boxes tab now also includes an in-tool canvas editor for:

- `BodyBox`
- selected `HurtBox`
- selected action `DamageEvent -> HitBox`

Current canvas workflow includes:

- sprite-backed preview using the selected animation frame or default sprite
- mirrored preview for facing-sensitive boxes
- foot-point crosshair and grid overlay
- show / hide toggles for body, hurt and hit boxes
- click-to-select box editing
- drag-to-move for all visible box types
- resize handle editing for rectangle and capsule bounds
- radius resize support for circle boxes
- optional `0.1` unit snap for box offsets and sizes
- box copy / paste for the current selection
- same-kind bulk paste for repeated hurt-box or hit-box tuning
- preview-frame sync helpers for box active frame ranges and selected damage-event frame ranges
- optional current-frame hit-box filtering inside the canvas

This keeps hit / hurt / body box tuning asset-driven inside the same character authoring window instead of pushing those values into runtime code.

## Current Boundaries

- current runtime movement is still prototype 2D free-move, not full DNF lane / gravity / airborne combat
- action FPS timing is still simplified in `PlayerCombatController`
- box editing is editor-window canvas based, not yet a scene gizmo editor or full per-frame timeline track editor
- animation import / slicing is editor-assisted, but still uses the current Unity texture import pipeline rather than a custom dedicated sprite editor
- JSON export is asset-focused and not yet connected to external spreadsheet roundtrip

## Default Scene Integration

The starter scene setup path now also integrates the sample character configs:

- `Setup Starter Test Slice` automatically generates sample character config assets if missing
- the default player gets `CharacterConfigRuntimeBridge` bound to `CharacterConfig_DogHero`
- the default melee and ranged enemies get `CharacterConfigRuntimeBridge` bound to `CharacterConfig_MouseBandit`

To avoid overriding chapter encounter tuning too early, enemy-side default integration currently applies:

- placeholder sprite / visual
- bridge reference wiring

while leaving combat and movement tuning to the existing chapter enemy definitions.

The player path applies:

- visual
- combat stats
- movement
- dash
- combo actions
- skill slot config
- input buffer timing
- cancel / protection runtime timing
- hit reaction protection tuning
