# 任务配置编辑器界面与剧情 MD 文档读取规则完整方案

> 项目类型：2D 横版清版动作 RPG / 妖兽大陆项目  
> 模块范围：任务配置编辑器、任务前置关系、任务目标、任务奖励、任务链路、剧情文档导入、MD 自动生成任务配置  
> 目标：让策划可以在编辑器里完整配置任务，也可以直接导入剧情 Markdown 文档，自动生成可编辑的任务配置草稿。

---

## 1. 设计目标

任务编辑器不只是填任务名和描述，它需要完整管理：

```text
任务基础信息
任务类型
任务前置关系
任务解锁条件
任务接取条件
任务目标
任务阶段
任务目标追踪
任务地图标记
任务奖励
任务对话
任务事件
任务完成条件
任务失败条件
任务保存数据
任务测试预览
剧情文档自动生成任务配置
```

最终目标：

```text
1. 一个任务可以从剧情文档直接生成草稿
2. 策划可以在编辑器里修改所有字段
3. 前置任务、后续任务、任务链路能可视化
4. 任务目标类型足够完整
5. 奖励配置清楚可靠
6. HUD、地图、NPC、对话、奖励弹窗都能通过任务配置自动联动
7. 保存前能自动检查错误
8. 程序运行时可以直接读取任务配置
```

# 6. 任务前置关系页

## 6.1 前置关系页目标

这个页面用于管理任务何时出现、何时可接、何时自动触发。

它必须支持：

```text
前置任务完成
前置任务进行到某阶段
玩家等级
区域已解锁
NPC 已出现
物品已获得
技能已学会
Boss 已击败
变量条件
剧情旗标
多个条件 AND / OR
```

---

## 6.2 前置条件类型

| 条件类型 | 说明 | 示例 |
|---|---|---|
| QuestCompleted | 某任务已完成 | MQ_01 完成 |
| QuestAccepted | 某任务已接取 | MQ_02 已接 |
| QuestStageReached | 某任务达到阶段 | MQ_03 Stage_02 |
| PlayerLevel | 玩家等级 | Lv >= 5 |
| RegionUnlocked | 区域解锁 | 绿叶森林已开放 |
| RegionDiscovered | 区域发现 | 发现蜂鸣花田 |
| NPCAvailable | NPC 可见 | 村长已出现 |
| ItemOwned | 拥有物品 | 古代钥匙 x1 |
| SkillUnlocked | 技能解锁 | 火环术已学会 |
| EnemyKilled | 敌人击杀 | 击败蜂王守卫 |
| FlagTrue | 剧情变量为真 | HasSeenDream = true |
| Reputation | 声望条件 | 犬族声望 >= 10 |
| TimeCondition | 时间条件 | 夜晚触发 |
| RandomChance | 随机触发 | 20% 奇遇概率 |

---

## 6.3 条件组合方式

任务前置条件支持：

```text
AND：全部满足
OR：满足任意一个
NOT：不满足某条件
GROUP：条件组嵌套
```

示例：

```text
解锁任务 AQ_01 月下白狐：

AND
├── QuestCompleted: MQ_04
├── PlayerLevel >= 5
└── OR
    ├── TimeCondition: Night
    └── ItemOwned: 月光铃铛 x1
```

---

## 6.4 前置关系可视化

底部显示任务链路图：

```text
MQ_01 醒来的勇者
    ↓
MQ_02 村外的史莱姆
    ↓
MQ_03 森林边的怪声
    ↓
MQ_04 洞穴里的魔力
    ├── MQ_05 学习火焰魔法
    └── SQ_05 大史莱姆出没
```

节点颜色：

```text
绿色：配置正常
黄色：有警告
红色：有错误
灰色：禁用
紫色：奇遇
```

## 6.5 后续任务配置

每个任务可配置完成后触发：

```text
UnlockNextQuest
AutoAcceptNextQuest
ShowNextQuestHint
OpenRegion
SpawnNPC
EnableShopItem
UnlockDungeon
```

示例：

```text
MQ_04 完成后：
- 解锁 MQ_05
- 解锁 SQ_05
- 开启火焰神殿
- 魔法导师 NPC 显示主线图标
```

# 7. 任务阶段与目标页

## 7.1 任务阶段 Stage

任务可以分多个阶段，每个阶段可以有多个目标。

```text
Quest
├── Stage 01：接任务
│   ├── Objective 01：和村长对话
│
├── Stage 02：前往村外
│   ├── Objective 01：到达南部草地
│
├── Stage 03：击败史莱姆
│   ├── Objective 01：击杀草史莱姆 0/3
│
└── Stage 04：返回交付
    ├── Objective 01：和村长交谈
```

## 7.2 Stage 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| StageID | string | 阶段 ID |
| StageName | string | 阶段名称 |
| StageDesc | text | 阶段描述 |
| StageOrder | int | 顺序 |
| CompleteMode | enum | All / Any / Custom |
| AutoAdvance | bool | 完成后自动进入下一阶段 |
| ShowInHUD | bool | 是否显示在 HUD |
| MapMarkerGroup | list | 该阶段的地图标记 |
| OnStageStartEvents | list | 阶段开始事件 |
| OnStageCompleteEvents | list | 阶段完成事件 |

## 7.3 Stage 完成模式

```text
All：全部目标完成
Any：任意目标完成
Custom：脚本 / 条件表达式
```

## 8.3 目标类型详细规则


## 9.3 屏幕外方向指引

如果目标不在当前屏幕内：

```text
屏幕边缘显示方向箭头
箭头上显示目标类型图标
箭头旁显示距离
如果目标在上方，箭头贴近屏幕上边
如果目标在左侧，箭头贴近屏幕左边
```

规则：

```text
只显示当前追踪任务的主目标
多个目标时显示最近的未完成目标
如果目标在当前屏幕内，隐藏边缘箭头，显示世界图标
```

# 15. MD 读取支持两种模式

## 15.1 严格模板模式

剧情文档按固定格式写，解析准确率最高。

优点：

```text
字段明确
错误少
适合正式配置
不依赖 AI
```

缺点：

```text
写文档时要遵守格式
```

## 15.2 自然剧情模式

剧情文档是普通故事大纲，系统通过规则 + AI 辅助生成任务草稿。

优点：

```text
可以直接用剧情文档
适合快速生成任务草稿
```

缺点：

```text
需要人工确认
不能直接覆盖正式配置
```

推荐流程：

```text
自然剧情文档 → 自动生成任务草稿 → 编辑器确认 → 保存为正式 QuestConfig
```

# 22. 自动拆分任务规则

## 22.1 拆分依据

自然剧情按以下信号拆分任务：


## 22.2 拆分粒度规则

不要把整个章节变成一个任务。  
也不要一句话生成一个任务。

推荐粒度：

```text

```

例子：

```text
和村长对话 → 去村外杀 3 只史莱姆 → 回村长领奖
```

这是一个完整任务。


最重要的是新增 **剧情 MD 导入入口**：

```text
剧情文档不是直接变正式任务，
而是先生成任务草稿，
再由你确认 NPC、目标、奖励、前置关系，
最后保存为正式配置。
```

这样后期你只要写：

```text
第一章剧情文档.md
第二章剧情文档.md
支线剧情文档.md
奇遇剧情文档.md
```

```text

前置关系
```
