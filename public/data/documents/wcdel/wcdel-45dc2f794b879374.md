# 战斗界面 UI 与 HUD 系统设计文档

> 项目类型：2D 俯视角开放世界轻 ARPG  
> 当前章节：战斗界面 UI、技能 UI、角色血条、属性显示、战斗反馈 UI  
> 目标风格：参考《猫咪斗恶龙》这类轻量开放世界 ARPG 的低遮挡、强可读、世界空间血条、可爱圆润 HUD 结构  
> 重要说明：本设计复刻的是“功能结构、布局逻辑、交互节奏和可读性”，不直接复制原版的图标、美术素材、字体、角色形象、UI 图形和具体排版像素。

---

## 1. 战斗 UI 设计目标

战斗 UI 的核心目标不是把信息堆满屏幕，而是让玩家在移动、普攻、翻滚、释放技能时，永远能第一眼看懂：

```text
我还剩多少血？
我还能不能放技能？
敌人快死了吗？
危险攻击在哪里？
我打出了多少伤害？
当前目标和任务有没有变化？
```

本项目的战斗 UI 设计目标：

```text
1. 战斗时界面轻量，不遮挡地图和敌人红圈
2. 玩家血条、蓝条要始终可读
3. 技能按钮要大、圆、清楚，适合移动端点击
4. 冷却、蓝量不足、锁定、可释放状态必须一眼区分
5. 敌人血条和等级要直接贴近敌人，不放复杂目标框
6. Boss 战才显示大型顶部 Boss 血条
7. 伤害数字、暴击、治疗、元素伤害要有明确层级
8. 任务战斗进度要轻提示，不抢战斗视线
9. UI 动画要轻快、有弹性，符合可爱冒险风格
10. 所有 HUD 元素都要支持 PC、移动端、手柄三端输入
```

## 2. 原版式 UI 结构拆解

该类游戏战斗 HUD 的特点是：

```text
世界空间信息多，屏幕固定 UI 少；
角色和敌人的血条通常贴在单位附近；
大部分战斗信息通过伤害数字、红圈预警、技能特效表达；
玩家不需要盯着复杂状态栏；
界面不做 MMO 式大头像、大面板、大量技能栏。
```

因此本项目采用：

```text
角色头顶 / 脚下附近显示轻量生命资源条
敌人脚下显示血条
Boss 顶部显示大血条
移动端右下角显示战斗按钮
PC 端战斗按钮可弱化，只显示技能槽和快捷键
左上角保留小型角色状态卡，可选
右上角显示小地图和任务追踪
```

## 3. 战斗 HUD 总布局

### 3.1 移动端横屏布局

推荐 16:9 横屏。

```text
┌────────────────────────────────────────────┐
│ 左上：角色小状态卡       右上：小地图/任务 │
│                                            │
│                                            │
│              战斗区域 / 地图               │
│        敌人血条、红圈、伤害数字             │
│                                            │
│          玩家角色 + 浮动血条/蓝条           │
│                                            │
│ 左下：虚拟摇杆              右下：技能按钮 │
│                             普攻 / 翻滚    │
└────────────────────────────────────────────┘
```

右下角按钮布局：

```text
             技能3
       技能2       技能4

           普攻按钮

       技能1       翻滚按钮
```

或者更清晰的实战布局：

```text
         技能2      技能3

技能1        普攻        技能4

          翻滚
```

推荐移动端最终布局：

```text
普攻按钮最大
翻滚按钮次大
技能按钮围绕普攻按钮
技能按钮比普攻小 20%~30%
按钮之间留足间距，避免误触
```

### 3.2 PC 端布局

PC 端可弱化虚拟按钮，保留快捷键提示。

```text
左上：角色状态卡
右上：小地图 / 任务
底部中间：技能快捷栏 Q / E / R / F
角色附近：血条 / 蓝条
敌人附近：血条
Boss 顶部：Boss 血条
```

PC 战斗按钮显示：

```text
[Q] 火环    [E] 雷线    [R] 治疗    [F] 陷阱
```

普攻和翻滚不必做大按钮，只在教学阶段提示：

```text
左键：攻击
空格：翻滚
```

### 3.3 手柄布局

手柄模式显示：

```text
X：普攻
A：翻滚
LT + X/Y/B/A：技能
Y：交互
```

技能 UI 可以显示为：

```text
按住 LT 后，在角色右侧或底部显示 4 个技能槽
松开 LT 后技能槽半透明隐藏
```

## 4. 战斗 UI 层级

### 4.1 UI 层级从低到高

```text
地图地面
地面装饰
敌人攻击预警
玩家技能范围
角色 / 敌人
角色世界空间血条
敌人世界空间血条
命中特效
伤害数字
掉落提示
战斗按钮
任务提示
Boss 血条
暂停 / 弹窗
```

### 4.2 UI Sorting Layer 建议

```text
WorldGround
WorldVFX_Back
AttackWarning
Character
WorldVFX_Front
WorldHPBar
DamageNumber
WorldInteractIcon
ScreenHUD
ScreenButtons
ScreenPopup
Fade
```

### 4.3 UI 不遮挡原则

```text
敌人红圈不能被技能按钮遮挡
玩家脚下区域不能被过大的血条遮挡
伤害数字不能挡住预警中心
Boss 血条不能挡住小地图
任务提示不能挡住角色
移动摇杆和右侧按钮必须远离中心战斗区
```

## 5. 玩家战斗状态 UI

### 5.1 玩家世界空间血条

本项目推荐采用类似轻量 ARPG 的“贴近角色显示”的玩家状态条。

显示位置：

```text
玩家角色下方 0.35~0.55 个角色高度
或玩家角色头顶上方 0.45 个角色高度
```

推荐放在角色下方，原因：

```text
不会遮挡角色头部动画
接近原版轻量 HUD 感
玩家能自然看到自己脚下血条
和敌人血条表现统一
```

### 5.2 玩家血条组成

```text
玩家等级徽章
生命条 HP
魔法条 MP
受击闪烁层
护盾层，可选
低血提示
```

结构示意：

```text
   Lv 12
┌────────────────┐
│ HP 红色/粉色条  │
├────────────────┤
│ MP 蓝色/紫色条  │
└────────────────┘
```

或者更原版式轻量表现：

```text
[Lv12] █████████  HP
       █████      MP
```

### 5.3 玩家血条尺寸

移动端建议：

| 项目 | 尺寸 |
|---|---:|
| 血条宽度 | 90~120 px |
| 血条高度 | 8~12 px |
| 蓝条高度 | 5~8 px |
| 等级徽章 | 24~32 px |
| 条间距 | 2 px |
| 外描边 | 2 px |
| 圆角 | 4~6 px |

世界空间缩放规则：

```text
摄像机缩放变化时，血条屏幕尺寸保持基本不变
血条不会随角色远近变得过小
```

### 5.4 玩家 HP 显示规则

| 状态 | 表现 |
|---|---|
| 满血 | 血条正常显示，可半透明 |
| 受伤 | 血条立即显示，血量减少有延迟残影 |
| 低血 | 血条闪烁，屏幕边缘轻红 |
| 受治疗 | 血条绿色加亮，数字上飘 |
| 获得护盾 | 血条外层增加蓝白护盾层 |
| 无敌 | 血条边缘轻微发光 |
| 死亡 | 血条归零，淡出 |

### 5.5 血量减少动画

血条分两层：

```text
即时血量层：立即减少
延迟伤害层：0.25s 后缓慢追上
```

流程：

```text
玩家受到伤害
→ 即时层马上减少
→ 延迟层保持 0.25s
→ 延迟层用 0.35s 缓动减少到即时层
```

这样玩家能感觉到自己刚刚损失了多少血。

### 5.6 低血提示

当 HP 低于 30%：

```text
血条闪烁
角色周围轻微红色心跳光
屏幕边缘出现低透明红色暗角
播放低血提示音，每 8 秒最多一次
```

当 HP 低于 15%：

```text
血条闪烁频率提高
心跳音效更明显，但不能吵
```

低血提示不应遮挡红圈预警。

## 6. 玩家屏幕固定状态卡

### 6.1 是否需要固定状态卡

原版风格偏轻 HUD，玩家自身状态通常贴近角色显示。  
但移动端屏幕复杂时，建议左上角增加一个小型状态卡作为保险。

状态卡可配置开关：

```text
简洁模式：只显示角色附近血条
完整模式：角色附近血条 + 左上状态卡
```

### 6.2 左上角状态卡内容

```text
角色头像
等级
HP 条
MP 条
当前金币，可选
当前经验进度，可选
状态图标，小型
```

示意：

```text
┌───────────────┐
│ 头像 Lv12     │
│ HP ████████   │
│ MP █████      │
└───────────────┘
```

### 6.3 状态卡显示规则

| 情况 | 状态 |
|---|---|
| 平时探索 | 半透明，较小 |
| 战斗中 | 不透明度提高 |
| 受击 | 状态卡轻震 / 血条闪 |
| 低血 | 状态卡红边闪 |
| 打开菜单 | 状态卡隐藏或降低透明 |

### 6.4 状态卡尺寸

| 平台 | 宽度 | 高度 |
|---|---:|---:|
| 手机横屏 | 170~220 px | 70~90 px |
| PC | 200~260 px | 80~100 px |
| 平板 | 220~280 px | 90~110 px |

## 7. 魔法 / 蓝条 UI

### 7.1 蓝条定位

蓝条是技能释放资源，必须跟技能按钮联动。

显示位置：

```text
玩家世界空间血条下方
左上状态卡内
技能按钮不足蓝时变暗提示
```

### 7.2 蓝量变化表现

| 事件 | 表现 |
|---|---|
| 消耗蓝量 | 蓝条立即减少，按钮闪一下 |
| 回复蓝量 | 蓝条轻微发光 |
| 蓝量满 | 蓝条末端小亮点 |
| 蓝量不足 | 技能按钮蓝色闪烁 / 变灰 |
| 获得回蓝 Buff | 蓝条外圈出现流动光 |

### 7.3 蓝量不足提示

按技能但蓝量不足：

```text
技能按钮抖动
按钮颜色变灰蓝
显示小字：魔力不足
播放轻提示音
不弹大提示框
```

提示持续：

```text
0.6s
同一技能 1s 内不重复显示
```

## 8. 技能 UI 总设计

### 8.1 技能按钮数量

推荐 4 个主动技能槽：

```text
SkillSlot_1
SkillSlot_2
SkillSlot_3
SkillSlot_4
```

外加：

```text
普攻按钮
翻滚按钮
交互按钮，非战斗常驻或按需出现
```

### 8.2 技能按钮视觉结构

每个技能按钮包含：

```text
圆形按钮底板
技能图标
冷却遮罩
冷却数字
蓝量不足遮罩
锁定图标
可释放高亮
升级 / 新技能提示点
快捷键文字
技能元素边框
```

结构示意：

```text
┌────────────┐
│  元素边框   │
│   图标      │
│  CD 遮罩    │
│   3.2       │
│ [Q] 快捷键  │
└────────────┘
```

按钮形状：

```text
圆形或圆角正方形
推荐圆形，更接近可爱动作 RPG 手感
```

### 8.3 技能按钮尺寸

| 平台 | 普攻按钮 | 翻滚按钮 | 技能按钮 |
|---|---:|---:|---:|
| 手机 | 82~96 px | 68~78 px | 58~68 px |
| 平板 | 96~110 px | 78~90 px | 70~80 px |
| PC | 48~60 px | 48~60 px | 48~60 px |

移动端点击热区要比视觉按钮大：

```text
视觉 64 px
点击热区 76~84 px
```

### 8.4 技能按钮状态

| 状态 | 表现 |
|---|---|
| Normal 可释放 | 图标清晰，边框轻微亮 |
| Pressed 按下 | 按钮缩放 0.92，亮度提升 |
| Cooldown 冷却 | 灰色扇形遮罩顺时针减少 |
| NoMana 蓝量不足 | 蓝灰遮罩，图标降低饱和 |
| Locked 未解锁 | 锁图标，图标暗色 |
| Disabled 状态禁用 | 整体灰，不能点击 |
| NewSkill 新技能 | 小红点 / 星点 |
| UpgradeAvailable 可升级 | 小上箭头 |
| Selected 被选择 | 外圈高亮 |
| AutoAim 自动辅助中 | 技能边框短暂发光 |

### 8.5 冷却表现

推荐使用径向填充遮罩：

```text
技能释放
→ 按钮瞬间变暗
→ 冷却遮罩从满圆开始
→ 遮罩顺时针逐渐消失
→ 冷却剩余 > 1s 显示整数
→ 冷却剩余 < 1s 显示一位小数
→ 冷却完成按钮弹一下并发光
```

冷却完成动画：

```text
按钮缩放 1.0 → 1.15 → 1.0
外圈光环扩散
播放轻微 ready 音效，可关闭
```

### 8.6 技能释放反馈

按下技能按钮：

```text
按钮缩小
图标变亮
外圈出现短闪
角色播放施法动画
按钮进入冷却
```

释放失败：

| 原因 | 表现 |
|---|---|
| 蓝量不足 | 按钮左右抖动，小字“魔力不足” |
| 冷却中 | 冷却数字放大一下 |
| 被状态禁用 | 按钮灰色闪一下 |
| 未解锁 | 锁图标弹一下 |
| 目标无效 | 显示“无法释放” |

### 8.7 技能元素颜色

| 元素 | 按钮边框 |
|---|---|
| 无属性 | 白 / 银 |
| 火 | 橙红 |
| 冰 | 浅蓝 |
| 雷 | 金黄 |
| 毒 | 绿色 |
| 圣光 / 治疗 | 金绿 |
| 暗影 | 紫黑 |

注意：

```text
危险红圈也使用红色，所以火技能按钮可以偏橙，不要和敌方预警完全相同。
```

### 8.8 技能按钮图标规则

图标需要满足：

```text
64px 下仍可读
主体剪影清楚
不要有复杂背景
同元素技能用统一色系
不同技能类型有不同图形语言
图标外圈和按钮底板分离，方便换皮
```

技能图标分类：

| 类型 | 图标语言 |
|---|---|
| 范围攻击 | 圆环 / 爆炸 |
| 直线攻击 | 闪电线 / 光束 |
| 治疗 | 心 / 光爪 / 十字光 |
| 陷阱 | 地刺 / 符文圈 |
| Buff | 爪印 / 怒气火焰 |
| 召唤 | 小动物影子 / 魔法门 |

## 9. 普攻按钮 UI

### 9.1 普攻按钮定位

普攻按钮是移动端最常按的按钮，必须最大、最顺手。

位置：

```text
右下角核心区域
距离屏幕右边 110~150 px
距离屏幕底边 80~120 px
```

视觉：

```text
大圆按钮
中心是武器 / 爪击图标
边框厚实
按下有弹性缩放
命中时按钮可轻微亮一下
```

### 9.2 普攻按钮状态

| 状态 | 表现 |
|---|---|
| 可攻击 | 正常亮度 |
| 攻击中 | 按钮短暂压下 |
| 攻击冷却 | 极短暗遮罩，可不明显显示 |
| 禁用 | 灰色 |
| 连击窗口 | 外圈短暂闪光，可选 |
| 命中反馈 | 按钮中心亮点扩散，可选 |

### 9.3 普攻按钮尺寸

```text
手机：88~96 px
平板：100~112 px
视觉按钮圆形
点击热区比视觉大 12~20 px
```

### 9.4 普攻按钮音效

| 操作 | 音效 |
|---|---|
| 按下 | 轻按钮声，可非常弱 |
| 攻击释放 | 武器挥砍音 |
| 命中 | 命中音，不从 UI 播放，由战斗系统播放 |

UI 点击声不要盖过战斗音效。

## 10. 翻滚按钮 UI

### 10.1 翻滚按钮定位

翻滚按钮应靠近普攻按钮，但避免误触。

推荐位置：

```text
普攻按钮右下或下方
比普攻小一圈
```

示意：

```text
       技能
技能   普攻   技能
       翻滚
```

### 10.2 翻滚按钮视觉

```text
圆形按钮
图标为小脚印 / 翻滚箭头 / 闪避残影
颜色偏蓝白或浅灰
外圈显示冷却
```

### 10.3 翻滚冷却表现

翻滚冷却较短，可以弱化数字。

```text
翻滚后按钮变暗
外圈径向填充恢复
冷却完成按钮轻弹
冷却小于 1s 可不显示数字
```

### 10.4 翻滚不可用提示

如果当前状态不能翻滚：

```text
按钮变灰
按下时小抖动
不弹文字
```

如果冷却中：

```text
冷却遮罩闪一下
```

## 11. 交互按钮 UI

### 11.1 显示时机

交互按钮不是一直显示，而是按需出现。

```text
玩家靠近 NPC
玩家靠近宝箱
玩家靠近洞穴入口
玩家靠近机关
玩家靠近采集物
玩家靠近任务物品
```

### 11.2 交互按钮位置

移动端推荐：

```text

伤害数值
```

| 类型 | 颜色 | 动画 |
|---|---|---|
| 普通物理 | 白 / 浅黄 | 上飘 |
| 魔法 | 蓝紫 | 上飘 + 微闪 |
| 火焰 | 橙红 | 弹出 + 火苗 |
| 冰霜 | 浅蓝 | 慢速上飘 |
| 雷电 | 金黄 | 快速跳动 |
| 毒 | 绿色 | 小幅上飘 |

```text

逐渐淡出
持续 0.8s
```

暴击：

```text
生成时缩放 0.6 → 1.3 → 1.0
轻微左右抖动
向上弹出
持续 1.0s
```

持续伤害：

```text
小号数字
偏移位置
持续 0.6s
避免刷屏
```

治疗：

```text
绿色数字
向上慢飘
带小星光
```

### 17.5 多数字防遮挡

同一目标短时间受到多段伤害：

```text
每个数字有随机 X 偏移
数字出生高度递增
DoT 可合并显示
同一帧多目标伤害不播放过多大数字
```

最多同时显示：

```text
普通怪周围 5 个
Boss 周围 12 个
全屏总数 40 个
```

超过后：

```text
低优先级小伤害数字合并或丢弃
暴击、玩家受伤、治疗优先保留
```

## 18. 敌人攻击预警 UI

### 18.1 预警 UI 与 HUD 关系

敌人攻击预警属于战斗 UI 的核心信息，优先级高于装饰，但不能盖住角色。

预警层级：

```text
地面之上
角色之下
伤害数字之下
技能按钮之下
```

### 18.2 预警样式

| 预警类型 | UI 表现 |
|---|---|
| 圆形预警 | 半透明红圈 + 外边框 |
| 扇形预警 | 红色扇形区域 |
| 矩形预警 | 长条红区 |
| 直线预警 | 细线逐渐变粗 |
| 环形预警 | 内外圈危险区 |
| 锁定预警 | 玩家脚下红圈跟随 |
| Boss 大招预警 | 红圈 + 边缘闪烁 + 音效 |

### 18.3 预警倒计时表现

预警不能只是一块红色区域，最好有“快触发”的感觉。

推荐：

```text
预警出现时透明度 25%
随时间逐渐变亮到 70%
边框向内收缩或填充
触发前 0.15s 快速闪烁
触发瞬间播放攻击特效
```

### 18.4 预警颜色规则

```text
普通敌方攻击：红色
Boss 大招：红 + 黑边 / 橙红
毒地形：绿色，不作为攻击预警
玩家技能范围：蓝 / 金 / 元素色，避免纯红
友方治疗范围：绿色 / 金色
```


血条：

```text

```

### 25.3 UI 音效原则

UI 音效要轻，不要抢战斗音效。

```text
技能按钮点击声很弱
冷却完成音效可关闭
升级和稀有奖励音效较明显
任务完成音效明显
低血音效限制频率
```

## 31. UI 状态流程

```text

→ 左上状态卡透明度提高
→ 技能按钮亮度提高
```

```text

→ 状态卡透明度降低
→ 技能按钮恢复探索状态
→ 奖励提示完成淡出
```

```text
Boss 触发
→ 屏幕轻微变暗 0.3s
→ Boss 名称出现
→ Boss 血条从顶部滑入
→ 战斗按钮保持显示
→ 小地图可隐藏或缩小
```

### 31.4 Boss 战结束

```text
Boss HP 归零
→ Boss 血条震动并破碎
→ Boss 名称淡出
→ 掉落奖励提示
→ 任务目标更新
→ Boss 血条隐藏
```

## 36. 关键设计总结

战斗 UI 的重点不是“信息多”，而是：

```text
1. 玩家血量必须一眼看见
2. 技能能不能放必须一眼看见
3. 敌人快没血必须一眼看见
4. Boss 阶段变化必须一眼看见
5. 伤害反馈必须爽
6. UI 不能挡住红圈和角色
7. 移动端按钮必须足够大
8. 战斗中不显示不必要的复杂属性
9. 世界空间血条比大型固定面板更适合轻 ARPG
10. 做到“像原版一样轻”，而不是“照搬原版一样的图”
```

最终目标：

```text
玩家不用看复杂面板，也能完成完整战斗判断；
玩家只需要关注角色、敌人、红圈、技能按钮和血条；
界面越轻，战斗越爽。
```
