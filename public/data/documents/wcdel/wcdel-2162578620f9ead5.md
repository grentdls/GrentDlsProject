# Chapter01 Content Pack Sync

## Goal

Map the new `Chapter01` design package onto the current Unity MVP architecture without inventing a second content pipeline, so the existing generated-config flow can boot into a more chapter-shaped playable slice.

## Scope

- Upgraded `FoundationAssetUtility` generated assets from generic starter data to a Chapter01-flavored content pack.
- Added generated Chapter01 definitions for:
  - player starting stats
  - economy tuning
  - 2 starter skills
  - 5 equipment items
  - 2 quests
  - 5 enemy definitions
  - 2 dungeon definitions
  - 1 chapter overworld region
- Updated `GameBootstrapConfig` auto-wiring so new games now inherit the Chapter01 starting region, stats, economy, starter skills and starter equipment.
- Updated player bootstrap setup so the generated chapter stats also drive:
  - runtime HP baseline
  - runtime MP baseline
  - movement stats definition binding
  - initial combatant stats
- Rethemed the starter world slice naming and interaction copy to match the Chapter01 design package:
  - Grass Village
  - Glow Herb quest
  - Grassleaf Cave
  - Bee Field waypoint
  - Hive Guardian boss entrance

## Current Behavior

- Running `Tools/WCDEL/Foundation/Setup Starter Test Slice` now produces a prototype scene that reads like a Chapter01 first playable slice instead of a generic systems sandbox.
- New local save slots inherit Chapter01-flavored start data through the existing bootstrap flow.
- Equipment, skill, quest board, merchant, shrine, cave entrance, teleport waypoint and boss gate all continue to use the current runtime architecture, but now surface chapter-specific content names and rewards.
- Enemy and dungeon definitions are now created in the same generated config folder, ready for later runtime hookup without changing asset paths again.

## Boundaries

- This is still a Chapter01 MVP sync, not a literal full import of the entire content document.
- The runtime still does not consume full drop tables, boss multi-phase logic, quest chains, scene-path loading, or formal skill unlock progression.
- `EnemyDefinition` and `DungeonDefinition` are now generated and documented, but current combat controllers still use local prototype component tuning rather than directly reading those assets.
- Only the subset already representable by the current codebase was synchronized this round.

## Next Suggestions

1. Hook `EnemyDefinition` into scene enemy setup so Chapter01 enemy assets directly drive prototype combat units.
2. Split Chapter01 quest flow into multiple quest board / NPC handoff points once the quest runtime supports more objective types.
3. Add a lightweight chapter bootstrap scene setup pass that places named encounter groups from the Chapter01 map plan.
4. Extend dungeon and boss runtime so the generated `Grassleaf Cave` and `Bee Nest` definitions are consumed beyond editor-side asset generation.
