# 快捷道具栏与背包同步规则

## 功能目标

- 玩家拥有 6 个快捷道具栏槽位，对应战斗快捷键 `1`、`2`、`3`、`4`、`5`、`6`。
- 快捷栏配置存放在玩家运行时/存档数据中，而不是 UI 临时状态。
- 背包界面负责配置快捷栏，战斗 HUD 负责显示和使用快捷栏。
- 背包按钮使用、战斗快捷键使用、战斗 HUD 点击使用统一走 `InventoryItemUseService`，避免效果结算分叉。

## 配置规则

- 快捷栏只允许放入 `InventoryItemCategory.Consumable` 且 `Usable = true` 的消耗品。
- 技能书、任务物品、材料、钥匙、货币、特殊道具默认不放入战斗快捷栏。
- 如果未来需要“特殊战斗道具”进入快捷栏，应先明确配置分类或新增字段，不要临时放宽全部物品。
- 背包中选中可配置消耗品后，点击快捷栏 `1-6` 会绑定该物品。
- 背包中未选中可配置消耗品时，点击已配置快捷栏会清空该槽位。

## 使用规则

- 战斗内按 `1-6` 使用对应快捷栏物品。
- 战斗 HUD 上点击快捷栏按钮也会尝试使用对应物品。
- 战斗中使用必须满足物品 `UseInCombat = true`。
- 数量为 0、未配置、不可用、不可战斗使用时，不消耗物品。
- 物品只有在实际产生恢复、护盾、Buff、净化、学习技能、金币、传送、任务触发或自定义效果时才会消耗。
- 成功使用后会触发 `QuestObjectiveType.UseItem` 任务进度。

## UI 规则

- 后台菜单顶部合并为一行：金币在顶部左侧，页面页签居中，返回/继续在顶部右侧。
- 背包页显示快捷道具栏，文案为“快捷道具栏：选中消耗品后点击 1-6 配置”。
- 战斗 HUD 在技能栏上方显示轻量快捷道具栏，展示快捷键、道具名和数量。
- 快捷栏 UI 通过运行时结构补齐，不直接修改 Prefab YAML，避免覆盖手调 Overrides。

## 修改入口

- `PlayerRuntimeData.QuickItemSlotItemIds` 保存 6 个快捷栏物品 ID。
- `InventoryItemUseService` 统一处理物品能否使用、使用失败原因和效果结算。
- `BackendMenuCanvasPresenter` 负责背包快捷栏配置和后台顶部布局。
- `CombatCanvasHudPresenter` 负责战斗 HUD 快捷栏显示、按钮点击和 `1-6` 快捷键。

## 验证方式

- 打开背包，切到消耗品，选中可使用消耗品后点击快捷栏 `1-6`，应显示道具名和数量。
- 未选中消耗品时点击已配置快捷栏，应清空该槽。
- 进入战斗后 HUD 应显示 6 个快捷栏槽位。
- 按 `1-6` 使用可战斗消耗品，生命/法力/护盾/Buff 等效果应生效并扣除数量。
- `dotnet build WCDEL.sln /p:BuildProjectReferences=false` 应通过且无警告。
