# UI 规则

## 设计原则

本项目 UI 必须服务于“轻量开放世界 ARPG”的核心体验，而不是堆满信息。

UI 目标：

- 可读
- 低遮挡
- 轻快
- 可爱
- 支持 PC、移动端、手柄

## UI 分类

### 1. 战斗 HUD

- 保持轻量
- 不遮挡敌人预警与走位空间
- 玩家生命、技能冷却、交互提示必须一眼可读

### 2. 后台菜单

- 层级浅
- 2 到 3 次点击内完成常用操作
- 装备、技能、任务、设置分组清楚

### 3. 主菜单

- 快速进入游戏
- 视觉轻松、有冒险感
- 不做重运营大厅

## 布局规则

### 屏幕空间 UI

- 左上：角色状态摘要
- 右上：小地图、任务追踪、菜单入口
- 左下：移动端虚拟摇杆区域
- 右下：战斗按钮区域
- 底部中间：PC 技能栏或快捷提示

### 世界空间 UI

- 敌人血条贴近敌人
- 任务点与交互点就地提示
- Boss 使用顶部独立血条

## 适配规则

### PC

- 强化快捷键提示
- 可以弱化大按钮

### 移动端

- 普攻按钮最大
- 翻滚按钮次大
- 技能按钮围绕主按钮布局
- 交互按钮需靠近主操作区且避免误触

### 手柄

- 按钮映射与 HUD 提示一致
- 焦点切换明确

## 视觉规则

- 使用圆角、轻阴影、柔和高对比
- 重要状态用颜色和图标同时表达
- 冷却、资源不足、不可用要显式区分
- 不直接复制参考游戏的图标、排版和视觉素材

## 技术规则

- HUD Canvas 与后台菜单 Canvas 分开
- 世界空间血条与普通屏幕 UI 分层
- 动画以简洁反馈为主，不做过重特效堆叠

## 本阶段要求

基础搭建阶段必须先保留这些 UI 接口：

- 玩家状态区
- 战斗技能区
- 交互提示区
- 暂停菜单入口
- 任务追踪入口

即使暂未完成最终 UI 资源，也必须保证代码与架构上有接入位置。
