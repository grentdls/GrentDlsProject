# 背包装备运行时性能与使用链路修复

## 背景

背包界面打开后存在明显卡顿，装备页会出现旧槽位数据残留，点击普通物品时详情内容偶尔被空装备详情覆盖，装备和道具使用缺少明确反馈或因运行时引用为空而看起来没有效果。

## 修复规则

- 背包页不再每帧完整重建内容，菜单内容改为脏标记刷新，背包页被动刷新间隔为 1.5 秒。
- 菜单结构自检、依赖查找、布局补齐不再每帧执行，打开菜单时立即检查，运行中按低频间隔检查。
- 运行时测试装备只注册定义，不自动塞进玩家拥有列表，避免测试装备污染背包。
- 旧 `Accessory` 字段只作为旧数据兼容入口，新数据统一归并到 `Necklace`，运行时会清空旧字段。
- 背包拥有列表会移除空 ID、未知装备 ID 和旧运行时测试装备 ID。
- 普通物品分页只走普通物品详情刷新，不再先写空装备详情再覆盖。
- 道具使用先确认实际产生效果，再消耗数量；无效果时弹出“物品未消耗”提示。
- 装备成功、装备失败、道具成功、道具无效都会给出中文结果提示。
- `CombatHudDataSource` 支持主动刷新引用，避免后挂组件或 Awake 顺序导致回血、回蓝、护盾、装备属性同步失效。

## 验证

- `dotnet build WCDEL.sln /p:BuildProjectReferences=false`
- 编译通过，0 warning，0 error。

## 后续注意

- 不要重新启用每帧 `RefreshPageContent` 或每帧 UI 结构扫描。
- 若后续需要新增真正的饰品槽，应新增明确槽位和 UI 规则，不要复用旧 `Accessory` 兼容字段。
- 背包 Prefab 的手调布局应优先通过 Overrides 保存；运行时代码只做必要兜底，不应覆盖策划手调参数。
