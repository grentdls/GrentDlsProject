# Chapter01 Expanded Battlefield And Camera Sync

## Goal

Expand the current `Sandbox_Combat` prototype into a much larger combat field, spread enemies and interactables across a more readable route, define terrain regions such as plains, grassland, shallow water and deep-water borders, and keep the player visible by making camera follow and bounds match the new battlefield scale.

## Scope

- Expanded the Chapter01 sandbox route from a compact pocket into a much wider horizontal prototype lane with distinct left, middle and boss-side spaces.
- Repositioned player spawn, shrine, NPC, shop, quest board, cave entrance, portals, chests, enemies and boss-route objects so they are distributed across the larger map instead of clustering around the original start area.
- Added generated terrain definition assets for:
  - `Plain`
  - `Shallow Water`
  - `Deep Water`
- Reused the existing `TerrainZone2D` architecture and added larger zone placements for:
  - village plain
  - main road
  - south grassland
  - east meadow
  - shallow water lowland
  - poison swamp
  - bee field grassland
  - boss approach plain
  - north / south deep-water borders
- Updated runtime sandbox layout safety pass so the scene still corrects itself to the expanded coordinate set even if editor-side scene content lags behind.
- Hardened the runtime bootstrap path so entering `Sandbox_Combat` from load flow or direct scene play both trigger the expanded layout and camera setup.
- Updated camera defaults and camera trigger profiles so the player stays on screen while moving through the expanded field.

## Current Behavior

- New runs in `Sandbox_Combat` start in a wider left-side village area instead of a cramped combat pocket.
- Enemies now occupy separated encounter pockets across the route:
  - slimes in the south grass route
  - cave bats in upper meadow and cave-side spaces
  - poison bees in a more distant bee field
  - captain and boss near the far-right approach and arena
- Terrain reads as a rough gameplay map instead of a single flat prototype:
  - plains and road support the safe approach
  - grassland frames combat lanes
  - shallow water slows movement in the lowland detour
  - poison swamp remains a more dangerous route pocket
  - deep water marks outer map borders
- Camera follow now uses the larger battlefield bounds by default, and the runtime scene pass no longer reapplies the old compact default profile immediately after binding the player target.
- The bootstrapper now re-applies the sandbox layout across the first few loaded frames without resetting saved player positions, which helps camera follow recover even if scene objects initialize a little later.
- Camera trigger zones still shape the experience, but they now align with the larger start area, mid-route and boss arena spaces.

## Boundaries

- This is still a generated prototype battlefield, not a full authored overworld with tilemap art, collision painting or procedural biome generation.
- Deep water currently communicates boundary and traversal blocking through terrain definition and region placement; final movement blocking visuals and collision walls can still be refined later.
- Encounter positions remain handcrafted in editor utility code, which is acceptable for the current slice but should eventually move into a more data-driven layout source if multiple maps need the same workflow.

## Next Suggestions

1. Rebuild the sandbox scene once in Unity so the generated scene content and prefab visuals fully reflect the new zone set.
2. Add light landmark props or background dressing per region so plains, bee field, cave route and water edges are easier to read at a glance.
3. Add explicit collision blockers or navigation shaping around deep-water edges if the team wants firmer movement containment than terrain rules alone.
