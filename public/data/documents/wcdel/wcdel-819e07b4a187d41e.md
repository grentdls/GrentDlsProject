# 资源规则

## 总原则

- 不直接使用参考游戏素材
- 不随意移动大资源、场景、Prefab
- 资源命名、目录、用途必须清楚
- 先有目录规范，再逐步导入内容

## 目录规则

- `Assets/Game/Art`：正式美术资源
- `Assets/Game/Audio`：正式音频资源
- `Assets/Game/Prefabs`：正式 Prefab
- `Assets/Game/Scenes`：正式场景
- `Assets/Game/UI`：UI 资源与 UI Prefab

## 命名规则

建议格式：

```text
模块_类别_名称_变体
```

示例：

- `Player_Prefab_BearHero`
- `UI_Icon_SkillFireball`
- `Enemy_Slime_Green`
- `SFX_Combat_Hit01`
- `Region_StarterField`

## Sprite 规则

- 明确像素风或非像素风路线后再统一导入设置
- 同类角色动画使用一致的切片规则
- 朝向、攻击、受击、翻滚命名统一

## Prefab 规则

- Prefab 必须有清晰职责
- 玩家、敌人、交互点、掉落物、UI 组件分别建类
- 不要把大量一次性逻辑直接写死在场景对象上

## Scene 规则

- 场景中逻辑物体按父节点分组
- Tilemap、交互点、敌人刷点、触发器分层清楚
- 不直接手工重排大型 YAML，尽量通过 Unity 编辑器完成

## ScriptableObject 规则

- 统一作为静态定义资产
- 一个资产只表达一类核心含义
- ID、显示名、描述、数值范围要清楚

## 音频规则

- BGM、UI、战斗、环境音分目录
- 命名上体现用途与区域
- 同类音效尽量提供 3 到 5 个轻变化版本

## 调试资源规则

- 调试占位图、临时材质、测试 Prefab 应标记为 `Debug` 或 `Temp`
- 正式资源接入后及时替换或移除

## 本阶段要求

基础搭建阶段允许使用：

- 空目录
- 占位 Prefab
- ScriptableObject 定义资产
- 编辑器工具生成的基础对象

但必须保证后续正式资源能无痛替换进去。
