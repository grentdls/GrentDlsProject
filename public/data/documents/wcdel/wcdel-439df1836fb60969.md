# Quest System UI Editor Full Sync

## Scope

This follow-up implements the first MVP slice aligned with `Docs/quest_system_ui_editor_full_design.md`.

## Runtime Upgrades

- Expanded quest categories and objective types to cover talk, buy, chest, skill learn, and equipment objectives.
- Added runtime quest status, tracked quest id, available quest list, completed quest list, and timestamped quest state updates.
- Introduced `QuestPresentationHelper` and `QuestPresentationSnapshot` as a shared formatting/query layer for future HUD, backend menu, and quest popup work.
- Upgraded `GameSession` so quest accept, progress, completion, availability, and tracking now use one consistent runtime path.

## Event Wiring

- Extended `QuestEventRouter` beyond collect/kill so existing gameplay interactions can now report:
  - NPC talk
  - item purchase
  - chest open
  - skill learn
  - equipment equip
- Wired current world interactions into the quest event flow:
  - `NpcDialogueInteractable2D`
  - `ShopInteractable2D`
  - `RewardChestInteractable2D`

## Runtime UI Follow-up

- Upgraded `QuestBoardInteractable2D` so board quests now register into the available quest list, prioritize available and active quests correctly, and auto-track a quest after accept or manual progress check.
- Upgraded backend quest page rendering to `BuildQuestPageMvp`, which now shows:
  - tracked quest summary
  - in-progress quest list
  - available quest list
  - completed quest list
- Wired quest progression to real gameplay actions in `GameSession`:
  - learning a new skill now reports `LearnSkill`
  - equipping gear now reports `EquipItem`
- Upgraded combat HUD quest tracking to consume `QuestPresentationHelper.GetTrackedQuestSnapshot(session)` and render:
  - category + quest title
  - objective + progress
  - target hint
  - lightweight direction / distance text for off-screen tracking
- Added a lightweight quest feedback strip on the combat HUD, driven by runtime quest events instead of one-off board-only text:
  - quest accept feedback
  - objective completed feedback
  - reward claimed feedback
  - tracked quest feedback
- Routed quest feedback through `GameSession.QuestFeedbackRaised`, so future NPC quest dialogs, reward popups, and backend quest interactions can reuse one feedback path.
- Added a dedicated quest reward popup on the combat HUD center layer for `RewardClaimed` events:
  - keeps accept / progress / tracking updates in the lightweight top-right strip
  - elevates only the actual reward-claim moment into a more formal centered reward presentation
  - reuses the same runtime quest feedback event flow instead of creating a second reward system
- Upgraded quest reward payloads from plain summary text into structured reward entries:
  - reward events now carry typed reward entry data for gold / experience
  - the centered reward popup now renders reward lines from structured entries instead of one flat summary string
  - this keeps the current implementation lightweight while opening a clean path for future equipment / item / skill reward rows
- Added a visual quest target layer to `CombatCanvasHudPresenter`:
  - a screen-edge arrow when the tracked target is outside the viewport
  - a lightweight world target label + distance marker when the tracked target is on screen
- Upgraded the quest target visuals from plain placeholder widgets into a more formal lightweight style:
  - category-based accent colors for main / side / bounty / tutorial / encounter / explore / collect / class quests
  - objective-type glyph mapping so talk, chest, combat, shop, region, skill, and equipment targets read differently at a glance
  - subtle pulse animation on both the world marker and screen-edge arrow to improve readability without over-blocking the playfield
- Synced the fallback HUD presenters `CombatHudPresenter` and `PrototypeHudPresenter` to the same tracked-quest snapshot path, so debug and prototype overlays no longer diverge from the main combat canvas HUD.
- Added runtime quest tracker compatibility growth in `CombatCanvasHudPresenter`, so old combat HUD prefabs can auto-create `Hint` and `Direction` rows without forcing an immediate prefab rebuild.
- Added `QuestTargetLocator` as a lightweight world target resolver for NPC, chest, enemy, shop, collectible, respawn point, and region objectives.
- Exposed minimal read-only ids/properties on existing interactables to support shared quest target lookup without introducing a new tracking system.
- Synced the generated combat HUD structure in `UiPrefabFactory`, so rebuilding generated / override combat UI now also includes the quest feedback strip instead of relying only on runtime patch-up.
- Synced `UiPrefabFactory` so rebuilt combat HUDs also include the quest reward popup structure on the center layer.

## Editor MVP

- Added `QuestEditorWindow` under `Tools/WCDEL/Quest/Open Quest Editor`.
- Added `QuestValidator` for basic field validation.
- Added `QuestDesignDraftUtility` to generate JSON quest draft files from story text documents without overwriting official quest assets.

## Current Limitations

- The world marker and edge arrow are still lightweight glyph-based HUD widgets, not yet a full sprite icon atlas / authored animation quest pointer system.
- Quest reward feedback now has a centered lightweight popup with structured reward rows, but it is still text-first and not yet the full icon-rich reward list / animation-heavy completion flow described in the design doc.
- World quest markers are still not implemented as a separate world-space reward popup flow in this MVP slice.

## 2026-05-21 Backend Quest Page Follow-up

- Replaced the backend quest page's text-only MVP view with a structured runtime page:
  - left-side quest filters for all / active / available / completed
  - clickable quest list rows
  - right-side detail panel for status, objective, progress, reward, and target hint
  - action buttons for track, accept, and claim reward
- Added runtime self-heal for old Backend UI prefabs and Overrides. If a quest page only has the old `PageBody`, the presenter now creates the structured quest layout at runtime and keeps the old text body hidden as a compatibility fallback.
- Synced `UiPrefabFactory` so newly rebuilt generated Backend UI prefabs include the same structured quest page instead of relying only on runtime patch-up.
- Wired the generated prefab references for quest list/detail/action buttons into `BackendMenuCanvasPresenter`.
- Cleaned quest presentation labels so category, status, objective type, progress, and hints display as readable Chinese instead of mojibake.
- The previous `_selectedQuestFilter` / `_selectedQuestId` fields are now fully used by the interactive page flow.
