# Combat Canvas HUD Foundation Sync

## 目标

把战斗 HUD 从纯 IMGUI 调试面板推进到可持续扩展的 Canvas 基础层，为后续移动端按钮、Boss 血条、Buff 图标和奖励提示留出正式接入口。

## 本次范围

### Canvas HUD 基础层

- 新增 `CombatCanvasHudPresenter`
- 运行时自动构建左上玩家状态卡、右下战斗技能区、右上任务追踪和中央警告提示
- 继续复用 `CombatHudDataSource`，不新起一套 HUD 数据获取链路

### Safe Area 适配

- 新增 `SafeAreaLayoutFitter`
- 让 `Canvas_BattleHUD/SafeAreaRoot` 根据设备安全区域更新锚点
- 为后续移动端和异形屏布局预留统一入口

### 编辑器脚手架同步

- 扩展 `Setup Starter Test Slice`
- 自动创建 `Canvas_BattleHUD`、`SafeAreaRoot`、`CombatCanvasHUD`
- 自动创建 `EventSystem`
- 自动停用旧的 `PrototypeHUD` 和旧的 `CombatHudPresenter` IMGUI 原型

### 程序集依赖

- 在 `WCDEL.Game.Runtime.asmdef` 中新增 `Unity.ugui` 引用
- 允许运行时代码正式使用 `Canvas`、`Text`、`Image`、`CanvasScaler` 和 `GraphicRaycaster`

## 本次不做

- 正式 HUD 美术资源、图标、字体和动效
- 真正的移动端虚拟摇杆和技能按钮点击输入
- Boss 顶部血条、Buff/Debuff 图标、奖励 Toast、升级提示
- 世界空间血条从 IMGUI 迁移到对象池化 Canvas

## 后续建议

1. 把 `CombatCanvasHudPresenter` 按模块拆成 `PlayerStatusCard`、`CombatSkillCluster`、`QuestTrackerPanel` 等独立组件。
2. 用正式 `Image` 填充条替换当前文本式 HP / 技能状态显示。
3. 把移动端按钮显示和实际输入桥接起来，并接入 PC / 手柄提示切换。
4. 引入统一 HUD 事件层，减少后续 `Update` 轮询式刷新的占比。
