# Skill Movement And Displacement Rules

> Scope: skill-side movement, teleport, multi-stage dash, leap smash, rush collision, invulnerability window, and editor configuration rules.
> World rule: logic is 3D. X = left/right, Z = forward/back depth, Y = jump, launch, floating height. Character art is 2D sprite presentation in a 3D world.

## 1. Goals

- Skill configuration must support displacement as first-class data, not only damage volume and VFX.
- A skill may move the caster during one or more frame windows.
- A skill may teleport the caster to a validated target point.
- A skill may perform a leap or jump smash with real Y-axis height.
- A skill may optionally ignore unit collision, pass walls, rush-hit enemies, or grant invulnerability during movement.
- Skill movement preview must be visible in the character config tool and skill detail preview.
- Movement, hit volume, ground projection, VFX, camera feedback, and combat impact must stay synchronized.

## 2. Relationship With Action Movement

Current authoring rule:

- `CharacterActionDefinition.Movement` is the primary movement entry.
- Normal attack, air attack, skill action, and ultimate action all configure displacement on the bound action.
- `CharacterActionMoveDefinition` remains as hidden legacy/simple compatibility data only and should not be shown as a normal authoring panel.
- `CharacterSkillEntryDefinition.Movement` remains only as a fallback for old skill data.

Why movement moved to actions:

- Normal attacks also need dash, step-in, leap, teleport, invulnerability, and super armor windows.
- Skills already bind a `BoundActionId`, so skill movement should follow that action instead of being authored in a separate place.
- Action frame data, damage events, VFX frame events, cancel windows, and movement frames must be edited in one page.

Runtime priority:

```text
Bound Action Movement > Skill fallback Movement > hidden legacy ActionMove compatibility > ordinary player input movement
```

If action movement is active, ordinary input movement is paused unless the segment explicitly allows steering.

## 3. Data Model Draft

Recommended runtime data entry:

```csharp
CharacterActionDefinition.Movement
```

Recommended main block:

```text
CharacterSkillMovementConfig
```

Fields:

| Field | Type | Rule |
|---|---|---|
| Enabled | bool | Whether this skill has skill-side movement. |
| LockFacingOnStart | bool | Locks facing at cast start. |
| RetargetPolicy | enum | Whether each segment reselects target or uses cast-start target. |
| InterruptPolicy | enum | What happens if blocked, hit, stunned, or target invalid. |
| Segments | list | Ordered movement segment list. |
| ShowPathPreview | bool | Show path in config tool and skill UI. |
| ShowLandingProjection | bool | Show landing / teleport target projection. |

Recommended segment block:

```text
CharacterSkillMovementSegmentDefinition
```

Fields:

| Field | Type | Rule |
|---|---|---|

| Mode | enum | Dash, teleport, leap smash, retreat, pull, etc. |
| StartFrame | int | Segment starts at skill action frame. |
| DurationFrames | int | Segment lasts this many frames. Teleport can be 1 frame. |
| Distance | float | Main movement distance on XZ plane. |
| MaxDistance | float | Target-based movement clamp. |
| MinDistance | float | Optional minimum displacement before segment is valid. |
| SpeedCurve | enum / AnimationCurve | Movement interpolation curve. |
| TargetMode | enum | How target point is selected. |
| TargetOffset | Vector3 | Offset relative to target point, target forward/back, or caster. |
| UseInputDirectionFallback | bool | Uses input direction when no valid target exists. |
| AllowSteering | bool | Allows limited input steering during segment. |
| SteeringRate | float | Steering strength, 0 means no steering. |
| IgnoreUnitCollision | bool | Caster does not get pushed by unit bodies during this segment. |
| CanPassThroughEnemy | bool | Caster may pass through enemies. |
| StopOnEnemy | bool | Segment stops when touching an enemy body. |
| CanRushHitEnemy | bool | Segment can trigger rush hit while moving. |
| RushHitInterval | float | Minimum time between repeated rush hits on same target. |
| CanPassWall | bool | Allows passing terrain blockers. Default false. |
| StopOnWall | bool | Stops at wall if blocked. Default true. |
| RequireWalkableGround | bool | Target must be on valid ground / platform. |
| ClampToValidGround | bool | Invalid target is clamped to nearest valid point. |
| InvincibleDuringMove | bool | Grants full invulnerability during this segment. |
| SuperArmorDuringMove | bool | Grants super armor, but still takes damage unless invincible. |
| HideDuringTeleport | bool | Optional presentation hide during teleport. |
| LeapHeight | float | Y-axis arc height for leap smash. |
| LandingImpactFrame | int | Frame to trigger landing damage or shockwave. |
| LandingRecoveryFrames | int | Recovery after landing. |

## 4. Movement Modes

### 4.1 None

No skill-side displacement.

Use when:

- Skill only plays animation, VFX, projectile, or area damage.

### 4.2 Directional Dash

Caster moves along a resolved direction on the XZ plane.

Direction sources:

- Current facing.
- Last movement input.
- Cast input direction.
- Caster-to-target direction.
- Fixed world direction.

Rules:

- Movement changes X/Z only unless segment has leap height.
- Y remains controlled by current grounded / airborne state.
- Unit collision behavior is controlled by segment flags.

### 4.3 Target Point Dash

Caster dashes toward a point, but movement is continuous.

Target point sources:

- Mouse / world cursor ground point.
- Locked target ground position.
- Nearest enemy ground position.
- Skill aim indicator point.
- Current movement input projected to max distance.

Rules:

- If target is farther than `MaxDistance`, clamp to max distance.
- If target is closer than `MinDistance`, optionally cancel or use minimum distance.
- If blocked by wall and `CanPassWall` is false, stop or clamp according to segment flags.

### 4.4 Teleport To Point

Caster instantly relocates at the trigger frame.

Rules:

- Teleport uses `StartFrame` as the relocation moment.
- `DurationFrames` controls presentation lock, not travel time.
- Pre-teleport VFX plays before relocation.
- Post-teleport VFX plays after relocation.
- Target must pass walkable and wall rules unless `CanPassWall` is true.
- Teleport should not push enemies. If attack is needed, use a landing or arrival damage event.

### 4.5 Teleport To Target

Caster teleports relative to an enemy, NPC, object, or locked target.

Target offset modes:

- Target front.
- Target back.
- Target left side.
- Target right side.
- Target center.
- Target body edge plus configured distance.

Rules:

- "Front/back" is based on target facing when available.
- If target has no facing, use caster-to-target direction.
- If target position is invalid, fallback to nearest valid ground point or cancel segment.
- Teleport behind target must not place caster inside walls or unwalkable platforms.

### 4.6 Multi-Segment Movement

A skill may contain multiple ordered movement segments.

Examples:

- Dash forward, slash, dash behind target, slash again.
- Step back, charge, rush forward.
- Teleport to target front, bounce to target back, landing strike.

Rules:

- Each segment has its own target resolver and collision flags.
- Segment order follows list order and frame timing.
- Segments may overlap only if explicitly allowed; default validation should warn about overlap.
- Retarget can happen per segment or be locked at cast start.
- If one segment is blocked, `InterruptPolicy` decides whether to stop all later segments, skip this segment, or continue from current position.

### 4.7 Leap Strike

Caster performs a real Y-axis jump arc while also moving on XZ.

Rules:

- Movement contains XZ displacement plus Y arc.
- Y movement must use logic height, not only sprite offset.
- During leap, caster may count as airborne for hit height and ground attack avoidance.
- Landing may trigger damage, screen shake, hit stop, and ground decal.
- Landing point must follow valid ground rules unless `CanPassWall` and special skill rules allow otherwise.

### 4.8 Jump Smash

A leap strike variant where the main hit happens at landing.

Required fields:

- Leap height.
- Rise frames.
- Hang frames.
- Fall frames.
- Landing impact frame.
- Landing damage volume.
- Landing ground projection preview.

Rules:

- Warning circle / ground projection appears at predicted landing point.
- Damage volume triggers at landing impact frame.
- If landing point is invalid, clamp or cancel according to segment rules.
- If caster is hit during leap and does not have super armor or invincibility, the skill may be interrupted and fall logic takes over.

### 4.9 Retreat / Backstep

Caster moves away from target or opposite facing.

Use when:

- Archer-like enemies reposition.
- Player skills evade then counterattack.

Rules:

- Default direction is negative facing direction.
- Target-based retreat uses target-to-caster direction.
- Cannot pass wall unless configured.

### 4.10 Pull To Target

Caster moves toward a target and stops at a configured distance.

Use when:

- Hook slash.
- Short pursuit skill.
- Enemy lunge.

Rules:

- Stop distance should account for both body boxes.
- If target moves, retarget policy determines whether the path updates.
- If target dies before arrival, fallback to last known target point.

## 5. Target Selection Rules

Target mode enum should include:

| Target Mode | Meaning |
|---|---|
| CasterForward | Current facing direction. |
| InputDirection | Current skill input direction. |
| LastMoveDirection | Last non-zero movement direction. |
| AimPoint | Mouse / stick / skill indicator world point. |
| LockedTarget | Current lock-on target. |
| NearestEnemy | Nearest valid enemy in skill range. |
| LowestHpEnemy | Optional AI-friendly target rule. |
| TargetFront | Position in front of target. |
| TargetBack | Position behind target. |
| TargetSide | Position at target side. |
| FixedWorldDirection | Fixed XZ world vector. |
| ScriptedPoint | Designer-authored point for enemy / boss skills. |

Validation order:

```text
Resolve raw target -> apply offset -> clamp distance -> validate wall/platform -> clamp ground -> final target
```

Fallback order:

```text
Primary target invalid -> configured fallback target -> input direction -> caster forward -> cancel segment
```

## 6. Collision And Traversal Rules

Skill movement must not reuse ordinary soft unit pushing blindly. It needs explicit rules.

### 6.1 Unit Collision Flags

| Flag | Behavior |
|---|---|
| IgnoreUnitCollision | Caster is not pushed by unit collision during segment. |
| CanPassThroughEnemy | Caster may cross enemy body volume. |
| StopOnEnemy | Segment ends when enemy body is reached. |
| CanRushHitEnemy | Movement can deal rush hit to enemies crossed or touched. |

Important rule:

```text
Unit movement must not push other units away unless this segment enables rush hit / collision impact.
```

This follows the existing combat rule that normal movement should not squeeze the player or enemies away. Knockback, launch, and rush displacement must come from combat impact configuration.

### 6.2 Wall And Terrain Flags

| Flag | Behavior |
|---|---|
| CanPassWall | Allows crossing terrain blockers. Default false. |
| StopOnWall | Stops at the first wall hit. Default true. |
| RequireWalkableGround | Target point must be walkable. |
| ClampToValidGround | Invalid target is moved to closest valid point. |

Platform / height rule:

- Ordinary dash cannot move from a low platform to a high platform unless the target is connected by walkable path or the skill is configured as leap / teleport that permits height transition.
- Leap can change Y during the skill, but landing still requires valid landing ground.
- Teleport can cross height only if the skill explicitly allows it and target validation succeeds.

## 7. Invulnerability, Super Armor, And Interruption

Segment-level defensive flags:

| Flag | Rule |
|---|---|
| InvincibleDuringMove | Ignores damage and hit reactions during segment. |
| SuperArmorDuringMove | Takes damage but ignores hit stun, knockback, and launch. |
| IgnoreBodyPushDuringMove | Cannot be moved by body collision. |
| CanBeInterrupted | If false, only death or scripted force stop can cancel. |

Priority:

```text
Death > scripted force stop > invincible ignore hit > super armor ignore reaction > normal hit interrupt
```

Designer guidance:

- Dodge-like movement should use short invulnerability, not long invulnerability.
- Rush attack should usually use super armor, not full invulnerability.
- Ultimate movement may use both, but must be clearly visible.

## 8. Rush Hit Rules

Rush hit is movement-caused attack contact. It is different from ordinary body collision.

Requirements:

- `CanRushHitEnemy = true`.
- A damage source must be linked to the skill entry or a movement segment damage event.
- Target must be inside the segment rush volume or crossed by the swept path.

Runtime rules:

- Each target has hit deduplication per segment.
- Repeated hits require `RushHitInterval > 0`.
- Rush hit uses the skill's `Impact` block unless the segment overrides it.
- Knockback / launch still uses target body size, resistance, and skill impact power.
- If target has super armor or anti-rush state, damage may apply but displacement reaction can be ignored.

Swept path:

```text
Previous caster body volume -> current caster body volume -> swept capsule / box -> target hurt volume
```

This avoids missing enemies when the caster moves quickly.

## 9. Teleport Rules

Teleport has no travel collision, but target validation is strict.

Validation:

- Target point must exist.
- Target point must be within cast range unless skill explicitly ignores range.
- Target point must be on walkable ground if required.
- Target point must not be inside wall unless `CanPassWall` is enabled and final point is legal.
- Target point must not overlap a blocking unit unless `CanPassThroughEnemy` or `IgnoreUnitCollision` permits it.

Presentation:

- Pre-teleport flash at caster foot / body.
- Optional hide frames.
- Relocate at exact frame.
- Arrival flash at destination.
- Optional afterimage line between source and destination.

Damage:

- Teleport alone does not damage.
- Damage should be configured as arrival impact, slash frame event, or skill area volume.

## 10. Leap And Jump Smash Rules

Leap movement must use real logic Y.

Coordinate rules:

```text
XZ = horizontal travel on ground plane.
Y = airborne height above current ground / platform.
```

Arc rules:

- Rise frames move from Y 0 to `LeapHeight`.
- Hang frames keep near peak if configured.
- Fall frames move back to landing ground.
- Landing frame snaps to valid landing ground only after validation.

Hit height:

- During leap, caster is airborne.
- Low ground attacks can miss airborne caster if existing hit-height rules say so.
- Anti-air or high hit volume can hit airborne caster.

Landing damage:

- Landing impact uses true 3D hit volume.
- Ground red circle / warning circle is only XZ projection.
- Damage volume height must cover intended targets. A ground shockwave can have low Y height; a slam explosion can have taller Y height.

Runtime height cleanup:

- Leap and jump-smash segments may temporarily override the caster's logic Y height.
- The override is owned only by the currently active leap / jump-smash segment.
- If the current action frame is outside all active leap-height segments, runtime must immediately clear the skill height override and snap the caster back to the cached ground Y.
- Skill finish, skill cancel, component disable, hit interruption, dodge cancel, and invalid movement interruption must also clear the skill height override.
- Clearing a skill height override must not recache the current airborne Y as the new ground height before snapping down.

Blocked landing:

- If landing point becomes invalid before impact, choose one policy:
  - Clamp to nearest valid ground.
  - Land at last valid point.
  - Cancel into fall.
  - Interrupt skill and play stumble.

## 11. Scaling Rules

Skill movement distance can optionally be affected by character attributes.

Recommended attribute hooks:

| Attribute | Affects |
|---|---|
| SkillRangeMultiplier | Dash max distance, target acquisition range. |
| SkillRadiusMultiplier | Rush hit width, landing projection radius. |
| VfxScaleMultiplier | Movement trail, landing VFX scale. |
| ProjectileCountBonus | Not directly related unless movement spawns projectiles. |

Default:

- Movement distance should not scale unless `UseSkillRangeScale = true`.
- Hit volume and projection should still use existing skill radius / range scaling rules.
- VFX path length should match actual movement result, not raw configured distance.

## 12. Runtime Execution Flow

Recommended flow:

```text
Skill input accepted
-> Resolve skill entry and bound action
-> Build movement context from caster, target, input, stats
-> Pre-resolve cast-start targets if RetargetPolicy requires
-> Play skill action
-> On each frame, activate matching movement segment
-> Resolve / update target point
-> Validate movement path
-> Apply XZ displacement and optional Y arc
-> Evaluate rush hit swept volume
-> Trigger frame VFX / SFX / damage / projectile
-> Finish segment
-> Finish skill action and restore normal movement rules
```

Component responsibilities:

| Component | Responsibility |
|---|---|
| `PlayerSkillController` | Accept skill input, cooldown, cost, action binding, movement executor start. |
| Skill movement executor | Execute segment timing, displacement, teleport, leap, collision flags. |
| Motor / movement component | Apply validated XZ movement without normal body push. |
| Jump / height component | Apply skill-driven Y arc and airborne state. |
| Area skill emitter | Damage from skill volumes and landing impacts. |
| Combat impact utility | Knockback, launch, body size, kill multiplier. |
| Ground indicator system | Preview dash path, landing point, teleport point. |

## 13. Editor Tool Requirements

Character config tool should add a Chinese-facing section:

```text
技能配置 -> 技能位移
```

Required panels:

- 位移总开关.
- 位移段列表.
- 当前段基础信息.
- 时间与帧.
- 目标点选择.
- 碰撞与穿透.
- 冲撞命中.
- 无敌与霸体.
- 瞬移表现.
- 跳跃 / 砸击.
- 预览与校验.

Preview requirements:

- Game View preview: approximate final presentation.
- Top View: XZ path, wall stop point, target point, landing circle.
- Side View: Y arc for leap and jump smash.
- Frame scrubber: selecting a frame shows current segment position.
- Target front/back preview: show target body and final offset point.

Validation warnings:

- Segment start frame exceeds bound action frame count.
- Segment duration is 0 for non-teleport movement.
- Multiple segments overlap unintentionally.
- Teleport has no target fallback.
- `CanPassWall = true` on non-special skill.
- `CanRushHitEnemy = true` but no damage source exists.
- Jump smash has no landing impact frame.
- Leap landing requires ground but has no clamp / invalid policy.
- Invincibility window is longer than segment duration or too long for non-ultimate.

## 14. Skill UI Preview Requirements

Skill detail panel should show:

- Movement type summary.
- Distance / target rule.
- Whether it can pass enemies.
- Whether it can pass walls.
- Whether it has invulnerability or super armor.
- Whether it rush-hits enemies.
- Jump smash landing radius if any.

Animation preview:

- Loop bound skill action.
- Draw path overlay.
- Play frame VFX.
- Display landing projection for leap smash.
- If target-relative, show a dummy target and front/back positions.

## 15. Save And Compatibility Rules

- Existing skills without movement data behave exactly as before.
- Old `ActionMove` remains untouched.
- New movement config defaults to disabled.
- Generated configs should include a disabled movement block so tools can display it consistently.
- Runtime must tolerate null / empty segment lists.

## 15.1 Editor Conditional Display Rules

- Character config tool must not expose every movement field at once.
- Always show segment identity, movement mode, start frame, and duration frame.
- `None` only shows the basic frame window and summary.
- Dash, target dash, retreat, pull, leap, jump smash, and teleport modes show distance and max distance.
- `PullToTarget` additionally shows minimum reserved distance.
- Instant teleport modes show teleport-specific visual hiding, but hide movement curve and steering fields.
- Leap and jump-smash modes show leap height, landing impact frame, and landing recovery frames.
- Fixed-world-direction target mode shows fixed XZ direction.
- Target-relative modes show target offset.
- Target-dependent modes show input-direction fallback.
- Steering rate is shown only after "allow steering" is enabled.
- Rush hit interval and skill-radius scaling are shown only after rush hit is enabled.
- Wall stop is shown only when wall pass-through is disabled.
- Ground validation is shown only for real movement modes.

## 17. Acceptance Criteria

- A skill can be configured to dash forward from frame 3 for 8 frames.
- A skill can ignore unit collision during dash without pushing enemies away.
- A skill can rush-hit enemies only when `CanRushHitEnemy` is enabled.
- A skill can stop at walls by default.
- A special skill can pass walls only when explicitly configured.
- A skill can teleport to target back and avoid invalid wall positions.
- A skill can contain multiple movement segments.
- A jump smash skill moves on XZ and Y, then lands on valid ground and triggers landing damage.
- Invulnerable and super armor windows follow segment timing.
- Character config tool displays Chinese labels and validates risky configurations.
- Skill UI preview shows movement path and landing / teleport point.
