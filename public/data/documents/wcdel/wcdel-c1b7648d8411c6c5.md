# Chapter01 Reward Runtime Sync

## Goal

Upgrade key Chapter01 rewards from text-only prompts into real runtime grants so cave clear and boss clear rewards affect player progression immediately.

## Scope

- Extended `RewardChestInteractable2D` with support for:
  - equipment rewards
  - skill rewards
  - optional auto-equip for equipment
  - optional auto-assign of the first rewarded skill to skill slot 1
- Extended `GameSession` with lightweight runtime registries for learned skill and owned equipment definition references.
- Updated `BackendMenuCanvasPresenter` so runtime-granted reward definitions appear in equipment and skill pages instead of relying only on bootstrap config assets.
- Added a generated Chapter01 boss reward weapon asset:
  - `Bee Sting Blade`
- Updated starter slice reward setup:
  - `GrassCaveRewardChest` now grants a real equipment reward into runtime inventory
  - `BossRewardChest` now grants gold, equips the boss reward weapon, and teaches / equips `Fire Ring`

## Current Behavior

- Opening reward chests can now mutate real progression state instead of only showing reward flavor text.
- Equipment rewards granted at runtime become visible in the backend equipment menu.
- Skill rewards granted at runtime become visible in the backend skill menu.
- The Chapter01 boss chest now acts like a real power spike:
  - boss weapon is equipped
  - `Fire Ring` is assigned to slot 1
  - follow-up chapter closing quest still starts through the existing quest path

## Boundaries

- Reward chests still use direct world interactables, not a formal inventory reward list or loot distribution framework.
- Auto-equip and auto-assign are deliberately simple toggles for MVP pacing, not player-choice reward presentation.
- Runtime definition references currently live only in the active session and are meant to support prototype visibility, not a final asset indexing system.

## Next Suggestions

1. Split “grant reward” from “present reward” if later chapters need multi-item reward cards with preview / confirm flow.
2. Add explicit item rarity or reward icon display in the interaction overlay so rewarded gear feels more legible.
3. Extend reward chests to support consumables and chapter ability unlocks using the same runtime grant path.
