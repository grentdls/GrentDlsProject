# 06 详情面板布局规范：物品、技能、角色、词条

## 1. 文档目标

详情面板是游戏 UI 中最容易混乱的界面。因为它通常包含：

- 图标
- 名字
- 品质
- 类型
- 等级
- 属性
- 效果
- 描述
- 来源
- 条件
- 操作按钮

如果没有统一规则，不同物品的详情会越做越乱。本文档规定所有详情面板的标准结构。

---

## 2. 详情面板的核心阅读顺序

详情面板必须遵守以下阅读顺序：

```text
1. 这是什么？        Icon / 名字 / 品质 / 类型
2. 它有什么用？      属性 / 主效果 / 词条
3. 它为什么特别？    特殊机制 / 稀有效果 / 套装效果
4. 它还有什么说明？  描述 / 来源 / 限制 / 条件
5. 我能做什么？      装备 / 使用 / 升级 / 出售 / 关闭
```

不要把背景故事、来源、限制放在最上面。玩家最先关心的是“这东西对我有没有用”。

---

## 4. 详情面板视觉分区

### 4.1 Header：识别区

Header 的作用是让玩家 0.5 秒知道当前对象是谁。

包含：

- Icon
- 名字
- 品质
- 类型
- 等级/数量/锁定状态

布局示意：

```text
┌────────────────────────────────────┐
│ [Icon]  雷霆核心             [X]   │
│        传说 · 攻击部件 · 闪电流派   │
│        Lv.3 / 已装备               │
└────────────────────────────────────┘
```

规则：

- Icon 固定尺寸，不跟随名字长度变化。
- 名字最多 1-2 行，超过显示省略号。
- 标签行可以自动换行，但最多 2 行。
- 关闭按钮固定右上角，不参与自动布局。

推荐尺寸：

| 元素 | 移动端横屏 | PC |
|---|---:|---:|
| IconBlock | 96×96 / 120×120 | 80×80 / 96×96 |
| 名字字号 | 30-40 | 24-32 |
| 标签字号 | 18-24 | 14-18 |
| Header 高度 | 130-170 | 110-150 |

## 5. Icon 与品质框规则

### 5.1 图标不直接裸放

所有重要对象图标必须放进 `IconBlock`。

```text
IconBlock
├── Bg_IconBack       图标底板
├── QualityFrame      品质边框
├── IconMask          遮罩
│   └── IconImage     真正图标
├── Badge_Level       等级角标
├── Badge_Count       数量角标
└── StateOverlay      锁定/已装备/禁用覆盖层
```

### 5.2 图标根据框体做遮罩

用途：让圆形、六边形、异形图标框内的图标不会溢出。

实现规则：

```text
IconMask
├── Image：使用框体内部形状 Sprite
├── Mask：开启 Show Mask Graphic = false
└── IconImage：作为子节点，被 Mask 裁剪
```

如果需要柔边遮罩，可以使用：

- `RectMask2D`：性能好，但只能矩形。
- `Mask`：支持异形，但会增加渲染开销。
- 自定义 Shader Mask：适合大量异形图标。

### 5.3 图标留白规则

IconImage 不要贴满框体。

| 图标类型 | 建议填充比例 |
|---|---:|
| 装备/物品 | 72%-82% |
| 技能图标 | 78%-88% |
| 角色头像 | 90%-100% |
| 部件图标 | 75%-85% |
| 货币图标 | 70%-80% |

## 6. 名字、标签、类型排列规则

### 6.1 名字行

名字行只放对象名，不混入描述。

正确：

```text
雷霆核心
传说 · 攻击部件 · 闪电流派
```

错误：

```text
雷霆核心：一个可以发射闪电并且击杀敌人后弹射的强力部件
```

### 6.2 标签行

标签行负责快速识别分类。

推荐标签顺序：

```text
品质 > 类型 > 玩法字段 > 状态
```

示例：

```text
[传说] [攻击部件] [闪电] [弹射] [已装备]
```

### 6.3 标签数量限制

- 1-4 个标签：正常显示。
- 5-6 个标签：允许换行。
- 超过 6 个：只显示前 5 个，最后一个显示 `+N`。

示例：

```text
[传说] [攻击] [闪电] [弹射] [击杀] [+3]
```

点击或悬停 `+3` 时再展开完整标签。

## 7. 主属性区 Section_MainStat

主属性区展示最直接影响战斗/养成价值的字段。

示意：

```text
┌ 基础属性 ───────────────────────┐
│ 攻击力        +12                │
│ 攻击间隔      -0.15s             │
│ 暴击率        +5%                │
└─────────────────────────────────┘
```

层级：

```text
Section_MainStat
├── SectionTitle
└── StatList
    ├── InfoRow_Attack
    ├── InfoRow_AttackSpeed
    └── InfoRow_Crit
```

InfoRow 结构：

```text
InfoRow
├── Icon_Field       字段图标，可选
├── Txt_Label        字段名
├── Txt_Value        数值
└── Txt_Change       对比变化，可选
```

规则：

- 字段名左对齐。
- 数值右对齐。
- 正向变化用正向色。
- 负向变化用负向色。
- 同类数值单位必须统一。

---

## 8. 效果区 Section_Effect

效果区展示玩法机制，是详情面板最重要的信息之一。

示意：

```text
┌ 效果 ───────────────────────────┐
│ 命中敌人时，有 25% 概率释放一道 │
│ 连锁闪电，对附近 3 个敌人造成   │
│ 60% 攻击力的闪电伤害。          │
└─────────────────────────────────┘
```

如果效果包含字段，必须高亮关键词。

示例：

```text
命中敌人时，有 <概率>25%</概率> 概率释放 <闪电>连锁闪电</闪电>，
对附近 <数量>3</数量> 个敌人造成 <伤害>60%攻击力</伤害> 的闪电伤害。
```

Unity 实现可以用：

- TextMeshPro Rich Text
- 自定义字段颜色表
- 策划配置字段替换

---

## 9. 词条区 Section_Tags

词条区用于展示玩法字段，不是简单标签堆叠。

例如：

```text
┌ 机制词条 ───────────────────────┐
│ [闪电] 造成闪电伤害，可触发导电  │
│ [弹射] 命中后会跳向附近目标      │
│ [击杀] 击杀敌人时触发额外效果    │
└─────────────────────────────────┘
```

每个词条用 `KeywordRow`：

```text
KeywordRow
├── Tag_Keyword       词条标签
└── Txt_KeywordDesc   词条解释
```

规则：

- 标签负责识别。
- 说明负责解释。
- 不要只显示一堆标签不给解释。
- 玩家第一次接触机制时必须能看懂。

---

## 10. 描述区 Section_Desc

描述区分为两种：

| 类型 | 用途 | 视觉 |
|---|---|---|
| 玩法描述 | 说明具体效果 | 正文色，清晰优先 |
| 世界观描述 | 氛围文本 | 弱色、斜体、低优先级 |

推荐结构：

```text
Section_Desc
├── Txt_GameplayDesc
└── Txt_LoreDesc
```

示例：

```text
玩法描述：
攻击命中后有概率生成闪电链，适合高攻速流派。

背景描述：
它的表面不断跳动着细小电弧，像一颗被困住的雷云心脏。
```

规则：

- 玩法描述放前面。
- 背景描述放后面。
- 背景描述不能影响玩家理解效果。

---

## 11. 来源与限制区 Section_Source

用于展示：

- 获取来源
- 装备限制
- 职业限制
- 等级限制
- 是否已拥有
- 是否已解锁

示意：

```text
┌ 来源与限制 ─────────────────────┐
│ 来源：第三章 Boss 掉落           │
│ 限制：攻击部件槽位              │
│ 条件：飞船等级 Lv.5 解锁         │
└─────────────────────────────────┘
```

规则：

- 来源信息默认弱化。
- 限制信息如果影响操作，必须高亮。
- 未满足条件时，Footer 主按钮要变为不可点击状态，并显示原因。

---

## 12. Footer 操作区

Footer 负责玩家行为，必须固定在面板底部。

常见按钮：

| 按钮 | 类型 | 样式 |
|---|---|---|
| 装备 | Primary | 最亮、最大 |
| 使用 | Primary | 最亮、最大 |
| 升级 | Primary | 最亮、最大 |
| 购买 | Primary | 显示价格 |
| 出售 | Danger/Secondary | 弱于主按钮 |
| 取消 | Secondary | 普通 |
| 关闭 | Secondary 或右上角 X | 普通 |

布局示意：

```text
┌──────────────────────────────┐
│        [装备]   [出售]        │
└──────────────────────────────┘
```

或：

```text
┌──────────────────────────────┐
│ [取消]              [确认]    │
└──────────────────────────────┘
```

规则：

- 主按钮在右侧或居中。
- 危险按钮不要靠近主按钮。
- 不可点击按钮必须显示原因。

## 16. 词条详情 Tooltip 模板

当玩家点击或悬停某个词条时，出现小型 Tooltip。

```text
KeywordTooltip
├── Bg_9Slice
├── Header
│   ├── Icon_Keyword
│   └── Txt_KeywordName
└── Body
    ├── Txt_Definition
    └── Txt_Example 可选
```

示意：

```text
┌──────────────────────┐
│ ⚡ 闪电               │
├──────────────────────┤
│ 闪电伤害可以触发导电。│
│ 导电目标受到连锁伤害时│
│ 会额外扩散一次。      │
└──────────────────────┘
```

规则：

- Tooltip 不放操作按钮。
- Tooltip 不能遮挡当前点击对象。
- Tooltip 最大宽度固定，文字自动换行。
- 内容超过最大高度时，不建议滚动，改为精简说明。

## 17. 多内容长度处理

### 17.1 名字过长

规则：

- 名字最多 2 行。
- 超过后显示省略号。
- 完整名字可在 Tooltip 中显示。

Unity 设置：

```text
TextMeshProUGUI
├── Enable Word Wrapping: true
├── Overflow: Ellipsis
└── Max Visible Lines: 2
```

### 17.2 描述过长

规则：

- Body 使用 ScrollRect。
- Header 和 Footer 固定。
- 只有内容区滚动。

不要让整个弹窗一起滚动。

### 17.3 词条过多

规则：

- Header 标签最多显示 2 行。
- 详细词条放在 Body 的 Section_Tags。
- 超过 6 个词条时折叠，可点击展开。

### 17.4 属性过多

规则：

- 主要属性最多显示 4-6 条。
- 次要属性进入“更多属性”。
- 或分为攻击、防御、功能三组。

---

## 18. Prefab 变体规则

不要为每种对象完全重新做一套详情面板。应使用基类 + 变体。

```text
DetailPanelBase.prefab
├── ItemDetailPanel.prefab variant
├── SkillDetailPanel.prefab variant
├── CharacterDetailPanel.prefab variant
├── BuffDetailPanel.prefab variant
├── BuildingDetailPanel.prefab variant
└── ModuleDetailPanel.prefab variant
```

Base 负责：

- 背景
- Header / Body / Footer 结构
- 关闭按钮
- 动效
- 自适应

Variant 负责：

- 特定 Section 的显示/隐藏
- 特定按钮逻辑
- 特定数据绑定
- 特定图标类型

---

## 19. 详情面板制作检查清单

- [ ] Header 是否能一眼识别对象？
- [ ] Icon 是否有品质框和遮罩？
- [ ] 名字是否限制最大行数？
- [ ] 标签是否不会无限撑开 Header？
- [ ] 主效果是否比背景描述更靠前？
- [ ] 属性是否列对齐？
- [ ] 词条是否有解释，不只是标签？
- [ ] Body 内容过长是否可以滚动？
- [ ] Header/Footer 是否固定不滚动？
- [ ] 按钮是否有主次关系？
- [ ] 未满足条件时是否显示原因？
- [ ] 内容少时是否不会出现大块空洞？
- [ ] 所有背景框是否使用 9-Slice？
