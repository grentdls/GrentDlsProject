# 05 Unity UI 美观性布局总规则：视觉层级、间距、对齐

## 1. 文档目标

本文档定义 Unity 游戏 UI 的基础美观规则。它不关注单个 Button、Slider 怎么实现，而是规定：

- 一个界面中哪些信息应该最显眼。
- 图标、标题、描述、按钮之间怎么排列。
- 间距、边距、对齐、字号、背景板应该如何统一。
- 内容多时如何不挤，内容少时如何不空。
- 后续做新界面时如何保持同一套视觉语言。

所有 UI 面板都应该先满足本文档，再进入具体控件制作。

---

## 2. UI 美观的四个基本判断标准

### 2.1 清晰

玩家不需要思考，就能知道：

- 这个界面是干什么的。
- 当前最重要的信息是什么。
- 哪些按钮可以点击。
- 点击后会发生什么。

错误示例：所有文字一样大、所有背景一样亮、所有按钮都像装饰。

正确示例：标题最大、主要奖励最亮、次要说明变弱、主按钮颜色最明确。

### 2.2 有层级

一个界面不能所有东西都抢眼。必须分成：

| 层级 | 名称 | 用途 | 表现 |
|---|---|---|---|
| L1 | 核心焦点层 | 玩家第一眼要看的内容 | 大图标、大标题、高对比、居中或靠上 |
| L2 | 主要信息层 | 数值、效果、属性、奖励 | 清晰字段、分组背景、图标辅助 |
| L3 | 补充说明层 | 描述、来源、限制、提示 | 小字号、弱颜色、浅背景 |
| L4 | 操作层 | 确认、购买、装备、关闭 | 固定位置、按钮样式统一 |
| L5 | 装饰层 | 花纹、光效、角标、底纹 | 不能影响阅读 |

### 2.3 有呼吸感

UI 不是把信息塞满，而是让信息之间有“空气”。

基础规则：

- 标题和正文之间要有明显间距。
- 不同模块之间的间距要大于同模块内元素间距。
- 图标周围不能贴边。
- 按钮之间要留足防误触距离。

推荐采用 `8px 网格规则`：

| 场景 | 推荐间距 |
|---|---:|
| 同一行图标和文字 | 8 / 12 px |
| 同一模块内两行文字 | 4 / 6 / 8 px |
| 模块与模块之间 | 16 / 20 / 24 px |
| 面板内边距 | 24 / 32 px |
| 弹窗与屏幕边缘安全距离 | 48 / 64 px |
| 手机按钮最小触控尺寸 | 80×80 px 以上 |
| PC 按钮最小触控尺寸 | 48×48 px 以上 |

### 2.4 可维护

美观不能靠每个界面手调。应该通过组件化维护：

- 标题区统一一个 `HeaderBlock`。
- 属性行统一一个 `InfoRow`。
- 词条标签统一一个 `TagChip`。
- 详情面板统一一个 `DetailPanelBase`。
- 按钮统一 `Btn_Primary / Btn_Secondary / Btn_Danger`。

如果一个界面需要很多手动调位置，说明预制体结构有问题。

## 3. 统一术语

后续所有 UI 文档、策划表、程序字段都使用以下名词。

| 名词 | 解释 |
|---|---|
| 面板 Panel | 一个完整窗口，例如背包、设置、物品详情。 |
| 弹窗 Popup | 临时出现的确认/提示/详情窗口。 |
| 卡片 Card | 用来承载一个物品、角色、技能、奖励的独立信息块。 |
| 槽位 Slot | 背包格、装备格、技能格、部件格。 |
| 标题区 Header | 面板顶部，放标题、关闭按钮、核心对象名。 |
| 主体区 Body | 内容区域，放列表、描述、属性、词条。 |
| 操作区 Footer | 面板底部，放确认、取消、购买、装备等按钮。 |
| 信息组 Section | 一组同类信息，例如基础属性、技能效果、获取来源。 |
| 信息行 InfoRow | 一行字段信息，例如“攻击力 +10”。 |
| 标签 Tag | 小型字段标识，例如“闪电”“弹射”“被动”。 |
| 角标 Badge | 放在图标角上的小标识，例如等级、数量、锁定。 |
| 品质框 QualityFrame | 根据稀有度改变颜色/边框/底纹的图标框。 |
| 遮罩 Mask | 控制图标只显示在某个形状或框体内。 |
| 安全区 SafeArea | 避免被刘海屏、圆角屏、系统栏遮挡的区域。 |
| 滚动区 ScrollArea | 内容超过最大高度时可滚动的区域。 |
| 内容容器 Content | LayoutGroup 控制的实际内容父节点。 |

## 4. 视觉层级规则

### 4.1 一屏只允许一个最强焦点

每个界面必须明确 `视觉焦点`。

| 界面 | 推荐焦点 |
|---|---|
| 主界面 | 开始按钮 / 当前角色 / 当前任务 |
| 背包 | 当前选中的物品详情 |
| 商店 | 推荐商品 / 折扣商品 / 当前货币 |
| 三选一奖励 | 三张可选卡牌 |
| 物品详情 | Icon + 名字 + 品质 |
| 设置界面 | 当前选中的设置分类 |
| 图鉴界面 | 当前查看对象模型/大图 |
| 战斗 HUD | 角色状态 + 技能按钮 |

不能同时让标题、图标、按钮、描述都高亮。玩家眼睛会乱跑。

### 4.2 标题不是永远最大，重点才最大

- 页面标题：说明当前界面，如“背包”。
- 对象标题：说明当前对象，如“雷霆核心”。
- 当前收益/关键奖励：可能比页面标题更重要。

例如奖励界面中，“获得稀有部件”应比“战斗结算”更强。

### 4.3 使用大小建立层级

推荐字号关系：

| 类型 | 移动端参考 | PC 参考 | 用途 |
|---|---:|---:|---|
| 大标题 | 40-56 | 32-48 | 页面标题、奖励标题 |
| 中标题 | 28-36 | 24-32 | 物品名、模块名 |
| 正文 | 22-28 | 18-24 | 描述、说明 |
| 小字 | 18-22 | 14-18 | 来源、限制、提示 |
| 数字强调 | 32-48 | 28-40 | 金币、伤害、等级 |

规则：字号差距至少 4px 才能看出层级。不要 24、25、26 混用。

### 4.4 使用颜色建立层级

颜色不要乱用，必须承担意义。

| 用途 | 颜色规则 |
|---|---|
| 普通正文 | 接近白色/深灰，保证可读性 |
| 次要说明 | 透明度降低，或使用灰蓝/米灰 |
| 正向数值 | 绿色/青色/暖黄色 |
| 负向数值 | 红色/橙红 |
| 稀有品质 | 固定品质色，不要随界面改变 |
| 可点击按钮 | 比背景更亮、更饱和 |
| 不可点击按钮 | 降低透明度、去除强光、置灰 |
| 警告/消耗 | 红/橙/暗金 |

## 5. 对齐规则

### 5.1 同类信息必须对齐

属性列表中，字段名、数值、图标要形成竖线。

推荐：

```text
攻击力       +12
生命值       +80
暴击率       +5%
攻击间隔     -0.15s
```

错误：

```text
攻击力 +12
生命值          +80
暴击率 +5%
攻击间隔      -0.15s
```

### 5.2 图标与文字的基准线

图标不要简单居中到整行高度，而要和文字视觉中心对齐。

- 小图标：建议高度为正文高度的 0.9-1.1 倍。
- 标签图标：建议 20-28px。
- 属性图标：建议 28-36px。
- 大图标：由卡片尺寸决定。

### 5.3 左对齐、居中、右对齐的使用场景

| 对齐方式 | 适合场景 | 不适合场景 |
|---|---|---|
| 左对齐 | 描述、属性、长文本、列表 | 大奖励展示 |
| 居中 | 标题、奖励弹窗、确认弹窗 | 长描述、大量属性 |
| 右对齐 | 数值列、价格、倒计时 | 普通说明 |

UI 里最常见的问题是长文本居中，读起来很累。描述类文本默认左对齐。

## 6. 间距规则

### 6.1 面板内部结构

标准面板推荐：

```text
Panel
├── Header       顶部标题区，高度 72-120
├── Body         主体内容区，自适应或滚动
└── Footer       底部操作区，高度 88-140
```

内边距推荐：

```text
Panel Padding
Left:   32
Right:  32
Top:    28
Bottom: 28
```

移动端横屏可以稍小，PC 可以更宽松。

### 6.2 模块间距大于模块内间距

```text
Header 与 Body：24px
Section 与 Section：20px
Section 内标题与内容：8px
InfoRow 与 InfoRow：6px
```

如果所有间距一样，界面会像表格，没有层次。

### 6.3 不同信息密度的间距

| 信息密度 | 用途 | 间距策略 |
|---|---|---|
| 低密度 | 主界面、奖励、弹窗 | 大留白、大图标、大按钮 |
| 中密度 | 背包、商店、图鉴 | 卡片整齐，局部留白 |
| 高密度 | 属性面板、设置、技能树 | 小间距，但必须分组 |

高密度不是无限压缩，而是通过分组降低阅读压力。

## 7. 背景板规则

### 7.1 背景板必须分层

推荐至少三层：

```text
Bg_Shadow       阴影/投影，拉开层次
Bg_Main         主背景，承载内容
Bg_Inner        内容内衬板，区分模块
```

不要所有内容直接放在同一张大背景上。

### 7.2 九宫格背景使用规则

所有会因为内容变长而拉伸的框体，必须使用 `9-Slice`。

| 框体 | 是否必须 9-Slice |
|---|---|
| 弹窗背景 | 必须 |
| 详情面板背景 | 必须 |
| 按钮背景 | 推荐 |
| 标签背景 | 推荐 |
| 列表项背景 | 推荐 |
| 固定图标框 | 可选 |

禁止直接拉伸带花纹的图片，否则边角会变形。

### 7.3 背景亮度不能抢文字

文字区域背后应尽量使用低对比背景。

- 大标题背后可以有装饰。
- 正文背后不要有复杂纹理。
- 属性列表背后最好用半透明平板或内衬板。

## 8. 信息排列规则

### 8.1 先识别，再解释，再操作

一个好界面通常按以下顺序排列：

```text
识别对象：Icon / 名字 / 品质 / 类型
理解价值：属性 / 效果 / 词条 / 稀有度
补充说明：描述 / 来源 / 限制 / 条件
执行操作：装备 / 升级 / 出售 / 关闭
```

不要先给长描述，再让玩家去找物品名字。

### 8.2 左图右文适合详情识别

物品、技能、装备、部件详情推荐：

```text
┌────────────────────────────┐
│ [Icon]  名字                │
│         品质 / 类型 / 等级   │
├────────────────────────────┤
│ 基础属性                    │
│ 技能效果                    │
│ 描述文本                    │
├────────────────────────────┤
│        [装备] [出售]        │
└────────────────────────────┘
```

### 8.3 上图下文适合卡牌展示

卡牌、三选一奖励、角色图鉴推荐：

```text
┌──────────────┐
│    大图标     │
│    名字       │
│    标签       │
│    效果       │
│    描述       │
└──────────────┘
```

### 8.4 左列表右详情适合管理界面

背包、商店、图鉴、角色列表推荐：

```text
┌──────────────────────────────┐
│ 标题 / 筛选 / 货币             │
├───────────────┬──────────────┤
│ 左：列表/网格   │ 右：详情面板  │
│               │              │
└───────────────┴──────────────┘
```

## 9. 美观检查清单

每个 UI 做完后检查：

- [ ] 第一眼是否能看出当前界面的核心内容？
- [ ] 标题、主体、按钮是否有明确层级？
- [ ] 长文本是否左对齐？
- [ ] 同类数值是否列对齐？
- [ ] 面板内边距是否统一？
- [ ] 模块之间是否有明显分隔？
- [ ] 背景纹理是否影响文字阅读？
- [ ] 所有可点击对象是否像按钮？
- [ ] 所有不可点击对象是否不会误导玩家？
- [ ] 内容多时是否不会超出背景？
- [ ] 内容少时是否不会显得空？
- [ ] 关闭按钮是否在玩家预期位置？
- [ ] 返回/确认/取消按钮是否样式统一？

## 10. 后续修改规则

### 10.1 改整体风格

优先改：

```text
UIThemeConfig
├── Font
├── ColorPalette
├── SpacingScale
├── QualityColors
├── ButtonSprites
└── PanelSprites
```

不要逐个界面改颜色。

### 10.2 改某类控件

例如所有物品格变大，只改：

```text
Prefab/UI/Common/Slot/ItemSlot.prefab
```

不要改每个背包格实例。

### 10.3 改详情面板布局

只改：

```text
Prefab/UI/Common/Detail/DetailPanelBase.prefab
```

具体物品、技能、角色详情只替换数据，不改结构。

### 10.4 改某个界面内容

只改该界面的 `Content` 或数据绑定脚本，不改公共组件。

```text
BackpackPanel
├── Header       不随便改
├── CategoryTabs 可改分类
├── ItemGrid     可改数据源
├── DetailPanel  调用公共详情面板
└── Footer       可改按钮逻辑
```
