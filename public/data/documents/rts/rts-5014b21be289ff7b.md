# Runtime Audio Placeholder and Replacement Rules

## Purpose

This project uses a lightweight runtime audio library for placeholder UI sounds, unit/building command sounds, combat fallback sounds, event alerts, and faction BGM.

Runtime entry:

- `Assets/Scripts/Core/RuntimeAudioManager.cs`

Runtime config:

- `Assets/Resources/Audio/RuntimeAudioLibrary.json`

Placeholder audio files:

- `Assets/Resources/Audio/Placeholders/UI/`
- `Assets/Resources/Audio/Placeholders/Commands/`
- `Assets/Resources/Audio/Placeholders/Events/`
- `Assets/Resources/Audio/Placeholders/Combat/`
- `Assets/Resources/Audio/Placeholders/BGM/`

## Replacement Rules

There are two supported replacement workflows.

1. Replace the existing `.wav` file with the same filename and keep it under `Assets/Resources/Audio/Placeholders/...`.
2. Put the final audio file under any `Assets/Resources/...` folder and update the matching `resourcePath` in `Assets/Resources/Audio/RuntimeAudioLibrary.json`.

`resourcePath` is a Unity `Resources.Load<AudioClip>()` path:

- It starts below a `Resources` folder.
- It has no file extension.
- Example: `Assets/Resources/Audio/Placeholders/UI/ui_click.wav` becomes `Audio/Placeholders/UI/ui_click`.

## Runtime Behavior

- UI buttons are bound automatically by `RuntimeAudioManager` at a low frequency. Button names containing `Cancel`, `Back`, `Close`, `Confirm`, `Apply`, `Start`, `Tab`, or `Category` choose a more specific cue.
- Selection, movement, attack, gather, patrol, building placement/completion, unit queue, research start/completion, under-attack warnings, resource-low warnings, victory, and defeat are event-driven.
- Combat systems still use unit/building/skill-specific `AudioClip` fields first. Runtime placeholder combat cues are only used as fallback clips.
- BGM switches to main-menu music in `MainMenu` and faction music in `Playing` or `Paused`.

## Authoring Notes

- Keep short UI and command sounds under one second.
- Keep event alerts clear and not too loud because they may interrupt busy combat.
- BGM placeholder loops are intentionally simple. Final BGM should be loop-safe and normalized before import.
- Prefer `wav`, `ogg`, or `mp3` formats supported by Unity. For fast iteration, keeping the same filename is the lowest-risk replacement path.
