# 机械族单位与建筑改造页面 UI 详细规则文档

## 一、设计目标

机械阵营的单位和建筑都没有传统升级，而是通过“改造模块”改变属性、技能、定位和玩法。

当玩家点击机械单位或机械建筑后，如果该对象拥有改造能力，需要额外显示“改造页面”。

该页面用于：

```text
1. 查看当前单位 / 建筑可安装的改造模块。
2. 查看当前已安装模块。
3. 选择新模块进行改造。
4. 显示模块图片、名称、消耗。
5. 鼠标悬停 / 手机长按显示模块详情页。
6. 支持替换模块确认。
7. 支持改造中进度显示。
8. 与造兵页面、建造页面、科技树页面同时存在时，不重叠、不混乱。
```

设计目标：

```text
1. 改造页面大小接近造兵页面，不占全屏。
2. 改造列表横向排布，可横向拖动。
3. 每个改造卡显示模块图片。
4. 模块图片下方显示资源消耗：ICON + 数字。
5. 页面必须显示改造槽位，玩家能看清当前装了什么。
6. 改造收益、代价、互斥、替换必须清楚。
7. PC端悬停显示详情，手机端长按显示详情。
8. 高风险替换必须弹确认。
9. 单位改造和建筑改造共用规则，但界面信息不同。
```

最终体验：

```text
玩家点击机械单位 / 机械建筑后，
右侧或底部弹出机械改造页面，
上方显示当前改造槽位，
中间显示可安装模块横向列表，
下方显示改造进度或当前模块状态，
点击模块可安装或替换，
悬停 / 长按查看完整改造详情。
```

# 二、改造页面出现条件

## 2.1 点击单位后显示改造页面

单位满足以下条件时，选中后显示改造页面：

```text
单位属于机械阵营或机械融合路线
单位拥有改造槽
单位未死亡
单位未被控制
单位当前可操作
当前玩家拥有控制权
当前模式允许改造
```

示例单位：

```text
机械狗
机器工人
动力机甲
主战坦克
装甲车
重型机械堡垒车
侦察机
轰炸机
歼敌机
潜艇
巡航舰
灵能机甲
兽械单位
```

---

## 2.2 点击建筑后显示改造页面

建筑满足以下条件时，选中后显示改造页面：

```text
建筑属于机械阵营或机械融合路线
建筑拥有建筑改造槽
建筑已建造完成
建筑未被摧毁
建筑未断供到完全失效
当前玩家拥有控制权
当前模式允许建筑改造
```

示例建筑：

```text
机场
重装工厂
机动机械场
船厂
维修平台
雷达站
防御炮台
导弹塔
电厂
反应堆
元素反应堆
灵能装配场
```

---

## 2.3 不显示改造页面的情况

以下对象不显示改造页面：

```text
没有改造槽的单位
没有改造功能的建筑
临时召唤机械
中立机械残骸
敌方机械单位
正在被占领且未完成控制权转换的建筑
战役中被禁用改造的目标
```

# 三、改造页面与其他页面的共存布局

机械建筑可能同时拥有：

```text
造兵页面
科技树页面
改造页面
建筑操作按钮
集结点按钮
```

机械单位可能同时拥有：

```text
建造页面
改造页面
技能按钮
巡逻 / 自动采集 / 自动施法按钮
```

因此必须设计统一的布局分区，避免重叠。

---

## 3.1 总体布局原则

同一时间最多显示：

```text
一个主列表页面
一个状态/队列栏
一个右侧操作按钮组
一个详情浮窗
```

主列表页面包括：

```text
造兵
建造
科技
改造
```

它们不能同时在同一区域展开堆叠。

推荐统一使用页签：

```text
[造兵] [科技] [改造]
[建造] [改造]
```

---

## 3.2 建筑选中后的布局

如果机械建筑同时有造兵、科技、改造功能：

推荐布局：

```text
┌────────────────────────────────────┐
│ 页签栏：[造兵] [科技] [改造]         │
├────────────────────────────────────┤
│ 当前页内容：横向卡片列表             │
├────────────────────────────────────┤
│ 当前页状态栏：队列 / 研究 / 改造进度 │
└────────────────────────────────────┘
                         [集结点]
                         [停止]
                         [详情]
```

显示优先级：

```text
主要生产建筑：默认打开造兵页
主要科研建筑：默认打开科技页
主要改造建筑：默认打开改造页
上次打开过的页签：可记忆
```

---

## 3.3 单位选中后的布局

如果机械单位同时有建造和改造功能：

推荐布局：

```text
┌──────────────────────────────┐
│ 页签栏：[建造] [改造]          │
├──────────────────────────────┤
│ 当前页内容                    │
└──────────────────────────────┘
                    [技能按钮区]
                    [操作按钮区]
```

对于机器工人：

```text
默认打开建造页。
改造页作为第二页签。
```

对于战斗机械单位：

```text
默认打开改造页或单位技能页。
如果单位可建造临时设施，则建造页作为第二页签。
```

---

## 3.4 手机端页面共存规则

手机端空间更小，必须严格控制。

规则：

```text
同一时间只展开一个主列表页面。
造兵 / 建造 / 科技 / 改造通过页签切换。
右侧操作按钮垂直排列。
详情页以浮层形式显示。
高风险确认居中显示。
```

手机推荐结构：

```text
┌──────────────────────────────┐
│ 页签：造兵 科技 改造           │
├──────────────────────────────┤
│ 横向卡片列表                  │
├──────────────────────────────┤
│ 状态栏 / 改造进度              │
└──────────────────────────────┘
        右侧：集结点 / 停止 / 详情
```

---

## 3.5 PC端页面共存规则

PC端空间较大，但仍不建议堆多个大页面。

规则：

```text
底部主面板显示当前页签。
右侧建筑操作按钮区独立。
详情卡悬浮在鼠标旁。
改造槽可在面板顶部或左侧固定显示。
```

PC推荐结构：

```text
┌────────────────────────────────────────┐
│ [造兵] [科技] [改造]                    │
├───────────┬────────────────────────────┤
│ 改造槽位   │ 横向模块列表                │
├───────────┴────────────────────────────┤
│ 改造进度 / 当前状态                     │
└────────────────────────────────────────┘
```

# 五、改造页面基础结构

## 5.1 标准结构

```text
┌────────────────────────────────────┐
│ 页签栏：[造兵] [科技] [改造]         │
├────────────────────────────────────┤
│ 当前改造槽位                        │
│ [主武器槽] [装甲槽] [能源槽] [AI槽] │
├────────────────────────────────────┤
│ 可安装模块横向列表                  │
│ [模块卡][模块卡][模块卡] →拖动       │
├────────────────────────────────────┤
│ 改造状态栏 / 改造中进度 / 当前提示   │
└────────────────────────────────────┘
```

---

## 5.1.1 当前项目固定 Prefab 挂点

当前项目中，机械改造页必须挂在：

```text
SelectionActionPanel_Prefab
  UnitBuildingActionPages_RightContainer
    BuildingControlPage_Standalone
      MechanicalModificationPage
```

`MechanicalModificationPage` 内固定节点至少应为：

```text
MechanicalModificationPage
  MechanicalSectionTitle
  MechanicalCategoryTitle
  MechanicalCategoryTabsViewport
    MechanicalCategoryTabsContent
  MechanicalSlotsViewport
    MechanicalSlotsContent
  MechanicalGridViewport
    MechanicalGridContent
      EmptyLabel
  MechanicalStatusPanel
    Icon
    NameLabel
    StateLabel
    RemainingLabel
    ProgressLabel
    ProgressBar
      Fill
    CancelButton
```

改造卡 `MechanicalModificationCard_Prefab` 内固定节点至少应为：

```text
MechanicalModificationCard_Prefab
  Title
  Icon
  Meta
  Description
  CostRow
    CostSlotTemplate
      Icon
      Amount
    FreeLabel
```

以上节点缺失时，应视为 prefab 结构错误，由代码报错并降级；不允许运行时重新拼出一套最终可见结构替代。

---

## 5.2 单位改造页面结构

单位改造页必须显示：

```text
单位名称
当前已安装模块
可安装模块列表
模块消耗
模块槽位
改造中状态
当前改造次数
最大改造次数
```

单位改造次数规则：

```text
每个单位最多改造2次。
```

显示：

```text
改造次数：1 / 2
```

---

## 5.3 建筑改造页面结构

建筑改造页必须显示：

```text
建筑名称
当前已安装建筑部件
可安装部件列表
建筑改造次数
电力影响
断电影响
建筑技能变化
```

建筑改造次数规则：

```text
每个建筑最多改造2次。
```

显示：

```text
建筑改造：0 / 2
```

---

## 5.4 代码职责边界

代码只负责：

```text
1. 判断当前选择对象是否显示改造页
2. 填充分类按钮文字与点击事件
3. 填充槽位标题、已安装模块名称、状态颜色
4. 填充改造卡名称、图标、Meta、资源消耗、可点击状态
5. 填充状态栏名称、进度、摘要、取消按钮事件
6. 控制改造页与普通建筑操作区之间的显隐切换
```

代码不再负责：

```text
1. 创建 MechanicalModificationPage 根节点
2. 创建 MechanicalSectionTitle / MechanicalGridViewport / MechanicalStatusPanel 等固定页面结构
3. 通过代码写死改造页各子区块的最终位置和大小
4. 在普通建筑操作按钮区内以旧逻辑混排机械改造卡
5. 用纯运行时 GameObject 作为最终可见的改造卡费用行、Meta 行、标题区
```

# 六、改造槽位设计

## 6.1 改造槽位目的

改造槽用于让玩家知道：

```text
这个单位/建筑现在装了什么
还空着什么
新模块会装到哪个槽
是否会替换已有模块
```

---

## 6.2 单位改造槽类型

推荐槽位：

```text
主武器槽
副武器槽
装甲槽
动力槽
感知槽
AI槽
特殊槽
```

不同单位拥有不同槽位。

示例：

| 单位 | 可用槽位 |
|---|---|
| 机械狗 | 感知槽、动力槽、AI槽 |
| 主战坦克 | 主武器槽、装甲槽、动力槽 |
| 轰炸机 | 武器槽、动力槽、感知槽 |
| 机甲 | 主武器槽、装甲槽、能源槽、特殊槽 |
| 潜艇 | 武器槽、隐蔽槽、动力槽 |

---

## 6.3 建筑改造槽类型

推荐槽位：

```text
结构槽
生产槽
防御槽
能源槽
电路槽
飞行槽
自毁槽
雷达槽
维修槽
```

示例：

| 建筑 | 可用槽位 |
|---|---|
| 机场 | 生产槽、雷达槽、防御槽 |
| 重装工厂 | 生产槽、结构槽、能源槽 |
| 电厂 | 能源槽、电路槽、自毁槽 |
| 防御炮台 | 武器槽、雷达槽、能源槽 |
| 维修平台 | 维修槽、能源槽、结构槽 |

---

## 6.4 槽位 UI 结构

槽位显示为小卡片：

```text
┌────────┐
│ 槽位名 │
│ [模块] │
└────────┘
```

空槽显示：

```text
空
```

已安装显示：

```text
模块图标
模块名称短名
```

被新模块选中时：

```text
槽位高亮
显示“将安装”
```

替换时：

```text
原模块红橙描边
新模块蓝色箭头指向槽位
```

---

## 6.5 槽位状态

| 状态 | 表现 |
|---|---|
| 空槽 | 灰蓝底，虚线边框 |
| 已安装 | 电蓝边框，模块图标亮 |
| 可替换 | 黄色描边 |
| 互斥不可装 | 红色锁 |
| 科技未解锁 | 灰色锁 |
| 改造中 | 流光进度 |
| 达到改造次数 | 灰显 |

# 七、模块分类栏

## 7.1 分类目的

机械模块数量会很多，需要分类。

推荐分类：

```text
全部
武器
装甲
动力
能源
AI
雷达
生产
特殊
```

手机端简写：

```text
全部
武器
装甲
动力
能源
AI
特殊
```

---

## 7.2 分类定义

### 武器模块

提高攻击、改变攻击方式、解锁新技能。

示例：

```text
穿甲炮
高爆炮
速射炮
导弹挂架
电磁炮
火焰喷射器
```

### 装甲模块

提升生存能力、抗性、护盾。

示例：

```text
复合装甲
反爆装甲
能量护盾
生存加固
重型外骨骼
```

### 动力模块

提升移动、飞行、转向、部署能力。

示例：

```text
涡轮推进
履带强化
喷气背包
飞行部件
两栖推进器
```

### 能源模块

影响电力、能耗、过载、充能。

示例：

```text
高效电容
备用电池
过载核心
反应堆副核
节能回路
```

### AI模块

改变自动行为、目标选择、技能释放。

示例：

```text
火控AI
自动维修AI
防空优先AI
集火协议
自动闪避协议
```

### 雷达模块

提供侦察、反隐、锁定、预警。

示例：

```text
广域雷达
反隐扫描
空域监控
导弹锁定器
潜航声呐
```

### 生产模块

建筑专用，影响造兵和生产。

示例：

```text
生产加速臂
自动装配线
并列生产舱
维修机械臂
```

### 特殊模块

高风险或改变玩法的模块。

示例：

```text
飞行部件
自爆部件
建筑移动核心
寄生控制器
灵能核心
```

# 八、模块卡片设计

## 8.1 模块卡片基础结构

每张模块卡显示：

```text
模块图片
模块名称
资源消耗
槽位类型
状态标记
```

推荐结构：

```text
┌──────────────┐
│   模块图片    │
│              │
├──────────────┤
│ 穿甲炮        │
│ 🪙260 ⚙180    │
│ ⏱35s         │
└──────────────┘
```

---

## 8.2 模块图片

模块图片要求：

```text
使用模块图标或小部件渲染图
透明背景
主体清楚
机械结构明确
能看出模块类别
```

图标建议：

| 模块类型 | 图标方向 |
|---|---|
| 武器 | 炮管、导弹、枪口 |
| 装甲 | 护甲板、盾牌、外骨骼 |
| 动力 | 引擎、履带、喷口 |
| 能源 | 电池、反应堆、电容 |
| AI | 芯片、眼睛、战术网格 |
| 雷达 | 雷达盘、扫描波 |
| 生产 | 机械臂、装配线 |
| 特殊 | 警告符号、核心、翅翼 |

---

## 8.3 模块名称

显示规则：

```text
最多 5 个汉字
超过缩略
完整名进入详情页
```

示例：

```text
穿甲炮
高爆炮
飞行部件
火控AI
自爆核心
```

---

## 8.4 消耗显示

模块卡下方显示消耗：

```text
ICON + 数字
```

推荐最多显示：

```text
黄金
金属
电力/能耗变化
改造时间
```

示例：

```text
🪙260  ⚙180
⚡+5   ⏱35
```

如果模块不增加能耗：

```text
不显示电力变化
```

如果模块降低能耗：

```text
⚡-3 用绿色显示
```

# 九、模块卡片状态

## 9.1 状态类型

| 状态 | 表现 |
|---|---|
| 可安装 | 正常亮度，电蓝描边 |
| 资源不足 | 缺少资源数字红色 |
| 科技未解锁 | 灰色遮罩，锁图标 |
| 槽位不匹配 | 红色槽位警告 |
| 改造次数不足 | 灰显，显示次数不足 |
| 已安装 | 完成勾，显示已安装 |
| 会替换 | 黄色替换标记 |
| 互斥 | 红橙互斥锁 |

# 二十一、最终硬规则

```text
1. 点击拥有改造能力的机械单位或建筑，才显示改造页面。
2. 改造页面不能全屏，大小应接近造兵页面。
3. 改造页面必须通过页签与造兵、建造、科技页面共存。
4. 模块列表必须横向排布。
5. 模块列表必须支持横向拖动。
6. 模块卡必须显示模块图片。
7. 模块图片下方必须显示资源 ICON + 数字。
8. 页面必须显示当前改造槽位。
9. 单位和建筑默认最多改造2次。
10. 替换已有模块必须确认。
11. 高风险模块必须确认。
12. PC端鼠标悬停显示模块详情。
13. 手机端长按显示模块详情。
14. 改造中必须显示进度和剩余时间。
15. 资源不足、科技未解锁、槽位不匹配、互斥、电力不足必须清楚显示。
16. 改造完成后必须刷新模型、属性、技能、槽位和详情数据。
```

---

# 二十二、一句话总结

```text
机械改造页面不是普通升级页，而是模块化装配页：玩家通过横向模块卡快速选择改造，通过槽位区理解当前配置，通过详情页判断收益和代价，通过确认弹窗避免误装高风险模块，并且整个页面必须和造兵、建造、科技页面用页签共存，保证战斗视野不被遮挡。
```

## 23.2 当前脚本职责

`Assets/Scripts/UI/SelectionPanel.cs` 当前负责：

```text
1. 判断单位/建筑是否进入机械改造页。
2. 填充分类栏。
3. 刷新已安装槽位。
4. 填充模块卡列表。
5. 刷新当前改造状态栏。
6. 绑定点击、悬停、长按详情逻辑。
```

代码当前不应再负责：

```text
1. 创建最终可见的旧式机械改造按钮排布。
2. 在普通建筑操作区内临时堆一整页改造卡作为最终展示。
3. 把机械改造页固定文案、背景和结构重新写回代码。
```

## 23.3 当前已实现边界

当前这轮已统一：

```text
1. 机械单位点击“改造”后复用同一套机械改造页。
2. 机械建筑改造模块列表不再直接作为普通建筑操作按钮的最终表现。
3. 槽位区、模块列表区、状态栏区已抽成独立节点。
4. 模块卡列表改为单独维护，不再和普通建筑操作按钮列表混用。
```

后续继续优化时，优先顺序必须是：

```text
先改 prefab 节点和布局
再补 SelectionPanel 绑定
最后补文档
```

## 23.4 当前资源校准规则（2026-05-16）

本轮补充了一条必须长期保持的资源规则：

```text
MechanicalSlotsContent 下必须真实存在 MechanicalSlotTemplate，
并且模板内必须直接带 SlotTitle / SlotValue。
```

原因：

```text
SelectionPanel.cs 现在已经禁止运行时用旧逻辑临时拼槽位文本。
如果 prefab 本体缺少该模板，运行时会直接报错并停止槽位区重建。
```

因此后续排查时必须同时检查两层：

```text
1. 生成器代码里是否声明了 MechanicalSlotTemplate
2. SelectionBuildingControlPage_Prefab.prefab 资源文件里是否真的存在该节点
```

本轮通过 Unity batch 重建后，以下关键节点已确认重新写回资源本体：

```text
MechanicalModificationPage
ActionButtonArea
MechanicalSlotsContent
MechanicalSlotTemplate
SlotTitle
SlotValue
```
