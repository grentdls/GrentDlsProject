# HUD 选择动作页模块

## 模块目标

`SelectionActionPanel_Prefab` 是选中单位/建筑后的右侧动作页容器。运行时节点名为 `UnitBuildingActionPages_RightContainer`。

## Prefab 文件

```text
Assets/Resources/UI/Prefabs/InGame/SelectionActionPanel_Prefab.prefab
```

## 数据与按钮来源

- 单位命令按钮：`SelectionPanel.CreatePcActionButton()` 动态写入 `RightActionArea`。
- 建筑科技页：`SelectionBuildingTechTreePage_Prefab`，动态填充研究按钮和研究队列。
- 建筑生产页：`SelectionBuildingProductionPage_Prefab`，动态填充造兵/建造按钮和生产队列。
- 建筑控制页：`SelectionBuildingControlPage_Prefab`，动态填充升级、集结、拆除等普通操作。
- 机械改造页：`SelectionPanel` 在 `BuildingControlPage_Standalone/MechanicalModificationPage` 内填充分类栏、槽位、改造卡和状态栏。单位机械改造与建筑机械改造共用这一页。
- 建筑普通操作按钮：`SelectionPanel.CreatePcActionButton()` 在建筑被选中时优先写入 `BuildingControlPage_Standalone/ActionButtonArea`，不再直接把按钮挂到 `BuildingControlPage_Standalone` 根节点。

## 布局规则

- 根节点 slotId 必须为 `UnitBuildingActionPages_RightContainer`。
- `RightActionArea` 用于单位命令和提示文本。
- 建筑子页由 `RefreshPcActionButtons()` 根据当前建筑能力显隐。
- 机械建筑存在改造模块时，`MechanicalModificationPage` 作为 `BuildingControlPage_Standalone` 内的主内容页显示，普通 `ActionButtonArea` 退回为辅助操作区。
- `BuildingControlPage_Standalone` 在机械改造页显示时仍保持父容器激活，仅切换内部 `ActionButtonArea` 与 `MechanicalModificationPage` 的显隐，避免父节点被隐藏后子页面无法显示。
- 机械单位点击“改造”后，也复用 `MechanicalModificationPage`，不再在 `RightActionArea` 临时堆一组改造卡。
- 右侧动作页不再使用 `SelectionPanel_Prefab` 里的旧 `ActionGrid_Buttons`。

## 运行时边界

- `SelectionPanel` 只负责：
  - 填充分类按钮
  - 刷新槽位文本与已装模块
  - 刷新改造卡数据、可点击状态、详情触发
  - 刷新状态栏进度与当前提示
- `SelectionPanel` 不再允许运行时创建 `MechanicalModificationPage` 根节点，也不应在缺少 `MechanicalSectionTitle`、`MechanicalCategoryTabsViewport`、`MechanicalSlotsViewport`、`MechanicalGridViewport`、`MechanicalStatusPanel` 等固定节点时临时补一套可见结构。
- `MechanicalSlotsContent` 下必须提供 `MechanicalSlotTemplate`，其中至少包含 `SlotTitle` 与 `SlotValue`。运行时只克隆模板并写入当前槽位数据，不再用 `ResolveOrCreateText(...)` 临时拼可见槽位文本。
- `SelectionBuildingControlPage_Prefab` 必须把 `MechanicalSlotTemplate` 直接序列化到 prefab 资源本体中；不能只在生成器代码里声明但没有实际写入资源。后续重建 prefab 时，需优先检查资源文件内是否真实存在 `MechanicalSlotsContent/MechanicalSlotTemplate`。
- 改造页的固定结构、节点名、位置、大小、背景、状态栏排版必须在 prefab 内维护。
- 改造卡内部固定节点至少应包含 `Title`、`Icon`、`Meta`、`Description`、`CostRow`；`CostRow` 内至少应包含 `CostSlotTemplate` 与 `FreeLabel`。卡片根节点必须直接带 `Button`、`UiPressFeedback`，代码只绑定名称、图标、分类元信息和费用数据。
- 建筑操作区旧的“机械改造卡混排大卡布局”已停用，机械改造卡只能在 `MechanicalModificationPage/MechanicalGridContent` 内显示。
- 后续如果要继续微调机械改造页布局，应优先编辑 `MechanicalModificationPage` 及其子节点，不要再把静态布局写回 `SelectionPanel.cs`。

## 生成与校验补充

- `UiPrefabWorkflowGenerator.GenerateEditableUiPrefabs()` 在重建整包 UI prefab 后，必须额外校准机械改造页结构，确保以下节点已经真实存在于资源文件：
  - `ActionButtonArea`
  - `MechanicalModificationPage`
  - `MechanicalSlotsViewport/MechanicalSlotsContent/MechanicalSlotTemplate`
- 推荐校验方式：
  - 运行 Unity batch：`RTSGame.Editor.UiPrefabWorkflowGenerator.GenerateEditableUiPrefabs`
  - 再扫描目标 prefab：
    - `MechanicalSlotTemplate`
    - `SlotTitle`
    - `SlotValue`
    - `ActionButtonArea`

## 禁止项

- 不允许恢复 `ActionGrid_Buttons` 和 `ActionButton_1~8`。
- 不允许在代码中创建旧式固定动作页背景；缺 prefab 只能创建无视觉占位并报错。
- 不允许把建筑生产页、科技页、控制页的节点名改掉。
- 不允许再把机械改造卡直接塞回普通建筑操作按钮行作为最终展示。
- 不允许再把机械改造卡的 `CostRow`、`Meta`、标题区、图标区以纯 `new GameObject(...)` 方式重建成最终可见结构。
