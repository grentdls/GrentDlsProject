# 竖版城市幸存者——全界面 UI 视觉、图文布局与 UX 动效完整规范

> 所属项目：《英雄城：永夜守望》（暂定名）  
> 文档版本：V1.0  
> 对应总案：《竖版城市建造 × 永久成长幸存者小游戏完整制作方案》  
> 对应战斗文档：《竖版城市幸存者——战斗逻辑、操作、动画与表现完整制作方案》  
> 对应建筑文档：《竖版城市幸存者——建筑玩法、预制体、HUD 与 UI 完整方案》  
> 默认平台：竖屏移动端/小游戏，参考分辨率 1080×1920，Unity UGUI 或等价 UI 框架  
> 文档目标：将当前临时、文本化界面升级为统一、美观、图文并茂、交互顺滑且可以直接制作的完整 UI 系统

## 1. 当前问题与改版目标

### 1.1 当前常见问题

- 货币、材料和属性只显示文字名称与数字，没有统一图标。
- 英雄、装备、技能和建筑详情由大量连续文本组成，缺少视觉分组。
- 所有信息使用相同底板、字号和颜色，玩家无法快速判断重要程度。
- 页面只有“打开/关闭”，缺少弹出、跳转、返回和内容变化反馈。
- 列表项像临时开发按钮，没有缩略图、状态角标、品质框和操作重点。
- 空内容、加载中、资源不足、禁用、完成、可领取等状态没有统一表现。
- 弹窗层级混乱，同一操作可能连续打开多个窗口，返回逻辑不稳定。
- 红点、感叹号和闪烁使用过多，界面显得嘈杂。
- 信息多时超出背景框，信息少时又留下大片空白。
- 战斗、城市、英雄和商店像不同项目拼在一起，缺少统一视觉语言。

### 1.2 改版目标

1. 玩家优先通过图标、头像、插图、颜色和框体理解信息，文字用于补充。
2. 每个页面只突出一个主要目标和一个主要操作。
3. 同类信息使用统一组件，降低玩家学习成本和开发维护成本。
4. 界面进入、退出、跳转、加载、领取和升级都具有明确 UX 反馈。
5. 长短内容均能自适应，适配不同语言、设备比例和数据长度。
6. UI 美观但不遮挡城市场景和战斗信息。
7. 动效提高理解和质感，不拖慢操作、不重复抢夺注意力。

### 1.3 核心设计原则

```text
先看图形 → 再看关键数字 → 再看名称 → 最后阅读详细文字
```

- 高频信息图标化。
- 重要对象角色化：英雄用头像/立绘，建筑用缩略模型，装备用独立图标。
- 复杂信息卡片化：属性、词条、效果、来源分成不同底框。
- 状态颜色与品质颜色分离。
- 主要操作固定位置，次要操作收纳。
- 所有跳转都能返回原上下文。

## 2. UI 整体视觉方向

### 2.1 视觉关键词

- 卡通低多边形。
- 温暖奇幻城镇。
- 冒险者工坊。
- 木材、羊皮纸、深蓝灰金属。
- 大色块、清晰轮廓、少量高亮金色。
- 轻量精致，不做厚重复杂的传统重度 SLG 框体。

### 2.2 界面材质分工

| 材质/色调 | 使用位置 | 视觉作用 |
| --- | --- | --- |
| 深蓝灰 | 顶栏、导航、功能页背景 | 稳定、衬托图标和内容 |
| 暖木 | 建筑、制造、普通按钮边框 | 对应城市和工坊 |
| 浅羊皮纸 | 说明、任务、故事、普通详情 | 便于阅读长文本 |
| 金属 | 装备、铁匠铺、防御、品质边缘 | 强化战斗与制造感 |
| 魔法蓝紫 | 卡牌、技能商店、研究 | 区分技能系统 |
| 金色 | 稀有奖励、主要完成状态 | 只用于重点，不滥用 |

### 2.3 推荐主色板

| 用途 | 色值建议 |
| --- | --- |
| 页面深色背景 | `#182331` |
| 一级面板 | `#243346` |
| 二级卡片 | `#31445A` |
| 羊皮纸浅底 | `#F0DFC1` |
| 暖木主色 | `#815238` |
| 暖木高光 | `#B9794D` |
| 主金色 | `#F2BF58` |
| 可操作绿色 | `#58C58A` |
| 信息蓝色 | `#58A7E6` |
| 警告橙色 | `#E89A43` |
| 错误红色 | `#DF5C5C` |
| 深底主文字 | `#F4F1EA` |
| 深底次文字 | `#B8C2CE` |
| 浅底主文字 | `#302820` |
| 浅底次文字 | `#746556` |

色值为生产起点，最终需要在实际场景、设备亮度和色弱模式下校正。

### 2.4 形状语言

- 主面板圆角：24～32 px。
- 卡片圆角：18～24 px。
- 小标签/货币胶囊：完整圆角。
- 英雄头像框偏圆角方形，装备框保持方形，资源图标使用无框或胶囊。
- 战斗危险 UI 使用尖角、三角和强方向性，与城市圆润 UI 区分。
- 按钮边框厚度统一，不按页面随意改变。

### 2.5 阴影和高光

- 深底卡片使用内高光和轻投影，不使用大片模糊阴影。
- 浅色羊皮纸使用暖灰阴影，避免纯黑。
- 选中状态优先用描边、底板抬高和图标填充，不只提高亮度。
- 金色高光只用于高级奖励、突破、进化和完成，不覆盖普通按钮。

## 3. 参考分辨率、布局与安全区

### 3.1 基础适配

- 参考分辨率：1080×1920。
- Canvas Scaler：Scale With Screen Size。
- Match：建议 0.5，实际根据 UI 框架测试。
- 顶部、底部操作全部位于 SafeAreaRoot。
- 长屏增加场景或滚动区域，不拉长固定卡片。
- 宽屏/平板限制主要内容最大宽度，左右使用背景、侧栏或留白。

### 3.2 基础间距

| 类型 | 建议 |
| --- | ---: |
| 基础单位 | 8 px |
| 页面左右边距 | 36～48 px |
| 卡片内边距 | 20～28 px |
| 同组元素间距 | 8～16 px |
| 信息组间距 | 24～32 px |
| 主按钮高度 | 88～104 px |
| 次按钮高度 | 72～88 px |
| 最小触控区域 | 80×80 px |

### 3.3 字号系统

| 样式 | 字号 | 用途 |
| --- | ---: | --- |
| Display | 48～56 px | 胜利、升级、重大解锁 |
| H1 | 40～48 px | 页面标题 |
| H2 | 34～40 px | 弹窗、区域标题 |
| H3 | 28～34 px | 卡片标题、名称 |
| NumberLarge | 34～44 px | 战力、产量、奖励数量 |
| Body | 24～30 px | 正文、效果描述 |
| Caption | 20～24 px | 标签、来源、辅助信息 |
| Mini | 18～20 px | 极小角标，禁止更小 |

### 3.4 信息密度

- 手机一屏同时出现的一级信息组不超过 5 个。
- 每张卡片只显示一个主结果、最多 3 个次要标签。
- 详细文本默认折叠为 2～3 行，点击展开。
- 列表页重在扫描，详情页重在理解，不把完整描述复制到列表。

## 4. 图文并茂的信息组织规则

### 4.1 通用阅读顺序

```text
对象大图/头像
→ 名称、等级、品质/类型
→ 最关键数值或当前状态
→ 图标化属性与标签
→ 分组详细说明
→ 获取来源与主要操作
```

### 4.2 文字的合理用途

文字用于：

- 解释技能规则。
- 说明条件和限制。
- 展示剧情和背景。
- 补充图标无法表达的差异。

文字不用于：

- 重复写“金币：1000”，应使用金币图标 + `1,000`。
- 重复写“攻击力提升”，应使用攻击图标 + `+12%` + 简短标签。
- 用长段落列出装备属性，应该拆成属性行和词条卡。
- 用文本按钮表示可领取资源，应该使用资源图标和完成状态。

### 4.3 详细信息标准结构

任何英雄、装备、技能、建筑、敌人或物品详情，都尽量采用：

1. **视觉头部**：头像/大图 + 专属框 + 名称 + 等级/品质。
2. **核心摘要**：战力、产量、伤害、用途等 1～3 个关键数字。
3. **属性卡**：图标 + 字段名 + 数值。
4. **效果卡**：不同底框区分主动、被动、套装、组合、限制。
5. **来源卡**：来源图标 + 地点/建筑/关卡 + 定位按钮。
6. **操作栏**：一个主按钮 + 0～2 个次按钮。

### 4.4 底框语义

| 底框 | 用途 | 色彩 |
| --- | --- | --- |
| SummaryFrame | 核心概览 | 深蓝灰 + 金色小边 |
| StatFrame | 数值属性 | 中性深灰/浅纸 |
| ActiveEffectFrame | 主动技能 | 英雄/技能主色 |
| PassiveEffectFrame | 被动效果 | 蓝灰或绿色 |
| SetEffectFrame | 套装效果 | 金属 + 品质色条 |
| WarningFrame | 互斥、损失、限制 | 橙红，不大面积纯红 |
| SourceFrame | 获取来源 | 羊皮纸或地图蓝 |
| LockedFrame | 未解锁 | 降饱和 + 锁图标 |

## 5. 图标系统

### 5.1 图标分类

| 分类 | 示例 | 风格 |
| --- | --- | --- |
| 货币资源 | 金币、木材、粮食、铁矿、卷轴 | 独立物体、明快色块 |
| 战斗属性 | 攻击、生命、防御、暴击、移速 | 实心符号、统一描边 |
| 功能操作 | 升级、分解、刷新、移动、锁定 | 简洁线面结合 |
| 状态 | 燃烧、护盾、眩晕、疲惫 | 高辨识轮廓 + 状态色 |
| 建筑 | 铁匠铺、农场、市场 | 3/4 俯视缩略图 |
| 玩法 | 主线、资源关、防守、试炼 | 场景化徽章 |

### 5.2 货币显示

所有高频货币使用：

```text
[资源Icon] [紧凑数字] [可选加号]
```

- 顶栏不显示完整资源名称。
- 数量 9999 以下完整显示；1 万以上使用 `1.2万`、`12.6万`。
- 点击货币打开来源与消耗面板。
- 数量不足时数字变橙红，并出现一次轻微左右晃动。
- 可购买或补充时显示小型 `+`，不可补充时不显示假入口。

### 5.3 图标尺寸

- 资源源文件：256×256，透明边距 12%～16%。
- 装备/技能源文件：512×512。
- 头像源文件：512×512 或 1024×1024。
- 界面常用资源图标显示：36～48 px。
- 属性图标：28～40 px。
- 列表对象图标：88～136 px。

### 5.4 图标一致性

- 同一含义只能有一个主图标。
- 不同资源必须在黑白模式下也能凭轮廓区分。
- 图标不依赖内部小文字。
- 图标的透视、光源和描边统一。
- 禁止直接混用不同素材库导致风格割裂。

## 6. 头像、立绘、缩略图与品质框

### 6.1 英雄头像

- 正方形圆角头像，头部占画面 55%～70%。
- 背景使用英雄主色和职业图案。
- 左上角可显示职业小图标。
- 右下角显示等级或状态，不同时显示过多角标。
- 星级放在头像下方或详情头部，不围绕头像塞满星星。

### 6.2 英雄立绘

- 英雄详情和招募页使用半身/全身立绘作为上半屏主视觉。
- 立绘背景使用英雄专属渐变、纹章和低透明场景元素。
- 立绘不能被属性卡和按钮大面积遮挡。
- 装备变化若不反映到模型，使用装备槽明确表达，不伪装成实时换装。

### 6.3 建筑缩略图

- 使用与城市相同的 3/4 俯视角。
- 背景按建筑类别区分：生产绿、制造橙、成长蓝紫、防御红灰。
- 缩略图包含建筑主体，不包含复杂场景。
- 突破后的建筑可以更新缩略图，普通等级不必逐级更换。

### 6.4 装备图标

- 物体占图标安全区 70%～82%。
- 品质由外框、顶部小光效和底色共同表示，不给物体本身强行染色。
- 已装备、锁定、可强化、套装等状态使用角标，最多同时显示 2 个。

### 6.5 品质框

| 品质 | 主色 | 表现 |
| --- | --- | --- |
| 普通 | 灰蓝 | 简洁细边 |
| 优秀 | 绿色 | 内侧柔光 |
| 稀有 | 蓝色 | 角部装饰 |
| 史诗 | 紫色 | 双层边 + 微粒 |
| 传说 | 金橙 | 专属纹章 + 低频流光 |

品质颜色不用于按钮状态、错误状态或建筑等级，避免语义冲突。

## 7. 通用 UI 组件规范

### 7.1 货币胶囊 CurrencyChip

结构：资源图标、数字、可选 `+`、点击区域。  
状态：正常、变化、资源不足、接近容量、禁用。  
动效：资源飞入后数字滚动，图标缩放 `1.0→1.12→1.0`。

### 7.2 头像卡 PortraitCard

结构：头像、类型/职业图标、名称、等级、状态角标。  
状态：正常、选中、锁定、出战、派遣、受伤。  
选中：框体抬高、底板变亮、右侧出现勾选，不仅加描边。

### 7.3 物品卡 ItemCard

结构：品质框、物品图标、等级、数量、状态角标。  
长按：打开快速详情。  
点击：选中或进入详情，行为必须按页面保持一致。

### 7.4 属性行 StatRow

```text
[属性Icon] [属性名]          [当前值] [变化值]
```

- 相同字段纵向对齐。
- 提升使用绿色 `+12`，下降使用红色 `-8`。
- 百分比与绝对值不可混写。
- 点击可打开来源说明，如攻击来自英雄等级、装备和卡牌。

### 7.5 效果卡 EffectCard

- 左侧技能/词条图标。
- 中部名称和 1～3 行描述。
- 右上显示等级、触发类型或品质。
- 底部放标签，如燃烧、弹射、护盾。
- 数值字段与普通文字采用不同颜色，但每句最多高亮 2～3 处。

### 7.6 标签 TagChip

- 用于职业、元素、技能类型、路线和状态。
- 高度 32～44 px，图标可选。
- 一张卡最多常显 3 个，更多折叠为 `+2`。
- 标签颜色按语义固定，不随机使用品质色。

### 7.7 主按钮 PrimaryButton

- 使用动作动词：开始建造、确认升级、装备、领取。
- 按钮内允许“图标 + 文本 + 消耗”，例如锤子图标、升级、金币图标 `1,000`。
- 同一页面只有一个最高视觉层级主按钮。
- 禁用时仍显示原因，点击禁用按钮可弹轻提示。

### 7.8 页签 TabBar

- 2～5 个页签可同时显示，超过 5 个改用二级入口或横向滚动。
- 当前页使用底板抬高、图标填充和短下划线。
- 切换页签保留页面滚动和筛选状态。
- 页签切换不重新播放全屏入场动画。

### 7.9 进度条 ProgressBar

- 由背景条、填充条、关键节点、当前值组成。
- 填充变化使用 0.2～0.45 秒追随动画。
- 等级/经验条接近完成时显示流光，不持续闪烁。
- 进度条必须同时显示数值或明确节点，不能只看长度猜测。

### 7.10 信息提示 Tooltip

- 点击信息图标或长按字段出现。
- 锚定目标附近，并自动避开屏幕边缘。
- 最多显示标题、2～5 行说明和一个“查看详情”入口。
- 点击外部关闭，不加入主要导航栈。

### 7.11 空状态 EmptyState

- 使用插图/剪影 + 标题 + 原因 + 建议动作。
- 例：“还没有装备”配空武器架插图，并提供“前往铁匠铺”。
- 禁止只有一行“暂无数据”。

### 7.12 加载骨架 Skeleton

- 列表和详情使用与真实布局近似的骨架屏。
- 超过 0.35 秒才显示，避免瞬间闪烁。
- 加载失败显示原因、重试和返回，不无限旋转。

## 8. 页面层级与导航架构

### 8.1 五级 UI 层

| 层级 | 内容 | 示例 |
| --- | --- | --- |
| Root | 主导航页面 | 城市、英雄、出征、装备、天赋 |
| FullScreen | 二级完整页面 | 铁匠铺、技能商店、地图、英雄详情 |
| Sheet | 保留背景上下文的抽屉 | 建筑详情、资源来源、筛选 |
| Modal | 必须确认的弹窗 | 购买、重置、拆除、选择 |
| Overlay | 不阻断或短暂反馈 | Toast、奖励、资源飞行、教学 |

### 8.2 导航栈

- Root 页面之间切换不叠栈，只替换当前根页面。
- FullScreen 页面入栈，返回时恢复上一页滚动、筛选和选中对象。
- Sheet 依附当前页面，关闭后回到原上下文。
- Modal 依附当前 Sheet/Screen，只处理一个明确任务。
- Overlay 不进入返回栈。

### 8.3 返回优先级

```text
关闭最高层Modal
→ 关闭Tooltip
→ 收起BottomSheet
→ 退出当前编辑/选择模式
→ 返回上一个FullScreen
→ Root页面不退出游戏，弹出退出确认或交由平台
```

### 8.4 深度跳转

例如资源不足时：

```text
装备强化页
→ 点击缺少铁矿
→ 打开铁矿来源Sheet
→ 进入矿洞关卡详情
→ 战斗/扫荡完成
→ 返回装备强化页并保留原装备
```

导航系统需要携带 ReturnContext，避免玩家获得资源后重新从首页寻找原功能。

### 8.5 防重复打开

- 同一页面请求打开时只聚焦现有实例。
- 转场期间锁定重复导航输入 0.15～0.3 秒。
- 按钮提交后立即进入 Loading/Processing 状态。
- 高延迟操作显示按钮内加载，不重复弹窗。

### 8.6 全界面跳转关系

| 根页面 | 主要二级页面 | 常用抽屉/弹窗 | 返回后的状态 |
| --- | --- | --- | --- |
| 城市 | 建筑功能页、铁匠铺、技能商店、酒馆等 | 建筑详情、资源来源、升级确认 | 恢复城市镜头和选中建筑 |
| 英雄 | 英雄详情、觉醒、构筑模拟 | 卡牌详情、属性来源、升星确认 | 恢复原英雄和页签 |
| 出征 | 世界地图、关卡准备、战斗 | 关卡详情、体力来源、战斗结算 | 恢复原章节和地图位置 |
| 装备 | 背包、装备详情、强化、重铸 | 装备对比、词条说明、分解确认 | 恢复部位筛选和选中装备 |
| 天赋 | 战斗/生存/城建路线 | 节点详情、升级/重置确认 | 恢复路线位置和缩放 |
| 通用入口 | 任务、活动、邮件、商店、设置 | 奖励、购买、帮助、错误 | 返回进入前的根页面 |

### 8.7 典型 UX 路径

```text
城市 → 选中铁匠铺 → 制造页 → 材料不足 → 铁矿来源
→ 矿洞关卡 → 战斗结算 → 自动返回制造页 → 原配方仍被选中
```

```text
英雄 → 永久卡牌 → 查看进化组合 → 缺少研究卡
→ 技能商店 → 锁定研究订单 → 研究完成 → 返回组合图鉴
```

```text
世界地图 → Boss关卡详情 → 战前准备 → 战斗
→ 胜利结算 → 下一关/返回地图 → 原地图位置与章节保持
```

## 9. 窗口打开、关闭与跳转动效

### 9.1 动效时长表

| 类型 | 打开 | 关闭 | 推荐曲线 |
| --- | ---: | ---: | --- |
| Root切换 | 0.16～0.22秒 | 同步 | EaseOut |
| FullScreen推进 | 0.22～0.30秒 | 0.18～0.24秒 | CubicOut/CubicIn |
| BottomSheet | 0.22～0.32秒 | 0.18～0.26秒 | BackOut轻量/QuadIn |
| Modal弹窗 | 0.18～0.25秒 | 0.14～0.20秒 | BackOut/QuadIn |
| Tooltip | 0.10～0.16秒 | 0.08～0.12秒 | EaseOut |
| Toast | 0.18秒 | 0.18秒 | EaseOut |
| 奖励演出 | 0.5～2.5秒 | 可跳过 | 分段 |

### 9.2 Root 页面切换

- 原内容向切换方向移动 16～32 px并淡出。
- 新内容从反方向轻移入并淡入。
- 顶栏和底栏保持稳定，不随页面重复入场。
- 相邻页签可有方向感，非相邻页直接交叉淡化。

### 9.3 FullScreen 推进

- 新页面从右侧移动约屏幕宽度的 12%～20%，同时淡入。
- 原页面向左轻移并降低亮度，不完全滑出，形成层级感。
- 返回时严格反向播放。
- 进入完成前，标题和主内容可提前到位，细节不需要逐项飞入。

### 9.4 BottomSheet

- 背景压暗到 35%～55%，按信息重要程度调整。
- 抽屉从底部滑入，最后 5%略微减速。
- 支持拖拽关闭时，抽屉跟手，速度/距离超过阈值后关闭。
- 有未保存改动时，下拉不直接关闭，弹出保留/放弃确认。

### 9.5 Modal 弹窗

- 背景压暗并轻微降饱和。
- 弹窗 `Scale 0.92→1.0` 同时淡入。
- 打开后焦点落到主内容，不让关闭按钮先闪烁。
- 关闭先禁用输入，再在 0.14～0.2 秒退场。

### 9.6 页面内跳转

- 页签切换：内容区横移 12～20 px + 淡化，0.14～0.2 秒。
- 列表到详情：对象缩略图可短暂放大并连接到详情头像/大图。
- 地图到关卡详情：关卡节点扩散成详情底板，或使用底部抽屉。
- 建筑到功能页：相机先聚焦建筑 0.2 秒，再打开页面；高频打开可跳过聚焦。

### 9.7 关闭方式

- 顶部左侧返回：FullScreen。
- 顶部右侧关闭：独立 Modal/Sheet。
- 点击遮罩：仅关闭非高风险 Modal/Sheet。
- 下拉：仅 BottomSheet。
- 系统返回键：按统一返回优先级。
- 关闭动作与打开方向相反，避免空间逻辑混乱。

### 9.8 动效可跳过

- 重复奖励、批量制造、十连结果允许点击加速/跳过。
- 核心首次解锁可以强演出，重复操作缩短。
- 设置中提供减少动态效果，关闭大幅位移和镜头缩放。

## 10. 按钮、列表与微交互

### 10.1 按钮状态

| 状态 | 表现 |
| --- | --- |
| Normal | 默认色与轻高光 |
| Pressed | 缩放0.96～0.98、阴影变浅 |
| Selected | 抬高、实色底、勾选/短光圈 |
| Disabled | 降饱和，保留文字和原因 |
| Loading | 锁定输入，图标替换为小进度 |
| Success | 短绿色勾选，然后恢复/关闭 |
| Error | 一次轻晃 + 原因Toast |

### 10.2 列表项反馈

- 点击时卡片背景先响应，再执行跳转。
- 长按 0.35～0.5 秒打开快捷详情，并给予轻触震动。
- 滑动列表时不误触卡片。
- 已读/未读用内容状态和小点表达，不整张卡持续发光。
- 列表刷新保持滚动位置，除非用户主动回顶。

### 10.3 数值变化

- 增加：旧值滚动到新值，绿色变化值短暂上浮。
- 减少：数字滚动，橙色闪现，不使用错误红色。
- 战力提升：战力值向上滚动，提升量在右侧 `+125`，持续 1 秒。
- 多项变化：先更新核心战力，再同时更新属性行，不逐行慢播。

### 10.4 选择状态

- 英雄、装备、卡牌的选中必须同时包含框体变化、勾选和详情联动。
- 不允许只改变边框 1～2 px，移动端不明显。
- 多选模式显示已选数量和固定底部操作栏。

### 10.5 拖拽

- 长按后对象抬起、阴影加深、原位留占位框。
- 合法目标高亮，非法目标红灰。
- 放下成功有吸附和轻震；失败回弹原位并解释原因。
- 重要装备和建筑移动支持取消，不因手指轻微偏移误触。

### 13.1 建造列表

- 3/4 俯视建筑缩略图。
- 建筑类型底色和小图标。
- 名称、功能一句话。
- 木材/金币图标 + 数量。
- 建造时间图标 + 时间。

### 13.2 建筑详情头部

```text
[建筑大缩略图/3D预览]
[类型底框] 建筑名称  Lv.5
[状态图标] 正在生产 / 可领取 / 升级中
```

- 核心产量卡：木材图标 + `120/小时`。

### 13.4 升级对比

- 上半部显示当前模型与下级新增部件高亮。
- 数值使用当前值 → 新值。
- 新功能以独立金色解锁卡显示，不塞在升级描述段落里。
- 成本使用资源图标行。
- 底部固定“开始升级”按钮，按钮内可显示时间图标和时长。

### 13.5 升级动效

1. 点击确认后资源从顶栏飞向建筑图标。
2. 按钮进入成功状态并关闭弹窗。
3. 城市场景建筑出现脚手架和锤击。
4. 完成时模型变化先出现，再显示 `Lv.4→Lv.5`。
5. 新功能卡从建筑方向飞入界面并被记录。

## 17. 升级三选一卡牌界面

### 17.1 卡面图文结构

竖屏推荐三张横向信息卡纵向排列：

- 左侧 28%：技能插图/特效图标。
- 中部 52%：卡名、当前等级 → 新等级、2～3 行效果。
- 右侧 20%：品质、路线、选择按钮或箭头。
- 底部：最多 3 个组合标签。

这种布局比三张细长竖卡更适合中文和小屏阅读。

### 17.2 卡牌底框

- 普通强化：英雄主色细边。
- 新技能：蓝色光标和“新技能”角标。
- 路线核心：双层边框、路线纹章和互斥警告。
- 进化：金紫底框、组合图标汇聚。
- 满级前最后一次强化：显示 `MAX` 预告。

### 17.3 打开动效

1. 战场 0.15 秒减速后暂停。
2. 背景压暗并保留英雄轮廓。
3. 标题“永久升级”从上方淡入。
4. 三张卡以 0.04～0.06 秒错峰从下方弹入。
5. 新技能/进化卡在落位后播放一次低频光效。

### 17.4 选择动效

- 点击卡牌先抬高并展开完整描述。
- 再次点击或点击“选择”确认。
- 其他卡牌向两侧/下方淡出。
- 已选卡缩放到 1.08，图标飞向英雄头像。
- 右上显示“已永久保存”，首次突出、后续缩短。

### 17.5 互斥路线确认

- 弹窗用两条路线图标并列显示。
- 明确列出“获得”和“将锁定”的卡牌类型。
- 主按钮写“选择万剑路线”，不使用模糊“确定”。
- 次按钮返回卡牌选择。

## 18. 战斗胜利、失败与奖励界面

### 18.1 胜利页

- 上半屏：英雄胜利姿势/半身立绘 + 场景光效。
- 大标题“胜利”与关卡徽章。
- 中部：永久等级进度、获得卡牌图标。
- 下部：奖励分组卡——城市资源、装备材料、首次奖励。
- 底部：返回城市、下一关两个按钮，下一关为主按钮。

### 18.2 奖励展示

- 普通资源不逐个占大卡，使用资源图标 + 数量网格。
- 新装备、高品质材料、图纸和英雄碎片单独大卡展示。
- 新物品先显示图标和品质，再展开名称与用途。
- 点击任意位置可加速，重复结算可一键跳过。

### 18.3 失败页

- 使用英雄倒地剪影/头像，不使用纯红大字压迫。
- 显示死亡原因敌人头像、技能图标和一句针对性建议。
- 已保留内容用绿色框：经验、永久卡牌、部分资源。
- 未获得内容使用灰色框解释条件。

## 31. 弹窗与确认规则

### 31.1 何时需要确认

需要：

- 消耗稀有货币。
- 分解高品质/锁定物品。
- 重置卡牌、天赋。
- 拆除建筑。
- 放弃未保存修改。
- 退出会损失本场未结算内容。

不需要：

- 普通资源领取。
- 普通页面跳转。
- 免费移动建筑。
- 低价值重复制造。
- 已明确可撤销的操作。

### 31.2 确认弹窗结构

- 顶部风险/对象图标。
- 标题使用明确动作，如“分解史诗长剑？”。
- 中部显示对象卡或损失/收益图标。
- 辅助说明最多 3 行。
- 左侧取消，右侧明确动作按钮。
- 危险按钮用红色，但不把整个弹窗染红。

### 31.3 连续弹窗

- 同时只能显示一个 Modal。
- 后续弹窗进入队列，不叠在当前弹窗上。
- 相同错误合并为 Toast，不连续弹多个确认。
- 奖励揭示 Overlay 不阻止高优先断线/错误提示。

## 32. Toast、气泡、红点与通知

### 32.1 Toast

- 普通成功：图标 + 一行文字，持续 1.2～1.8 秒。
- 错误：原因 + 可选解决入口，持续 2～3 秒。
- 同类短时间合并，如连续获得木材。
- Toast 从顶部安全区下方或底部导航上方出现，不遮挡主按钮。

### 32.2 角色气泡

- 城市居民和英雄可使用头像气泡表达事件。
- 气泡最多 1～2 行，点击进入完整内容。
- 同屏最多 2 个，避免城市变成弹幕。

### 32.3 红点语义

| 标记 | 含义 |
| --- | --- |
| 红点 | 新功能、必须处理、重要未读 |
| 绿色点 | 可免费领取 |
| 数字角标 | 待处理数量，如邮件、任务奖励 |
| 金色星标 | 新获得高品质内容 |
| 橙色感叹号 | 阻塞/资源满/配置异常 |

### 32.4 红点限制

- 主导航同时最多 3 个红点。
- 打开并看到内容后，新功能红点消失。
- 可升级不默认全局红点，只在当前对象或推荐强化时提示。
- 红点系统按来源注册，禁止各页面自行写死。

## 33. 加载、断线、错误与恢复 UX

### 33.1 加载状态

- 小于 0.35 秒：不显示加载。
- 0.35～2 秒：按钮内 Loading 或骨架屏。
- 超过 2 秒：显示阶段说明，如“正在加载城市场景”。
- 超过合理时间：提供重试、返回和网络检查。

### 33.2 提交中

- 升级、购买、领取、永久选卡等提交后立即锁定重复操作。
- 按钮显示转圈和“处理中”。
- 成功后显示勾选再关闭。
- 失败恢复原按钮状态，并保留玩家选择。

### 33.3 断线

- 非关键场景使用顶部网络图标和自动重连，不立刻弹窗打断。
- 永久选卡、购买、战斗结算失败时显示 Modal，说明数据已保存到哪一步。
- 重连成功回到原页面、原滚动位置和原选择。
- 不允许断线后重复领取或刷新卡牌候选。

### 33.4 空数据与错误数据

- 空数据使用插图化 EmptyState。
- 配置缺失使用开发环境错误占位，正式环境显示安全默认内容并记录日志。
- 图片未加载使用同类别占位图，不显示白框或破图符号。

| L4 | 新英雄、技能进化、章节完成 | 2.5～5秒，可跳过 |

### 34.2 普通资源

- 图标 + 数量弹出并飞向目标入口。
- 同类奖励合并。
- 不打开全屏奖励页。

### 34.3 高品质物品

- 背景压暗。
- 品质色从中心展开。
- 物品图标/模型出现。
- 名称、品质、核心用途逐步显示。
- 底部查看详情/继续。

### 34.4 新英雄

- 英雄剪影、职业纹章、立绘揭示。
- 播放一句角色语音或签名动作。
- 展示定位和 3 个核心技能图标。
- 不在揭示阶段塞入完整属性表。

### 34.5 系统解锁

- 以建筑、功能图标和一句用途为主。
- 显示“它能为你带来什么”，例如铁匠铺解锁装备制造。
- 点击“前往体验”直接深度跳转。
- 首次强演出，后续升级只做轻提示。

## 35. UI 音效与震动

### 35.1 音效类别

- 普通点击：轻木/皮革声。
- 页签切换：短滑动声。
- 弹窗打开：柔和展开。
- 金属制造：锤击和金属清脆声。
- 卡牌/魔法：纸张、符文和能量声。
- 领取资源：按资源类型区分基础质感。
- 错误：低沉短音，不刺耳。
- 重要奖励：品质递增的音乐层。

### 35.2 频率限制

- 高频按钮每 0.05～0.1 秒限制同类声音。
- 批量领取不逐项播放完整音效。
- 页面转场音与奖励音避免同时抢占。
- Toast 成功不需要每次震动。

### 35.3 震动

- 轻震：选择、普通领取、拖拽吸附。
- 中震：升级、稀有物品、卡牌确认。
- 强震：新英雄、技能进化、Boss 奖励。
- 支持关闭和系统减少动态设置。

## 38. 自适应、本地化与可访问性

### 38.1 长文本

- 卡片描述最多 2～3 行，超出显示展开。
- 详情内容自然增高。
- 超过可视区时中间滚动，标题和操作栏固定。
- 不用缩小字体解决文本过长。

### 38.2 数字长度

- 货币使用紧凑格式。
- 详细页面可显示完整值。
- 极大数字统一单位，不同页面不混用 K/M 和 万/亿。
- 表格列为最大预期数字预留宽度。

### 38.3 本地化

- 所有文本使用本地化 Key。
- 德语/英语等长文本测试宽度为中文的 1.5～2 倍。
- 图标不嵌入文字。
- 动态词句避免强拼接，使用完整格式化模板。

### 38.4 色弱

- 品质、状态、危险同时使用图标和形状。
- 提升/下降使用箭头，不只用红绿。
- 设置提供高对比预警。

### 38.5 减少动态效果

- 关闭大幅滑动和镜头缩放。
- 保留必要淡入淡出和状态确认。
- 奖励演出缩短。
- 不影响逻辑和输入锁定。

## 41. 性能规范

### 41.1 UI 性能目标

- Root 页面 Canvas 分层，避免一个数字变化重建整屏。
- 高频数值、倒计时和列表拆分 Canvas。
- 长列表使用虚拟化。
- 头像、图标异步加载并缓存。
- 页面关闭后释放大立绘和非共用横幅。
- 粒子与资源飞行对象池化。

### 41.2 动效限制

- 同屏 UI 粒子实例建议不超过 20～30 个。
- 普通页面转场不使用全屏高 Overdraw 粒子。
- 模糊背景可使用截图或低成本方案，低端档改为纯压暗。
- 同时最多播放一个 L3/L4 UI 强演出。

### 41.3 更新频率

- 计时显示每 0.2～1 秒更新，不必每帧。
- 资源数字仅变化时更新。
- 屏幕外列表项停止动效。
- 红点由事件驱动，不轮询所有系统。

## 44. 最终设计结论

本项目 UI 改版的重点不是简单增加装饰框，而是改变信息表达方式：

```text
文字列表
→ 对象大图/头像
→ 图标化关键数值
→ 语义化底框
→ 简短效果说明
→ 明确主要操作
```

货币应以图标和数字被快速识别；英雄、装备、技能、建筑和敌人应拥有稳定的头像、大图、类型框和品质框；复杂说明应拆成属性卡、效果卡、组合卡和来源卡。城市、战斗和功能界面使用同一套组件系统，但通过场景横幅、对象主色和材质主题保持各自特色。

UX 上必须让玩家始终知道自己从哪里来、当前窗口处于哪一层、关闭后会回到哪里、操作是否成功。所有弹出、关闭、页面推进、页签切换、领取、升级和解锁都应有与重要程度匹配的反馈，同时支持重复操作加速和低端性能降级。

当图形、框体、数字、状态和动效共同承担信息表达后，界面才会从“临时功能菜单”升级为真正具有游戏品质、容易理解并且可长期扩展的完整 UI 系统。
