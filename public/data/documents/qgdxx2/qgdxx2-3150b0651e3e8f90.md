# 英雄名册与英雄详情整合实现说明

## 目标

英雄详情页现在同时承担“查看当前英雄”和“切换英雄”两项职责。进入详情页后，顶部固定显示可横向滑动的英雄名册；名册右侧提供“全部英雄”按钮，用小弹窗展示完整英雄列表，避免在详情页与名册页之间来回跳转。

## 已实现内容

- `HeroDetail` 页面顶部新增 `HeroCarouselPanel`。
- 顶部名册使用独立的水平 `ScrollRect`：`HeroCarouselViewport -> HeroCarouselContent`，卡片按横向布局排列，支持拖拽、惯性和边界夹紧。
- 打开详情时自动把当前英雄滚动到可视区域；已解锁英雄显示头像、名称、战力与等级，锁定英雄保留在列表中并显示“尚未解锁”。
- 点击已解锁英雄卡片会更新详情标题、模型、技能、装备与培养内容，并保留当前详情标签，便于在相同效果页对比不同英雄；点击锁定英雄只提示解锁条件，不会切换当前详情。
- 详情下方的“总览 / 命格 / 装备 / 道途”改为四个视觉边界明确的独立按钮，并增加随一级分类变化的二级按钮。切换英雄时同时保留一级与二级选择。
- 二级分页为：总览“属性成长 / 已学功法”、命格“命魂 / 先天词条”、装备“装备栏 / 智能配装 / 装备方案”、道途“修行 / 道途 / 天赋”。每次只创建当前二级页内容，避免长列表堆叠。
- 新增“全部英雄”按钮。按钮打开 `AllHeroesScrim -> AllHeroesPopup -> AllHeroesViewport -> AllHeroesContent` 层级，弹窗内部使用两列网格，适合快速浏览完整名册。
- 弹窗卡片与顶部横向卡片共用选择入口，选择成功后自动关闭弹窗并刷新详情页；遮罩点击和关闭按钮均可关闭弹窗。
- 所有布局均为运行时创建的 uGUI 层级，不要求修改场景或预制体；比例锚点适配竖屏安全区，避免把英雄列表挤进详情内容滚动区。

## 关键布局比例

| 区域 | 锚点范围（父级归一化坐标） | 用途 |
| --- | --- | --- |
| 英雄名册 | `y=0.845..1.0` | 标题、解锁计数、横向卡片、全部英雄按钮 |
| 详情展示区 | 普通页 `y=0.425..0.835` | 3D/占位英雄模型与属性摘要 |
| 详情展示区 | 培养页 `y=0.585..0.835` | 给两级分页和培养内容预留空间 |
| 一级分页 | 普通页 `y=0.345..0.415`；培养页 `y=0.505..0.575` | 四个独立主分类按钮 |
| 二级分页 | 普通页 `y=0.265..0.335`；培养页 `y=0.425..0.495` | 当前分类的内容按钮 |
| 全部英雄弹窗 | `x=0.07..0.93, y=0.17..0.86` | 遮罩上的完整英雄两列列表 |

顶部名册与详情展示区之间保留固定间隔。一级、二级分页使用各自的独立按钮行；内容滚动区只承载当前选择的内容，不改变原有技能、装备、派系和升阶入口。

## 验证

自动化 PlayMode 测试 `HeroCityAppSmokeTests.CityRootAndEdgeEntriesExposeLayeredFeatureSurfaces` 已覆盖：

1. 详情页存在顶部英雄横向列表。
2. 横向 `ScrollRect` 的方向配置正确。
3. `HorizontalLayoutGroup` 负责卡片排列。
4. “全部英雄”弹窗为独立层级且使用两列网格。
5. 弹窗关闭后销毁完整弹窗层级。
6. 从顶部名册切换英雄后详情标题同步更新。
7. 四个一级分页都是独立 `Button`，且各一级页拥有对应二级分页。
8. 装备栏、智能配装、装备方案以及修行、道途、天赋不会在同一滚动区同时出现。

本次验证只读取 Unity 测试 XML/日志，没有截图，也没有执行构建。
