# 竖版城市幸存者：全界面 UI 视觉与 UX 动效实现说明

## 本次实现范围

本次按《竖版城市幸存者_全界面UI视觉与UX动效完整规范》重做当前项目已经存在的界面，不新增市场、酒馆、活动、抽卡等尚无业务规则的空页面。游戏规则仍由原有纯 C# 系统负责，UI 只读取状态、调用已有事务入口并负责表现。

已覆盖：

- 城市常驻顶栏、资源入口、主任务、建造队列、五页底部导航。
- 城市、英雄、远征、工坊、进度五个根页面。
- 建筑世界 HUD、建筑快捷面板、建造列表、摆放确认、建筑详情、升级资源与资源来源抽屉。
- 幸存者战斗 HUD、Boss HUD、摇杆、终极技能、暂停、胜利/失败结算。
- 永久卡三选一、路线二次确认提示、全局 Toast。

## 共享视觉系统

`UiFactory` 现在集中维护规范中的深蓝背景、抬高表面、暖木、金色、行动绿、信息蓝、魔法紫、警告与危险等语义色。运行时生成一张可九宫格拉伸的圆角 Sprite，并统一提供：

- `Card`：圆角底板、语义描边和轻量阴影。
- `CurrencyChip`：资源徽章、紧凑数值和来源入口。
- `IconBadge`：无正式图集时的可替换图形占位边界。
- `StatCard`、`ProgressBar`、`EmptyState`、`SectionTitle`。
- `Button`：统一选中/按下/禁用状态和 `UiPressFeedback`。
- `CompactNumber`、资源颜色/图形、卡牌稀有度颜色映射。

当前仓库没有正式角色立绘、建筑插图、卡牌图集和中文字体，因此视觉头图采用“语义色洗底 + 徽章 + 对象名称 + 关键指标”的完整布局，不用长文本假装图片。后续美术只需替换 `ObjectVisual`、`PortraitMask`、`CardIcon` 等契约节点，不需要改业务流程。

## 动效与可访问性

`UiMotionElement` 使用 `Time.unscaledDeltaTime`，因此暂停界面和战斗结算仍能正常播放。已实现根页面左右切换、底部抽屉上移、模态缩放、Toast 进入、永久卡错峰进入和按钮按压反馈。

动效组件在静止时关闭 `Update`，避免持续空转。关闭抽屉时先禁用射线，再淡出并销毁，防止退出动画期间拦截新界面输入。进度页提供 `Reduce Motion` 开关；开启后保留必要淡入，但取消位移、缩放和按压运动，设置写入本地 PlayerPrefs。

## 页面信息结构

- 城市：三个高频资源独立显示并可直达来源，任务和建造队列从长文本改为带状态徽章的常驻卡。
- 英雄：活动英雄头图、战力/生命/攻击、经验进度、英雄选择卡和装备/永久卡摘要。
- 远征：关卡头图、己方战力/推荐战力/时长、奖励条、主部署按钮和纵向关卡节点。
- 工坊：铁匠铺与技能商店使用不同主题头图，明确当前装备、继承规则、成本、卡池和解锁条件。
- 进度：阶段、英雄、战斗时长、下一城市目标、存档说明和减少动态效果设置。
- 战斗：英雄头像、生命/护盾/经验、时间、威胁、Boss 生命/架势与终极技能保持边缘布局；暂停和结算改为单任务模态卡。
- 永久卡：每张卡独立显示图形、稀有度、类型、名称、描述、当前等级到新等级以及路线锁定警告。

## 验证结果

- Runtime、Editor、EditMode、PlayMode 程序集：0 编译错误。
- Unity EditMode：26/26 通过。
- Unity PlayMode：5/5 通过，覆盖启动、幸存者战斗、城市建造、中文资源和五个根页面视觉/动效契约。
- Unity WebGL/IL2CPP：最终精确源码构建成功，18 个文件，共 82,877,602 字节。
- 构建仍通过 WebGL、竖屏、启用场景和 TTSDK 前置校验。
- 整个制作和验证过程未执行截图操作。

## 后续生产边界

正式美术阶段仍需补齐角色/建筑/关卡/卡牌图集、中文字体、UI 音效和品牌级粒子表现。市场、酒馆、招募、活动、邮件、排行榜等规范页面应在对应业务规则落地时再接入同一套组件，不应先制作不可操作的空壳。
